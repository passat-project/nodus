Выполни батч-мерж одобренных PR по процедуре ниже. Сессия свежая — весь порядок действий здесь; общие каноны — в AGENTS.md (уже загружен). Аргументы: `$ARGUMENTS`.

**Аргументы:** пусто — полный батч; «проба» (или dry) — только разведка и план, ничего не мержить; номера PR через пробел — мержить только их (протокол тот же).

## 1. Разведка (репо не меняется)

- `git fetch origin`; кандидаты: `gh pr list --state open --review=approved --json number,title,headRefName,headRefOid,updatedAt`. CHANGES_REQUESTED и draft — не кандидаты. Кандидатов нет → короткий отчёт и стоп.
- CI каждого кандидата: `gh pr checks <N>`. Зелёный → кандидат; pending → дождаться; красный → исключить с причиной в отчёт (красную ветку не мержим, её чинят отдельно).
- Карта конфликтов: для каждого head-SHA `git merge-tree --write-tree --name-only origin/main <sha>` (код выхода 1 = конфликт, дальше список файлов). Очередь — от старого PR к новому; конфликты между самими кандидатами карта не покажет — они проявятся по ходу слияний.

## 2. Worktree и окружение

- `git worktree add --detach ../nodus-wt-merge-batch origin/main`; далее в нём только абсолютные пути (gotcha #1072: относительные пути Bash в worktree-сессии читают основное дерево).
- Бутстрап сразу, до первого резолва: `pnpm install --frozen-lockfile` → `pnpm --filter @nodus/contracts build` → в `apps/api` `pnpm exec prisma generate`. Причина: Prisma-клиент и dist не коммитятся; без этого тесты web падают «Failed to resolve import "@nodus/contracts"», typecheck api — «Cannot find module generated/prisma».

## 3. Очередь слияний — строго по одному PR

CLEAN против текущего main:

- `gh pr merge <N> --squash --delete-branch --admin`; подтвердить `gh pr view <N> --json state,mergeCommit` = MERGED + sha. Достаточность: свой CI ветки зелёный, текстовых пересечений нет; итоговое объединённое состояние целиком проверит CI самого позднего конфликтного PR (если конфликтных нет — сказать об этом в отчёте: объединённое состояние не гонялось, риск почти нулевой).
- Пока CI конфликтного PR идёт — продолжать мержить следующие CLEAN-PR очереди (front-load).

CONFLICT (с текущим main или с уже влитым соседом):

1. В worktree: `git checkout -B <ветка-PR> origin/<ветка-PR>` → `git merge origin/main`.
2. Анализ ДО правок: что меняла каждая сторона, независимы ли поведения.
   - Текстовый/технический конфликт → совместить ОБЕ функции (цель по умолчанию: ничего не потеряно).
   - Слияние толкает файл за лимит I5 (бюджет lint — 39 предупреждений) → минимальный cohesive-вынос в новый файл без изменения DOM/поведения, README в том же коммите (I12).
   - **Бизнес-конфликт** (взаимоисключающие поведения) → разобрать «что получаем / что теряем» и STOP & ASK владельцу простыми бизнес-кейсами, не техническими нюансами. Норма отрасли: побеждает уже влитое в main, поздний PR адаптируется; продуктовое противоречие решает только владелец.
3. Гейты: точечно по затронутым (`npx eslint <файлы>`, `pnpm --filter @nodus/web exec vitest run <тесты>`) → полный прогон один раз: `pnpm lint` (≤ 39), `pnpm typecheck`, `VITE_API_MOCK=false pnpm test`.
4. Push: `git fetch` + проверка дрейфа main → `git push origin HEAD:<ветка-PR>`. Force-push запрещён.
5. CI ветки: ждать зелёного на текущем head-SHA опросом до `completed success` (`gh run list --branch <ветка> --limit 1`; `gh pr checks --watch` не использовать — гонка «no checks reported»). Долгое ожидание — норма, не сжимать.
6. Если за ожидание main ушёл вперёд → повторный `git merge origin/main` в ветку, точечные гейты, push, CI заново.
7. CI красный после подтяжки: диагностика. Тесты требуют старого поведения, которое PR законно меняет → обновить тесты в этом PR. Смысловой конфликт с влитой фичей → поздний PR адаптируется к main. Без владельца не решается → STOP. Не решается в этом прогоне вообще → вернуть ветку на последнее зелёное состояние, PR пропустить с причиной в отчёте.
8. Мерж: `gh pr merge <N> --squash --delete-branch --admin` (пуши резолва сбрасывают аппрув по правилу ветки — admin обязателен, канон 04.11).

## 4. Финал

- Все PR: `state=MERGED`, sha в main; связанные issues автозакрылись (`gh issue view <N> --json state`).
- Комментарий в issue — только где резолв был содержательным: что сведено, оба поведения сохранены, вынос файла, «аппрув сброшен пушами → admin». Чистые мержи не комментировать (GitHub записывает сам).
- Уборка в тот же день: `git status` дерева worktree (чужие незакоммиченные изменения → STOP & ASK) → `git worktree remove ../nodus-wt-merge-batch` → `git worktree prune` → удалить локальные ветки PR руками (`--delete-branch` не удаляет ветку, занятую worktree).
- Отчёт владельцу простым языком: таблица PR → commit; по конфликтам — что сведено и что сохранено; пропуски с причинами; факты admin-мержей.

## Ограничения

- Не мержить: без APPROVED, с красным или не завершённым CI, с CHANGES_REQUESTED.
- main локально не двигать — посадки только через `gh pr merge`; историю не переписывать; деструктивные операции — STOP & ASK.
- Команда безопасна к прерыванию: состояние живёт в GitHub (MERGED / открытые PR, ветки), повторный вызов подхватывает остаток. При риске прерывания на долгом CI — оставить HANDOFF-комментарий с состоянием очереди в самом старом незакрытом PR батча.
