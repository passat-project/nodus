# Линза ядра Nodus — разбор нового входа (ADR-0037)

Когда: новое интервью (саммари — в локальной папке владельца `docs/product/interviews/`, в репозитории её нет), жалоба или пожелание (issue, чат, слова владельца), новый процесс компании. Цель — не превратить боль в функцию под случай: сначала рецепт из блоков ядра, и только если не собирается — самый маленький пробел ядра.

## Что прочитать — по порядку и не больше

1. `AGENTS.md` (всегда в контексте) → `docs/product/north-star.md` §4–5.
2. `docs/adr/0037-automation-core.md` — блоки ядра.
3. `docs/product/core-recipes.md` — как известные процессы уже собраны; раздел «Пробелы ядра».
4. Источник входа: саммари интервью; полный транскрипт `full/` — точечно, по таймкодам.
5. Issues эпиков #377 (ядро) и #49 (проекты) — по номерам из рецептов.

Каждое знание живёт в одном месте: решения — ADR; принципы — north-star; термины — глоссарий; голос людей — интервью; идеи — инкубатор; работа — issues; «как процесс живёт в Nodus» — каталог рецептов. Не дублировать — ссылаться.

## Семь шагов

1. **Зафиксировать вход** — по правилам `docs/product/interviews/README.md`, комментарием issue или карточкой инкубатора; дословно, со ссылкой на источник.
2. **Отделить факты от мнений.** Факты — как работают сейчас, как часто, во что обходится боль. Мнения «как надо сделать» — гипотезы (05.11: сметчицы за четыре минуты назвали взаимоисключающие варианты).
3. **Собрать рецепт** из блоков: тип (атрибуты, форма, карточка, права, маршрут), кнопки (переходы и действия), гейты, шаги, правила, счётчики, реестры, виды, вкладки карточки. Собирается — строка в `core-recipes.md` (и issue посева, если нужно «из коробки»); ядро не трогаем.
4. **Не собирается — самый маленький пробел ядра:** какой блок чего не умеет; формулировка без слов предметной области («цвет строки по значению колонки», а не «серая строка отклонённой выдачи»); сначала параметр существующего блока, потом новый блок; правило двух случаев.
5. **Решение.** Пробел → карточка инкубатора «Ядро: …» → разбор владельцем → дополнение ADR-0037, issue в эпик #377, строка в «Пробелы ядра». Рецепт → `core-recipes.md` (+ посев).
6. **Вопросы владельцу — только бизнес** (цель, кто решает, что видит руководство, что запрещено), батчами в формате grilling. Как удобнее работать отделу — выбор настройки, не вопрос владельцу; техника — решение агента.
7. **Регресс модели:** при любом изменении ядра пройти все рецепты каталога; сломанный рецепт — блокер изменения.

## Правила ядра

- Сначала настройка, потом ядро.
- В коде ядра нет слов предметной области («задание», «комплект», «шифр») — они только в рецептах и посевах.
- Правило двух случаев: новое умение — если нужно ≥ 2 разным процессам или явно обобщается (тест абстракции, железное правило 4 этого навыка).
- Параметр лучше нового блока; второй механизм рядом с существующим запрещён. Отклонено ранее: конечный автомат у реестра, отдельный модуль расчётов, формула как тип атрибута.
- Системных полей минимум; всё предметное — атрибуты.
- Трассировка: рецепт ↔ источник (интервью с таймкодом) ↔ issues ↔ раздел ADR-0037.

## Анти-паттерны (сессия 03–05.11)

| Было | Почему плохо | Как правильно |
| --- | --- | --- |
| «Серая строка» отклонённой выдачи | функция реестра под один случай | значение колонки-списка, цвет варианта, фильтр вида |
| Вопросы владельцу «как работать сметчикам» | методология — это настройка | дать варианты рецепта, спрашивать только бизнес |
| Шифр — системное поле с проверкой уникальности | предметное в ядре | атрибут, формула, без проверок |
| Права на отдельные поля из-за жалобы | случай понят неверно: исполнитель и не должен править задачу постановщика | перечитать случай в транскрипте до нового механизма |
| Режим реестра «выдача с подтверждением» | второй движок состояний | подтверждение — шаг маршрута задачи |

## Итог разбора — формат

Таблица «случай → рецепт (блоки) → пробелы → решение (настройка / инкубатор / issue) → источник». Кладётся в саммари интервью (раздел «Куда ложится») или комментарием issue; рецепты — в `core-recipes.md`, запись в его журнал.

## Когда нужен полный конвейер

Пересборка модели целиком, вход ломает несколько рецептов сразу или владелец просит «проверь на прочность» — фазы 0–5 из `SKILL.md`.
