# Песочница live-stack: устройство, бутстрап, траблшутинг

Скрипт: `scripts/live-stack.mjs` (вызов через package.json: `pnpm live-stack <cmd>`).
Состояние: PID-файл `.live-stack/pids.json`; логи сервисов `.live-stack/{api,gateway,web}.log`; скриншоты проб `.live-stack/shots/`. Каталог `.live-stack/` — gitignored: сеансовые скрипты проб и артефакты живут там, НЕ в репо.

## Что делает `up` (по порядку)

1. Проверка сирот: живые pid из pids.json → «сначала down»; чужой процесс на порту :3011/:3012/:4173 → громкий отказ с рецептом (`netstat -ano | findstr :4173` → `taskkill /PID <pid> /F`).
2. **Авто-изоляция** (без явного env процесса): из корневого `.env` берутся прод-значения и переписываются — `DATABASE_URL`: база `nodus` → **`nodus_night`**; `REDIS_URL`: суффикс БД → **`/1`**. Логирует каждую подмену. Явный env процесса главнее; если он указывает на прод-базу `nodus` — ОТКАЗ (осознанный прод: `SANDBOX_ON_PROD=1`).
3. **Бутстрап** (идемпотентно, безопасно повторять): создать БД `nodus_night`, если нет (docker exec nodus_postgres) → `prisma migrate deploy` (schema `apps/api/prisma`) → `db:seed` с паролями из `tests/e2e/e2e-users.json` (роли, флаги, пользователи CI-e2e; ТОЛЬКО на `nodus_night` — на другой БД сид пропускается, иначе перезаписал бы пароль боевого админа) → `scripts/night-users.mjs` (night-a/night-b, upsert). Пользователи с публичными паролями (сид, night) — **только в `nodus_night`**: на любой другой базе бутстрап их пропускает, `night-users.mjs` отказывает.
4а. **Свои секреты подписи** (#247, security-ревью): `JWT_SECRET`/`STORAGE_URL_SECRET` песочницы — НЕ из `.env` (там прод), а из gitignored `.live-stack/secrets.json` (генерируется один раз; совпадение с `.env` — отказ старта). Иначе токен песочницы, полученный по публичному тестовому паролю, принимал бы прод (`JwtAuthGuard` верит правам из payload).
4. Сборка: `@nodus/api` build, `@nodus/gateway` build, web — `VITE_API_MOCK=false vite build` (напрямую, мимо turbo-кэша).
5. Старт api (:3011, RATE_LIMIT_MAX=30000 для двухбраузерных прогонов, COOKIE_SECURE=false) + gateway (:3012) + web :4173 (strictPort) c прокси на api/gateway: `up --dev` — vite dev-сервер (`VITE_API_MOCK=false` из env процесса перекрывает `.env`; dist не пишет), `up` / `up --preview` — `vite build` + `vite preview`. Исключение — `up --dev --mock <домены|all>`: vite dev с `VITE_API_MOCK` (список доменов или `true` для `all`) — UI-чекпоинт ДО бэкенда (ADR-0001). `all` — демо-актёр, вход любыми данными, веб к api не ходит; список доменов — покомпонентный режим #48: **живой вход учётками песочницы**, на моках только перечисленные домены (нужен, когда чекпоинту важны права разных сотрудников: admin правит, сотрудник смотрит — #379). `--mock` без `--dev` — отказ (#171: сборка всегда non-mock). Режим — в `pnpm live-stack status` (файл `.live-stack/mode`: `dev`, `preview`, `dev+mock:all`, `dev+mock:roles`; при `--local` — суффикс `+local` в конце: `dev+local`, `dev+local+mock:all`).
6. Health-гейты: `/api/v1/health/ready`, gateway, web — «Ready» только когда всё живо.

`down` — taskkill по дереву pid'ов. `status` — жив/мёртв/порт занят чужим + LAN-адреса web. `bootstrap` — только шаг 3.

## LAN-доступ (#675)

- По умолчанию web слушает `0.0.0.0`: `up [--dev]` печатает все приватные IPv4 (RFC 1918, без link-local) вида `http://<LAN-IP>:4173 (интерфейс)`; `status` показывает те же адреса. Прямые порты api `:3011` и gateway `:3012` закрыты (`API_HOST`/`GATEWAY_HOST=127.0.0.1`), но `:4173` через vite-прокси отдаёт и `/api`, и WS — firewall строго per-port TCP 4173 для подсети команды, «доверенная сеть» не граница.
- `--local` — только этот ПК (web на `127.0.0.1`); в режиме появляется суффикс `+local` (`dev+local`, `preview+local`, `dev+local+mock:all`).
- Firewall: входящий TCP 4173 только для подсети команды (профиль Private/Domain). На доменных ПК локальные правила может запрещать GPO — нужно правило домена/корпоративного файрвола; api/gateway не открывать.
- IP по DHCP меняется — актуальный брать из `status` или закрепить DHCP reservation; старые ссылки у коллег после смены IP не работают.
- Безопасность: тестовые пользователи с публичными паролями; доступ только внутри офисной сети, в интернет не публиковать. Исключение по интерфейсам — `OFFICE_ENABLED=true`: api остаётся на `0.0.0.0` ради `host.docker.internal` (ONLYOFFICE) с предупреждением; `--local` главнее — api на loopback, но офисный просмотр из контейнера тогда не откроется.

## Почему изоляция именно такая (уроки инцидентов)

- `nodus_night` — база ВНУТРИ прод-контейнера `nodus_postgres` (не отдельный контейнер): отдельный контейнер не нужен, изоляция на уровне базы полная.
- **БД**: два api на одной базе = два outbox-диспетчера, ворующих события друг у друга (находка #100). Плюс пробные данные в проде (инцидент 01.10 #175: канал-проба попал в прод, вычищали руками).
- **Redis db1**: без суффикса клиент сидит в db0 = прод-редис — два издателя стрима `nodus:domain:events` (fanout bootstrap помечает историю «опубликованной») крадут уведомления друг у друга. Ловушка regex'а: URL без суффикса БД не матчится наивным `\/(0)?$` — перезапись обязана навешивать `/1` явно.
- Прод-токены никогда не читаются песочницей и наоборот: разные БД и разные db редиса.

## Траблшутинг

| Симптом | Причина | Лечение |
|---|---|---|
| `Port :4173 is taken by a FOREIGN process` | сирота прошлой сессии (preview жив) | netstat+taskkill по рецепту из ошибки |
| «на 4173 не поменялось» после правок | preview держит СТАРУЮ сборку (или правка в api/gateway — dist) | цикл правок фронта — `up --dev`; иначе `down` + `up` (не F5) |
| api не healthy | docker/БД/миграции | `docker ps` (nodus_postgres жив?), хвост `.live-stack/api.log`; `pnpm live-stack bootstrap` |
| Логин night не проходит | БД пересоздана без юзеров | `pnpm live-stack bootstrap` |
| `EADDRINUSE` у свежего процесса | занятый порт молча валит процесс — до старта live-stack проверяет и кричит | видеть ошибку live-stack ДО запуска своих процессов |
| 404 на чат-маршрутах API с валидным токеном | API смотрит не в ту БД / сущность не создана | проверить базу процесса в api.log (`nodus_night`?) |

## Гигиена сессии

- Поднял для пробы → проба → `down` (если владелец не будет смотреть ветку на :4173 прямо сейчас; на время приёмки — оставить UP и сказать владельцу адрес/креды).
- Свои процессы вне live-stack на этих портах — запрещены; лишние скрипты проб не коммитить (место — `.live-stack/`).
