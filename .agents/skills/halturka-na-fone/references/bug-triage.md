# Отбор бага для «халтурки»

Читать перед выбором. Цель — за 10–15 минут найти один баг, который можно
починить и показать визуально, не задавая владельцу вопросов.

## 1. Запрос

```bash
gh issue list --state open --label type:bug --label status:ready \
  --search "no:assignee" --limit 100
```

`--search "no:assignee"` — жёсткое условие: **любой** assignee исключает
issue, включая владельца. `status:ready` — можно брать; `type:bug` — только
дефекты. Issues с `status:draft`/`waiting-trigger` не трогать: они ждут
владельца или триггера.

**Цикл последовательный:** один баг за прогон. Следующий issue не выбирается,
пока текущий цикл не закрыт: PR смержен + issue закрыт + владелец подтвердил;
при отказе/броске — владелец подтвердил закрытие. Никаких параллельных веток
и «второй начну, пока ждём».

## 2. Гоночные проверки до взятия

```bash
gh issue view <N> --json number,title,body,labels,assignees,comments
gh pr list --state open --search "<N>"
git branch --all --list "*<N>-*"
git ls-remote --heads origin "*<N>-*"
git log --oneline origin/main --grep="#<N>"
```

- В assignees пусто? Если кто-то появился — пропусти, не отбирай.
- В комментариях есть «беру/в работе/делаю» за последние дни? Пропусти.
- Есть открытый PR, локальная или удалённая ветка с этим номером? Пропусти.
- Баг уже исправлен в `origin/main`? Прокомментируй «на main не
  воспроизводится» и пропусти; issue вручную не закрывай.
- В теле есть вопрос без рекомендации («решить при взятии», «надо
  обсудить»)? Пропусти: это не «без участия владельца».

## 3. Жёсткие фильтры

- **Приоритет:** P0 — никогда; P1 — только если все четыре оси скоринга
  равны 2; P2/без приоритета — обычный кандидат.
- **Результат:** виден в UI и проверяется «до/после» (кадры/видео, обе темы).
- **Репро:** воспроизводится на `origin/main` за ≤ 2 попытки.
- **Скоуп:** ожидаемое поведение и критерии приёмки есть в теле; явная
  рекомендация допустима, открытый продуктовый вопрос — нет.
- **Риск:** вне поверхности из правила 10 `SKILL.md` (миграции, auth,
  RBAC, файлы, WS/events/BullMQ, зависимости, API-контракты, infra, секреты/
  env/конфиги, пользовательский ввод до SQL/shell/файлов/URL/HTML/логов,
  десктоп, субъективный редизайн). Полная карта — DoD; сомнение — STOP.
- **Бюджет:** один баг за прогон, ≤ 3 файла, ≤ 150 строк.
- **Свободен:** assignee нет, активной работы нет.

## 4. Скоринг

| Ось | 0 | 1 | 2 |
|---|---|---|---|
| Визуальность | нет UI-эффекта | эффект косвенный/только в консоли | явное «до/после» в UI |
| Локальность | > 3 файлов или межмодульно | 2–3 файла | 1–2 малых файла |
| Ясность | нет ожидаемого поведения | механизм есть, критериев нет | механизм + решение + критерии |
| Риск | риск-поверхность | shared-компонент/API без прав | чистый UI/текст |

Бери лучший; при равенстве — меньший дифф. Порог — **7/8**. Ниже — «нет
подходящих», покажи 2–3 отклонённых с причинами.

### Калибровка

- «Убрать слово из чипа, оставить красный + sr-only» — 2+2+2+2 = 8. Берём.
- «Отступы шапки по точным значениям из issue» — 2+2+2+2 = 8. Берём.
- «Клик по папке не открывает панель, свойства — по ПКМ» — 2+2+2+2 = 8,
  если рекомендация в теле явная; иначе ясность 1 и пропуск.
- «Счётчик сотрудников не совпадает» — 2+1+1+1 = 5. Пропуск: нужно решение
  по тестовым учёткам и данные боевой БД.
- «Канбан DnD: фантом не с той стороны» — 2+0+1+0 = 3. Пропуск: сложно,
  межмодульно, поведение с гонками.
- «Пин react-query» — 0+0+1+0 = 1. Пропуск: не визуально, зависимость.
- «Права/секретные проекты» — риск 0. Пропуск, обычный процесс.
- «E2E-флейк» — визуальность 0. Пропуск: пользователь ничего не видит.

Номера issue в калибровке — иллюстрация, не список для взятия. Живой бэклог
меняется: перепроверяй запросом.

## 5. Если кандидатов нет

Не выдумывай баг и не бери «почти подходящий». Сообщи владельцу коротко:

> Подходящих нет: все свободные `status:ready` баги либо заняты, либо не
> проходят по риску/бюджету/визуальности. Отклонил: #N — причина; #M —
> причина. Ничего не брал.

## 6. Что не считать «лёгким»

- Общий примитив/токен/сетка, который меняет вид в нескольких модулях.
- Новый эндпоинт, контракт, миграция, права, событие, зависимость.
- Гонки, флейки, «иногда не работает», проблема только на проде.
- Задача, где «как должно быть» — вкус или выбор владельца.
- Баг без репро или без критериев приёмки.
- Всё, что требует `ui-writer` (редизайн, новая композиция экрана).
