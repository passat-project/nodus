# Шаблоны сообщений «халтурки»

## 1. Взятие — сообщение владельцу (сразу)

> Беру #N — <одна строка сути>.
> Ветка `fix/N-<имя>`, покажу на `:4173`. Без твоего визуального «ок» никуда
> не выгружаю; после PR — отдельная остановка на твою проверку.

## 2. Взятие — комментарий в issue

```markdown
Беру в халтурку.
- Исполнитель: агент. Ответственный: @<owner> (по указанию владельца).
- Ветка: `fix/N-<имя>`.
- Приёмка: живой взгляд на `:4173`, обе темы. Push/PR — только после
  визуального «ок»; мерж — только после проверки PR владельцем.
- План: репро → минимальный фикс + регрессионный тест → гейты → показ.
```

## 3. Показ — комментарий в issue

```markdown
Показ #N (халтурка).
**Было:** <что видит пользователь>.
**Стало:** <что изменилось>.
**Где:** http://127.0.0.1:4173/<route>; тестовый пользователь — `tests/e2e/e2e-users.json`.
**Шаги:** 1) ... 2) ...
**Темы:** светлая/тёмная — кадры ниже.
**Статус:** ветка локальная, не запушена. Жду визуальное «ок»; без него не
выгружаю.
```

## 4. Показ — сообщение владельцу (кратко)

> #N готов к показу: <что было> → <что стало>.
> Смотри: `:4173/<route>`, шаги ... Обе темы. Ветка локальная, жду визуальное
> «ок» — без него не пушу.

## 5. Визуальное «ок» — фиксация и PR

```markdown
Владелец: визуальное ок (<дата>, <чат/issue>). Выгружаю: push → PR → CI.
После зелёного CI останавливаюсь: PR проверяет владелец на GitHub.
```

## 6. PR создан — проверка на GitHub

```markdown
PR #M по #N: <ссылка>. CI зелёный, ветка не смержена.
Проверь PR на GitHub. Жду «мержи»/аппрув; сам не мержу.
Следующий баг не беру до мержа и твоего подтверждения.
```

## 7. Мерж — фиксация

```markdown
Владелец: мержи/ок на PR (<дата>, <чат/issue>). Мержу squash, удаляю ветку,
синхронизирую main, пишу финальный отчёт.
```

## 8. Финал — отчёт в issue

```markdown
Готово: #N исправлен и смержен (PR #M).
**Что было:** ...
**Что стало:** ...
**Как проверено:** ...
**Где посмотреть:** `:4173` / кадры; после релиза — на проде.
**Ретро:** ... / пуста.
На прод не выкатывал — это отдельная команда «ОБНОВИТЬ ПРОД».
Следующий баг — только после подтверждения владельца.
```

## 9. Бросил / отказ

```markdown
#N бросил: <не репродьюсится / вышло за бюджет / нужен выбор владельца /
риск-поверхность>.
Ветку выбросил (если PR был — закрыл с удалением ветки), assignee снял,
issue оставил открытым. Push был только в PR, если он создавался.
Следующий баг — после подтверждения владельца, что цикл закрыт.
```

## 10. Возобновление после сессии

```markdown
#N: ветка `<имя>` (commit `<sha>`), песочница `:4173` <up/down>, PR #M <ссылка>.
Что сделано: ...
Что осталось: ...
Для продолжения: `pnpm live-stack up --dev`.
```
