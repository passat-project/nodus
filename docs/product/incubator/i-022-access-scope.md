# И-022 · Права: охват записей и ресурсные роли

**Дата:** 2026-10-02

**Суть:** остаток после #379. Владелец показал Битрикс24 и отметил три вещи, которые не вошли: (1) уровни охвата записей — «только свои / своего отдела / подотделов / всех»; (2) разбивка прав на действия («Исполнитель: делегирование», «Постановщик: удаление задач», «Просмотр всех задач в отделе»); (3) ресурсные роли проектов и наследование прав по дереву (FGA).

**Разбор:** #379 закрыл UI ролей, матрицу «роль × право» и защиту назначения (#490). Охват записей — это не экран, а модель доступа к данным: скоупы в выборках задач, писем и контрагентов во всех модулях, отдельный ADR, 3–5 агент-дней. Дробить права имеет смысл только вместе с проверкой на сервере, по модулю за раз: сейчас часть прав (`task.assign`, `user.manage`, `core.admin`, `correspondence.*`) сервером не проверяется — право без проверки есть обман. FGA — только при реальной потребности наследования вниз (проект → задачи).

**Открытые вопросы:** охват «свои/отдел» нужен в декабре или после? Кто владелец политики — администратор портала? Наследование прав по дереву проектов — сейчас или V2?

**Связи:** #379, #490, ADR-0034, I8, `docs/architecture/non-functional-requirements.md`.

**Статус:** обсуждается.
