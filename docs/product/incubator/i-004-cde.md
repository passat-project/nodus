# И-004 · CDE-контур: версии, редакции, накладные

**Дата:** 2026-09-23

**Суть:** видеть судьбу выданного документа — направили → согласовали → загрузили → выдали (накладная №) — без перещёлкивания десятков таблиц ГИПов. Боль подтверждена всеми ГИПами (интервью 05–06.10).

**Что уже закрыто:** статусы комплектов живут в папке «Комплект» с изменениями (#557), пульс проекта — агрегат по папкам (#469), модель — ADR-0030. Это совпадает с ISO 19650: WIP → Shared → Published как «разрешённое использование» документа.

**Остаток (зреет):** полный CDE-контур — накладные (transmittals) с номерами и получателями, авто-уведомление всех получателей новой версии, заморозка выданного файла, внутренние редакции внутри одного Изм. и «отпечаток» файла (дата изменения, размер) для ловли подмены.

**Разбор:** без файлового модуля контур не построить — сейчас файлы живут в Pilot-ICE, вне Nodus; хранить версии в S3 можно, но нужна модель «файл → версия → выдача». Поэтому — после запуска, вместе с файловым модулем. Не строить отдельную сущность «документ»: комплект уже папка, версия — её метаданные.

**Открытые вопросы:** файловый модуль свой или интеграция с Pilot-ICE? Что считать «выдачей» — статус задачи или запись накладной? Где хранить старую редакцию — файл в S3 или только отпечаток?

**Связи:** #557, #469, ADR-0030, И-038, интервью Вашурова, Левчук и Куралени (саммари — `docs/product/interviews/`, локально у владельца, в репо нет).

**Статус:** зреет — триггер: появится файловый модуль или запрос ГИПов на накладные (после запуска).
