# Каталог рецептов ядра — как процессы компании собираются настройкой

Здесь каждый известный процесс компании описан как **рецепт** — набор настроек ядра автоматизации (ADR-0037), без кода под случай. Каталог отвечает на вопрос «как процесс X живёт в Nodus» и служит проверкой модели: при любом изменении ядра все рецепты должны по-прежнему собираться.

Читать: перед разбором нового входа (интервью, жалоба, пожелание), перед работой над issue ядра (эпик #377) или посевом процессов, при вопросе «как это устроено у нас». Процедура разбора — навык `core-forge`, справка `references/nodus-core-lens.md`.

## Правила каталога

- Рецепт — только из блоков ядра: **тип** (атрибуты, форма, карточка, права, маршрут), **кнопки** (переходы и действия), **гейты**, **шаги**, **правила**, **счётчики**, **реестры**, **списки** (вкладки-списки), **вкладки карточки**, **тип папки** (поля, действия, показатели — указатели и сводки по работам папки, ADR-0042), **тип проекта** (форма, какие папки бывают, «что здесь можно создавать», статусы и кнопки проекта, ветки — ADR-0041, `unified-model.md`). Чего нет в ядре — записывается в «Пробелы ядра», а не прячется в рецепт.
- У рецепта есть источник (интервью с таймкодом, вердикт, issue) и статус: **посев** — поставляется настройками «из коробки»; **черновик** — собран на бумаге, ждёт интервью или ядра.
- Методология процесса (как удобнее работать отделу) — выбор настройки, а не код: варианты перечисляются в рецепте.
- Слов предметной области («задание», «комплект», «шифр») нет в коде ядра — они живут только здесь и в посевах.

## Рецепты

### Задание смежнику — посев, #638

- **Источник:** интервью Шайдеровой и Левчук 05.11 (00:07–00:24), вердикты владельца 05.11.
- **Тип** «Задание смежнику» — подзадача работы комплекта (разработка или Изм.); атрибуты: комплект-получатель (ссылка на папку), получатель (подстановка — ответственный текущей работы комплекта-получателя), пути к файлам, что изменилось, вид выдачи (новая редакция / дополнение к версии N), версия.
- **Маршрут:** «Подготовка» → «Выдать» → «На ознакомлении» (решающий — поле «Получатель»: «Принять» / «Отклонить» с причиной) → «Принято» → «Выдать» снова.
- **Шаги:** «Выдать» — строка в реестре «Выдачи заданий» (состояние «на ознакомлении», без номера); «Принять» — номер версии из счётчика задачи, состояние «принято»; «Отклонить» — состояние «отклонено» и причина.
- **Гейт** у «Выдано в печать» разработки и изменения: все подзадачи этого типа приняты; обход — руководство проекта с причиной.
- **Правило схемы** на каждый Изм.: окно «Кому выдать» (прежние получатели), шаг «создать задачи — по одной на отмеченного».
- **Вкладки:** «Выдачи» (реестр, рамка — задача) у типа; у комплекта и проекта — тот же реестр с рамкой места.
- **Варианты:** проверка главспецом перед выдачей — шаг маршрута (выключен); внешние получатели — не ведутся.

### Задание сметчикам — посев, #638

- **Источник:** интервью 05.11 (00:24–00:57), вердикты владельца 05.11.
- Как «Задание смежнику», но выдаётся на каждый комплект и каждый Изм. (ветка схемы с условием «у проекта „Сметная документация“ = да»); решающий — конкретный сотрудник из настройки кнопки (в посеве — руководитель сметного отдела; должность как источник убрана, #806), при принятии выбирает исполнителя.
- **Варианты дальнейшей работы (выбор настройкой):**
  1. **Связанная работа «Смета»** (посев): шаг «создать задачу по шаблону» со связью; внутренний чат сметчиков отдельно, вкладка «Чат задания» показывает разговор с проектировщиком.
  2. **Переадресация:** шаг «сменить ответственного» — та же задача уходит сметчику.
  3. **Сквозная задача:** тот же тип с подзадачами сметчиков.
- **Договор без смет** (решение владельца 15.11, ADR-0041): у ветки условие «у проекта „Сметная документация“ = да» — в договоре без смет задание сметчикам не появляется само, руками ничего не отключают.
- **Список** «Сметы» — вкладка-список задач этих типов, группировка по проекту и зданию (формула «ближайшая папка типа «Здание»»).
- **Вводная по объекту:** канал или страница знаний проекта, вкладкой в карточке сметы (#456, #272, #637).

### Комплект с изменениями — посев, #557

- **Источник:** вердикты 30.10, 02.11 (ADR-0030), интервью Вашурова и Левчук.
- **Тип папки** «Комплект»: атрибуты «Шифр» (формула, например `={Проект · Шифр}-{Здание · № по ГП}-{Марка}{Номер}`) и «Марка»; подпись — формула «ОВ1.1 · Изм. 2»; привязанные типы работ — «Разработка комплекта» и «Изменение» (создаются только в папке этого типа, #665).
- **Работы в папке:** «Разработка комплекта», «Изменение», задания.
- **Состояние комплекта** — показатели типа папки (#865, ADR-0042): «в работе» (ещё не выданная работа), «действует» (последняя выданная), **главная работа** — в работе (самая новая), иначе последняя выданная; через неё видны Изм., статус, исполнитель, срок, актуальный файл. Отменённые не считаются; руками не правится.
- **Точка выпуска** — у статусов работы начиная с «Выдано в печать» стоит отметка «результат выдан» (#635); с этого статуса «Файл» только для чтения (состояние полей по статусу).
- **Действие папки** «Внести изменения» (на папке-комплекте; в карточке выпущенной работы — ссылка на комплект): шаги — создать «Изменение» в папке, Изм. N из счётчика папки, строка в «Книге изменений» с номером «NN-ГГ»; задача показывает номер своей строки.
- **Правило** «Заменена»: изменение прошло точку выпуска → прежние выпущенные незакрытые работы закрываются с итогом «Заменена Изм. N».

### Книга изменений — посев, #557

- **Источник:** интервью 05.11 (00:09–00:12, 01:00), ГОСТ 21.1101 табл. Л.1, СТБ 2255.
- **Реестр:** номер «NN-ГГ» (счётчик на всю компанию, с нового года счёт заново) рождается в строке; строка хранит номер, ссылку на работу «Изменение», кто взял и дату. Комплект, Изм., код причины 1–5 (усовершенствование, изменение норм, требования заказчика, устранение ошибок, прочее) и основание показываются из карточки работы по ссылке — в строку не копируются. Для объекта, которого нет в Nodus, строку заполняют руками: объект текстом, причина, основание.
- **Права:** свой номер берёт каждый сотрудник сам (в карточке — действием «Внести изменения», для объекта вне Nodus — строкой в реестре); правит и аннулирует с причиной — нормоконтроль; строки не удаляются, номер повторно не выдаётся.

### Накладные — посев, #557

- **Источник:** интервью 05.11 (00:58).
- **Реестр:** номер `{Проект · Инв. №}-{N}` (счётчик по проекту), комплект, Изм., экземпляры, получатель, дата.
- **Действие папки** «Передать по накладной» (на папке-комплекте с действующим выпуском) — шаг «добавить строку»; номер виден в пульсе (показатель «последняя накладная папки» — указатель по строкам реестра, #636).
- Открыто: правило номера — у того, кто ведёт накладные.

### Пульс — посев, #469

- **Источник:** вердикты 23–25.10, 05.11; интервью 05.11 (00:59).
- **Вкладка-список проекта:** строки — папки типа «Комплект» по дереву; колонки — шифр, показатели комплекта (главная работа: Изм., статус цветом, исполнитель; действующий выпуск), номер накладной, дата передачи, часы. Вкладка по умолчанию — у типа проекта, ГИП правит для проекта, личные варианты; несколько вкладок («Пульс», «Для заказчика»).

### Переработка — собирает владелец, #437

- **Источник:** интервью Шайдеровой 22.10, вердикты 21–25.10.
- **Тип** «Переработка»: заявка → «Разрешить» (решающий — конкретный сотрудник, зам директора по персоналу; должность как источник убрана, #806) → дата и часы → «Подтвердить факт» (руководитель заявителя) → итог. «Кто видит задачи этого типа» — только участники, их руководители, решающие и роль кадров (ADR-0042).
- **Список** «Переработки» — список типа по умолчанию: группировка по подразделению, сумма часов за месяц. Это список задач, а не реестр: второй записи рядом с заявкой нет.
- **Проект** (решения владельца 13.11 и 15.11): тип проекта «Переработки» с одним разрешённым типом задачи (#665); проект такого типа один, поэтому при создании заявки подставляется сам; «проект, где отработано» — поле заявки; «Переработки» — вкладка-список в карточке проекта «Переработки» (#435), каждый видит в ней только доступные ему заявки. Посева нет: агент даёт недостающие блоки, тип и маршрут собирает владелец.

### Поручение из письма — в работе, M5 (ADR-0027, #463)

- **Тип письма** с регистрацией (счётчик «Вх-ГГГГ/N»); резолюция — переход с окном; поручения — шаг «создать задачи по шаблону» по одной на исполнителя, связь с письмом; итог поручения — блоком в чат письма.

### «Мои действия» — #438

- **Вид** задач на канбане и в списке: задачи, где у меня доступна кнопка со смыслом «действие» или моя отметка в сборе.

### Тендер — черновик, И-040

- **Источник:** запрос Валерии 03.11; интервью — впереди.
- **Проект-тема** «Тендеры» и **тип** «Тендер»: атрибуты из ТЗ (тип объекта, площадь, стадия…), маршрут «заявка → расчёт → подача → выигран / проигран».
- **Действие** «Рассчитать»: окно с подстановками-формулами, поиск по справочным реестрам (как ВПР); значения сохраняются.
- Нужны пробелы ядра: «сформировать документ по шаблону», «создать проект по шаблону».

### Тип проекта «Договор» — посев, #856, #468, #38

- **Источник:** решения владельца 15.11 (ADR-0041); интервью ГИПа и главспеца («нарезка задач = контрольный штамп»; структура проекта вводится трижды).
- **Форма проекта:** шифр, заказчик, признаки договора (например, «Сметная документация: да / нет») — обычные атрибуты.
- **Что здесь можно создавать** (#665): «Разработка комплекта», «Изменение», «Задание смежнику», «Задание сметчикам», «Стандартная», письма.
- **Статусы и кнопки проекта** (#856): «Подготовка → Проектирование → Экспертиза → Сдан заказчику → Завершён»; кнопки — в нижней полосе карточки проекта; гейт «Сдать заказчику» — все комплекты выданы (у каждого есть действующий выпуск и ничего не в работе), обход — руководство проекта с причиной; автопереход — правилом. «В архив» — системная кнопка завершённого проекта, не статус.
- **Контрольный штамп** (#468): окно кнопки «Начать проектирование» с таблицей строк; шаг «создать папки и работы по строкам» — папка «Комплект» + работа «Разработка комплекта».
- **Ветки** (#38): «каждая папка „Комплект“ с маркой …: после „Костяк готов“ → окно „Кому выдать задания“»; «после „Выдано в печать“, если „Сметная документация = да“ → „Задание сметчикам“»; повтор на каждый Изм. Нет папок с такой маркой — ветка молчит.
- **Варианты:** другой набор статусов, другие признаки договора и ветки — настройкой типа; принципиально другая работа («Авторский надзор», «Обследование») — новый тип проекта копией.

### Тип проекта «Тема» — посев

- Статусы «Действует → Завершена» с кнопками «Завершить» и «Вернуть в работу», веток нет; разрешены простые задачи и письма (#665). Темы группируют письма и задачи не по договору («Обучение персонала», «Тендеры», «Корреспонденция»); справочника рубрик нет.
