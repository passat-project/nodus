# Каталог рецептов ядра — как процессы компании собираются настройкой

Здесь каждый известный процесс компании описан как **рецепт** — набор настроек ядра автоматизации (ADR-0037), без кода под случай. Каталог отвечает на вопрос «как процесс X живёт в Nodus» и служит проверкой модели: при любом изменении ядра все рецепты должны по-прежнему собираться.

Читать: перед разбором нового входа (интервью, жалоба, пожелание), перед работой над issue ядра (эпик #377) или посевом процессов, при вопросе «как это устроено у нас». Процедура разбора — навык `core-forge`, справка `references/nodus-core-lens.md`.

## Правила каталога

- Рецепт — только из блоков ядра: **тип** (атрибуты, форма, карточка, права, маршрут), **кнопки** (переходы и действия), **гейты**, **шаги**, **правила**, **счётчики**, **реестры**, **виды**, **вкладки карточки**. Чего нет в ядре — записывается в «Пробелы ядра», а не прячется в рецепт.
- У рецепта есть источник (интервью с таймкодом, вердикт, issue) и статус: **посев** — поставляется настройками «из коробки»; **черновик** — собран на бумаге, ждёт интервью или ядра.
- Методология процесса (как удобнее работать отделу) — выбор настройки, а не код: варианты перечисляются в рецепте.
- Слов предметной области («задание», «комплект», «шифр») нет в коде ядра — они живут только здесь и в посевах.

## Рецепты

### Задание смежнику — посев, #638

- **Источник:** интервью Шайдеровой и Левчук 05.11 (00:07–00:24), вердикты владельца 05.11.
- **Тип** «Задание смежнику» — подзадача работы комплекта (разработка или Изм.); атрибуты: комплект-получатель (ссылка на папку), получатель (подстановка — ответственный текущей работы комплекта-получателя), пути к файлам, что изменилось, вид выдачи (новая редакция / дополнение к версии N), версия.
- **Маршрут:** «Подготовка» → «Выдать» → «На ознакомлении» (решающий — поле «Получатель»: «Принять» / «Отклонить» с причиной) → «Принято» → «Выдать» снова.
- **Шаги:** «Выдать» — строка в реестре «Выдачи заданий» (состояние «на ознакомлении», без номера); «Принять» — номер версии из счётчика задачи, состояние «принято»; «Отклонить» — состояние «отклонено» и причина.
- **Гейт** у «Выдано в печать» разработки и изменения: все подзадачи этого типа приняты; обход — руководство проекта с причиной.
- **Правило схемы** на каждый Изм.: окно «Кому выдать» (прежние получатели), шаг «создать задачи — по одной на отмеченного».
- **Вкладки:** «Выдачи» (реестр, рамка — задача) у типа; у комплекта и проекта — тот же реестр с рамкой места.
- **Варианты:** проверка главспецом перед выдачей — шаг маршрута (выключен); внешние получатели — не ведутся.

### Задание сметчикам — посев, #638

- **Источник:** интервью 05.11 (00:24–00:57), вердикты владельца 05.11.
- Как «Задание смежнику», но выдаётся на каждый комплект и каждый Изм. (правило схемы, в бессметном проекте ГИП его отключает); решающий — должность «руководитель сметного отдела», при принятии выбирает исполнителя.
- **Варианты дальнейшей работы (выбор настройкой):**
  1. **Связанная работа «Смета»** (посев): шаг «создать задачу по шаблону» со связью; внутренний чат сметчиков отдельно, вкладка «Чат задания» показывает разговор с проектировщиком.
  2. **Переадресация:** шаг «сменить ответственного» — та же задача уходит сметчику.
  3. **Сквозная задача:** тот же тип с подзадачами сметчиков.
- **Вид** «Сметы» — задачи этих типов, группировка по проекту и зданию (формула «ближайшая папка вида «Здание»»).
- **Вводная по объекту:** канал или страница знаний проекта, вкладкой в карточке сметы (#456, #272, #637).

### Комплект с изменениями — посев, #557

- **Источник:** вердикты 30.10, 02.11 (ADR-0030), интервью Вашурова и Левчук.
- **Вид папки** «Комплект»: атрибуты «Шифр» (формула, например `={Проект · Шифр}-{Здание · № по ГП}-{Марка}{Номер}`) и «Марка»; подпись — формула «ОВ1.1 · Изм. 2».
- **Работы в папке:** «Разработка комплекта», «Изменение», задания.
- **Состояние комплекта** — формулы по работам папки: текущий Изм., статус текущей работы, исполнитель, актуальный файл.
- **Точка выпуска** — состояние полей по статусу: после «Выдано в печать» «Файл» только для чтения.
- **Действие** «Внести изменения» (на папке и в выпущенной работе): шаги — создать «Изменение» в папке, Изм. N из счётчика папки, номер «NN-ГГ» из счётчика книги, строка в «Книге изменений».
- **Правило** «Заменена»: изменение прошло точку выпуска → прежние выпущенные незакрытые работы закрываются с итогом «Заменена Изм. N».

### Книга изменений — посев, #557

- **Источник:** интервью 05.11 (00:09–00:12, 01:00), ГОСТ 21.1101 табл. Л.1, СТБ 2255.
- **Реестр:** номер «NN-ГГ» (счётчик по году), проект (ссылка), комплект (ссылка, необязательно), Изм., кто взял, код причины 1–5 (усовершенствование, изменение норм, требования заказчика, устранение ошибок, прочее), основание — необязательная ссылка на письмо и текст, дата.

### Переработка — посев, #437

- **Источник:** интервью Шайдеровой 22.10, вердикты 21–25.10.
- **Тип** «Переработка»: заявка → «Разрешить» (решающий — должность «зам директора по персоналу») → дата и часы → «Подтвердить факт» (руководитель заявителя) → итог.
- **Вид** «Реестр переработок» — по умолчанию у типа: группировка по подразделению, сумма часов за месяц.

### Поручение из письма — в работе, M5 (ADR-0027, #463)

- **Тип письма** с регистрацией (счётчик «Вх-ГГГГ/N»); резолюция — переход с окном; поручения — шаг «создать задачи по шаблону» по одной на исполнителя, связь с письмом; итог поручения — блоком в чат письма.

### «Мои действия» — #438

- **Вид** задач на канбане и в списке: задачи, где у меня доступна кнопка со смыслом «действие» или моя отметка в сборе.

### Тендер — черновик, И-040

- **Источник:** запрос Валерии 03.11; интервью — впереди.
- **Проект-тема** «Тендеры» и **тип** «Тендер»: атрибуты из ТЗ (тип объекта, площадь, стадия…), маршрут «заявка → расчёт → подача → выигран / проигран».
- **Действие** «Рассчитать»: окно с подстановками-формулами, поиск по справочным реестрам (как ВПР); значения сохраняются.
- Нужны пробелы ядра: «сформировать документ по шаблону», «создать проект по шаблону».
