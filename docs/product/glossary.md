# Глоссарий

Доменные и технические термины проекта. Интерфейсная терминология — только русская деловая (см. `ux-principles.md`); таблица UI-строк — `packages/contracts/i18n/ru.ts`.

## Доменные термины

- **Поручение** — обычная задача (тип «Поручение» или любой рабочий тип), созданная из карточки письма исполнителем письма (ГИПом) или руководством при «Расписать сразу»; `source = letter`, проект письма по умолчанию (узел дерева — по выбору в форме); итог поручения падает блоком в чат письма, часы суммируются в письмо (ADR-0027).
- **Резолюция** — распоряжение адресата письма (руководителя): текст + один срок + ветка — «На исполнение» (исполнитель письма — конкретный ГИП, письмо становится его долгом «Расписать поручения»), «Расписать сразу» (поручения на конкретных людей) или «Для ознакомления» (получатели жмут «Ознакомлен»); у письма с поручениями кнопки «Ознакомлен» нет (ADR-0027).
- **Канал проекта** — чат, автоматически создаваемый для проекта; сообщения канала — новости-треды (поток Д, core-flows.md).
- **Тред (обсуждение)** — ветка ответов на сообщение канала (ровно один уровень: корень + ответы); UI-термин — «Обсуждение», уведомления — только участникам треда и наблюдателям.
- **Чат задачи** — беседа мессенджера, привязанная к задаче (`conversation.type=task`), — тот же движок, что у обычных чатов (канон владельца #252: двух чатов нет); состав = участники задачи; собраны во вкладке мессенджера «Чаты задач и писем», открытие задачи — карточкой в стеке (ADR-0009).
- **CDE** (Common Data Environment) — единая среда данных проектной документации (цель V3).
- **СМДО / АИС МВ** — государственная межведомственная система электронного документооборота РБ; подключение только через сертифицированные ВСЭД (перечень НЦЭУ).
- **ВСЭД** — ведомственная система электронного документооборота.
- **ГИП** — главный инженер проекта.
- **СЭД** — система электронного документооборота (у нас заменяет «Е-дело»).
- **Тип процесса (ProcessType; вкладка «Процессы» раздела «Автоматизация»)** — глобальный справочник шаблонов процессов двух категорий: тип задачи и тип письма (ADR-0024); тип несёт маршрут, форму создания, состав карточки, доступ, нумерацию (письма). Типы задач — системные «Стандартный» (с утверждением постановщиком) и «Быстрый» (без утверждения), пользовательские — в разделе «Автоматизация» (#378); тип определяет маршрут и значок/цвет в интерфейсе (ADR-0020/0021).
- **Маршрут (Workflow)** — статусы задачи и кнопки переходов между ними; статусы мапятся на скрытые системные состояния (I15); кнопки несут показ (главная / видна / в меню «Ещё»), условия «кто видит», гейты и пост-действия (ADR-0020). Правится в редакторе на холсте и публикуется версиями (конфликт версий — 409, ADR-0021).
- **Этап** — системная группа статуса: Ожидание / В работе / Пауза / Утверждение / Итог; уведомления, просрочка и порядок колонок канбана слушают этап (I14–I15). **Утверждение — промежуточный этап, не завершение**: работа сдана и ждёт приёмки, утверждающий может вернуть её в работу. Задача завершена только на этапе «Итог»; на утверждении она не просрочена (ADR-0020, дополнение 2).
- **Утверждающий / решающий** — кто вправе нажать кнопку шага: роль в задаче или письме, должность, руководитель автора или исполнителя, конкретные сотрудники, поле «Сотрудник», роль в проекте (ADR-0025). Решающий видит сущность, пока ход за ним, после решения становится наблюдателем без звука; утверждение пропускается, если утверждающий сам сдал работу.
- **Итог** — смысл закрытой задачи или письма: «выполнена», «отменена» или «отклонена» (отказ решающего, отличим от отзыва автором); задаётся статусом этапа «Итог» (ADR-0020, ADR-0025).
- **Кнопка (переход)** — действие смены статуса в карточке задачи («Взять в работу», «Завершить», «Утвердить»…); «из любого» — кнопка, доступная из всех статусов, кроме пары «Итог → Итог».
- **Действие** — кнопка маршрута без смены статуса: открывает окно, пишет данные, запускает шаги («Добавить замечание», «Взять номер», «Рассчитать»). В журнале переходов есть, учёт времени в статусах не трогает; на холсте маршрута рисуется у своего статуса (ADR-0037). Не путать со смыслом кнопки «действие / служебная».
- **Шаг** — что делает кнопка или правило: изменить поля этой или связанной записи, добавить или изменить строку реестра, создать задачи по шаблону (одну или по одной на каждое отмеченное значение), связать записи, сменить ответственного, выдать номер из счётчика, перевести связанные записи, выполнить шаги для каждой записи выборки. У шага может быть своё условие; выполняется от имени системы в пределах настроенного (ADR-0037).
- **Правило** — автоматизация «когда → если → сделать»: событие (запись создана, статус достигнут, поле изменилось, строка реестра добавлена; позже — расписание), условия и те же шаги, что у кнопок. Схема проекта — наглядный редактор правил типа проекта (ADR-0037).
- **Счётчик** — серия номеров с областью счёта (компания, год, проект, папка, задача) и шаблоном («15-26», «Инв.№-7», «v3»); номера не переиспользуются. Серии номеров писем — частный случай (ADR-0037).
- **Панель процесса** — нижний бар действий карточки задачи: слева главная кнопка, затем видимые, «Ещё ⋯»; порядок задаёт маршрут (сервер).
- **Схема маршрутов (WorkflowScheme)** — соответствие «тип задачи → маршрут»; системная — для задач без проекта, проект выбирает свою (ADR-0020).
- **Автоматизация** — раздел настройки процессов: вкладки «Процессы» (типы задач и писем, маршруты, формы, состав карточки), «Атрибуты» (атрибуты на весь портал и значения компании), «Схемы проектов» (типы проектов: холст схемы, форма проекта, доступ; виды папок), «Реестры» (виды реестров и все их строки по правам — ADR-0037), «Права доступа» (матрица прав раздела).
- **Ядро автоматизации** — набор универсальных механизмов, из которых любой процесс компании собирается настройкой, без разработки: записи и типы, атрибуты и формулы, конструктор форм, кнопки и гейты, шаги, правила, счётчики, реестры и виды, вкладки карточки (ADR-0037). Проектировщик работает только кнопками в карточке.
- **Права доступа (вкладка модуля)** — срез общей матрицы «роль × право» по правам раздела: строки — права модуля с названием и однострочным описанием, столбцы — роли портала, ячейки — флажки (ADR-0034, #379). Вкладка есть только у модуля, у которого есть настраиваемые права, и всегда последняя. Здесь права выдаются и отзываются; создание ролей и состав «кто в роли» — не здесь (инкубатор, И-022).
- **Роль (портала)** — именованный набор прав, общий на весь портал: у сотрудника несколько ролей, права складываются; отдельного набора ролей у модуля нет (антипаттерн разбора 02.10). Системные роли («Администратор», «Руководитель», «Сотрудник», «Модератор портала») создаёт сид; «Администратор» имеет все права, кроме надзорных и канальных (`project.view_secret` — отдельная роль «Системный надзор», `project.channel.post` — руководство проекта/точечная выдача), и в матрице неизменяем. Роли проекта отменены (ADR-0030, вердикт 29.10): руководство — системные поля; роли беседы — отдельный слой, в матрицу не входят.
- **Право** — разрешение на действие в точечной нотации `модуль.действие` (`workflow.manage`, `role.manage`): каталог в контрактах, тексты — в i18n. Право принадлежит разделу, в интерфейсе которого открывает действие. Выдать роли можно только право, которое есть у самого выдающего (`403 ROLE_PERMISSION_NOT_HELD`); изменения применяются у сотрудника после перезагрузки страницы или повторного входа.
- **Гейт DoR / DoD задачи** — условие перехода: DoR — «можно взять в работу» (заполнены поля), DoD — «можно завершить» (закрыт чек-лист, нет открытых подзадач, есть часы/результат). Собирается в конструкторе: какие записи проверить (подзадачи, родитель, связанные, задачи папки или проекта, записи по ссылке, строки реестра) с фильтром, что проверить (этап или итог, статус, поле), сколько (все, хотя бы одна, ни одной, есть хотя бы одна) и текст причины; редкие случаи — формулой. Кнопку гейт показывает, но не пускает и перечисляет причины. **Обход гейта** — с обязательной причиной; кто может, настраивается у гейта (по умолчанию руководство проекта и обладатели права обхода) (ADR-0020, ADR-0037). Не путать с DoD процесса разработки (`docs/process/definition-of-done.md`).

- **Мои действия** — вид задач по умолчанию на канбане и в списке: только задачи, где от меня ждут кнопку-действие или мою отметку в сборе; пусто = от меня ничего не нужно (ADR-0026, ADR-0037). Термин «ждёт меня» запрещён.
- **Смысл кнопки «действие» / «служебная»** — флаг кнопки: «действие» попадает в «Мои действия», «служебная» (пауза, отмена) — нет (ADR-0024). Не путать с **действием** — кнопкой без смены статуса.
- **Кнопку жмут несколько** — настройка обычной кнопки маршрута: одну кнопку («Завершить», «Ознакомлен», «Подписать») жмут несколько людей со счётчиком «N из M», каждый заполняет своё; после кворума кнопка выполняет свой обычный переход один раз (ADR-0025, дополнение 06.11.2026). Отдельного статуса и термина-существительного нет.
- **Тип письма** — тип процесса категории «письмо» (входящее / исходящее): маршрут, поля регистрации, серия номеров (ADR-0027).
- **Ждёт закрытия** — статус письма, когда все поручения выполнены: закрывает только расписавший — «Ответ направлен» или «Отработано без ответа» с причиной.
- **Приложенные письма** — системное поле письма: № + организация + дата вложенных писем-«матрёшек»; по нему ищется письмо.
- **Контрагент** — внешняя организация в справочнике CRM (заказчик, подрядчик, поставщик, госорган): краткое и полное название, УНП (уникален, если указан), адрес, e-mail, телефон. Письмо и проект ссылаются на контрагента по id, а не текстом (I14); удаления нет — только архив (ADR-0033, #460).
- **Контактное лицо** — сотрудник контрагента (ФИО, должность, телефон, e-mail) в его карточке; подписант письма — контактное лицо (#55).
- **Корреспондент** — контрагент, от которого пришло письмо или которому оно адресовано; поле письма — ссылка на справочник CRM.
- **Проект** — договор (на этап или весь объект) со своим шифром; «тема» — проект без шифра («Тендер», «Внедрение IT») (ADR-0030).
- **Руководитель проекта** — системное поле проекта (по умолчанию — создатель, передаётся): с помощниками имеет права уровня постановщика на все задачи проекта (закрывать забытые, удалять ненужные, менять поля проекта); вместе с помощниками управляет составом секретного проекта (вердикты 29.10, #52).
- **Помощник руководителя** — системное поле проекта (несколько сотрудников): все права руководителя, кроме передачи руководства и смены видимости на секретный.
- **Участник проекта** — сотрудник в составе проекта. Открытый проект: состав живёт из задач (постановщик, ответственный, соисполнители) + руководство + вступившие сам; наблюдатель задачи участником не становится. Секретный: состав прописывается вручную руководством; задачи состав не расширяют (ADR-0030).
- **Наблюдатель проекта** — участвует только просмотром: в открытом проекте — вступивший своей кнопкой или создатель-не-руководитель, в секретном — добавленный руководством. Не путать с наблюдателем задачи.
- **Портфель** — папка проектов в журнале «Проекты»: один заказчик одного большого объекта с десятками договоров-проектов. Своего состава и прав нет; сводная страница портфеля — после декабря (ADR-0030, дополнение 02.11).
- **Узел (папка)** — папка дерева проекта (стадия, очередь, здание по генплану, раздел, комплект…); часы и сроки собираются с задач. **Вид папки** — настраиваемый тип узла: свои атрибуты и форма создания; настраивается в «Автоматизации → Схемы проектов → Виды папок». Возможности («Документ с изменениями», «Показывать в пульсе», «Строка схемы») — готовые заготовки настроек ядра (ADR-0037). Вид без них — обычная папка.
- **Комплект** — папка вида «Комплект»; шифр — атрибут папки, может собираться формулой из шифра проекта и папок выше (ADR-0037). Внутри — работы: «Разработка комплекта», изменения, задания сметчикам и смежникам. Текущий Изм., статус текущей работы и актуальный файл считаются формулами по работам папки.
- **Работа** — задача внутри папки-комплекта (разработка, изменение, задание); закрывается по своему маршруту и не оживает. Подзадачи — части конкретной работы.
- **Изменение (Изм. N)** — отдельная работа по выпущенному комплекту («Внести изменения»): свой файл, маршрут и часы. «Изм. N» — порядковый номер в комплекте (счётчик папки); номер разрешения «NN-ГГ» — из книги изменений (графа «№ док.» штампа), выдаётся сразу при создании («взял изм»).
- **Книга изменений** — реестр номеров разрешений на всю компанию: номер «NN-ГГ» (счёт с начала года), проект, комплект, Изм., кто взял, код причины 1–5 по ГОСТ 21.1101 и СТБ 2255 (усовершенствование, изменение норм, требования заказчика, устранение ошибок, прочее), основание — необязательная ссылка на письмо. Строки не удаляются, только аннулируются с причиной; номер можно взять и для объекта, которого нет в работе в Nodus (ADR-0037).
- **Накладная** — строка реестра «Накладные»: номер по объекту, комплект и Изм., экземпляры, получатель, дата; создаётся кнопкой передачи, номер виден в пульсе (ADR-0037).
- **Задание смежнику** — задача на пару «кто → кому» (подзадача работы выдающего комплекта): готовит и отвечает выдающий, получатель (по умолчанию ответственный текущей работы комплекта-получателя) жмёт «Принять» — «ознакомился и взял в работу» — или «Отклонить» с причиной; номер версии даётся при принятии, все выдачи — строки реестра «Выдачи заданий». **Задание сметчикам** — так же, выдаётся на каждый комплект и каждый Изм.; как сметчики работают дальше, решает настройка (посев, ADR-0037).
- **Точка выпуска** — статус работы, с которого её файл и отмеченные поля только для чтения, правка — через «Внести изменения»; частный случай состояния полей по статусу в форме типа (по умолчанию «Выдано в печать»).
- **Заменена** — итог выпущенной, но формально не закрытой работы, когда выпущено следующее изменение комплекта; ставится правилом, работа считается выполненной.
- **Пульс** — настраиваемые виды проекта для быстрого ответа ГИПа заказчику: по умолчанию — комплекты по дереву с текущим Изм., статусом текущей работы и номером накладной; колонки — любые атрибуты и формулы. Вид по умолчанию задаёт тип проекта, ГИП правит его для своего проекта, каждый сохраняет свои варианты; видов в проекте может быть несколько. Замена таблиц ГИПов; дальше — отчёты и дашборды (ADR-0037).
- **Схема проекта** — наглядный редактор правил типа проекта: карточки видов работ и правила «после статуса работы A → создать работу B с окном дозаполнения» по видам папок и их атрибутам (в т.ч. на каждый Изм.); в проекте нарисована строка на каждую папку-комплект. В конкретном проекте ГИП правит экземпляр — отключает правило, добавляет разовое, меняет ещё не сработавшие узлы — без публикации типа (ADR-0030, ADR-0037). **Заглушка** — не задача и не черновик, а шаблон будущей задачи конкретного комплекта.
- **Реестр** — таблица записей «строка реестра» со своими колонками-атрибутами, формой и правами (кто добавляет вручную, кто правит, «только добавление», аннулирование): выдачи заданий, книга изменений, накладные, справочные таблицы для расчётов. Строки пишут кнопки и правила, вручную — кому разрешено; строка помнит, где и кем создана. Состояние строки — обычная колонка, особых режимов нет (ADR-0037).
- **Вид (представление)** — настраиваемое представление любых записей (задачи, письма, проекты, папки, строки реестра): колонки (атрибуты, формулы), фильтры, группировки, суммы, цвет по вариантам списков, рамка по месту открытия (из карточки чужие проекты не видны), выгрузка; сохраняется по умолчанию у типа, у проекта или лично. Пульс и «Мои действия» — виды (ADR-0037).
- **Вкладки карточки** — правая часть карточки задачи, письма или проекта: чат, файлы, реестр с рамкой, чат связанной задачи, страница базы знаний или канал проекта, связанные записи. Тип закрепляет нужные вкладки, остальные каждый добавляет себе через «+» (ADR-0037).
- **Новые** — вкладка корреспонденции с незарегистрированными письмами: очередь канцелярии (письма из почты и бумага, созданная вручную). Регистрация — переход маршрута с окном «Регистрация».
- **Способ поступления** — как письмо попало в компанию: электронная почта, почта, нарочным, СМДО (справочник `receipt-method`).
- **Регистрационный номер** — «Вх-2026/N» / «Исх-2026/N»: выдаёт сервер в транзакции перехода, серия и год — в типе письма; без пропусков и дублей.
- **Мастер создания проекта** — пошаговое окно: основа (тип и его форма) → структура → контрольный штамп (вставка таблицы; строка = папка «Комплект» + работа «Разработка комплекта») → схема.

## Технические термины

- **Outbox / Event log** — таблица доменных событий, гарантирующая доставку событий подписчикам (I9).
- **Оптимистичная мутация** — применение изменения в UI до ответа сервера с откатом при ошибке (I4).
- **ADR** — Architecture Decision Record, документ-фиксация архитектурного решения (`docs/adr/`).
- **Идемпотентность** — повторный запрос с тем же `Idempotency-Key` возвращает первый результат, не создавая дублей.
- **Transactional outbox** — запись события в `events` в той же транзакции БД, что и изменение сущности.
- **MSW** (Mock Service Worker) — библиотека моков HTTP-запросов; основа frontend-first разработки (ADR-0001).
- **Feature flag** — флаг включения модуля без пересборки (I10).
- **EntityLink** — универсальная связь между любыми сущностями портала; основа графа знаний.
- **Revision** — версия diff-аемого текстового контента (описание задачи, тело письма, текст сообщения).
- **DoD (процесса)** — Definition of Done, чеклист готовности issue разработки (`docs/process/definition-of-done.md`); гейты DoR/DoD задач продукта — в доменных терминах.

- **Атрибут** (кастомное поле, M10) — настраиваемое поле записи: «Шифр», «Марка», «№ накладной», «Сумма договора». Один атрибут на весь портал: название уникально, внутренний номер выдаёт система, «Где используется» — привязки к типам задач и писем, типам проектов, видам папок, видам реестров и «Компании» (ADR-0037). Реестр атрибутов живёт в «Автоматизации» (вкладка «Атрибуты»), значения — в карточке. В интерфейсе — только «атрибут»; в API и коде — `custom field` / `customFields`. **Скрытый атрибут** — служебный: значения живут для процессов, автоматики и отчётов, но в карточках, фильтрах и окнах переходов его не видит никто (замена архива, вердикт владельца 25.10.2026). Удаление разрешено всегда: окно перечисляет, сколько значений сотрётся и где атрибут используется, подтверждение — вводом названия.
- **Формула** — значение ячейки атрибута, начинающееся с «=», как в Excel: читает свои поля, родителей (задача, папки по виду или цепочке, проект), записи по ссылке, связанные записи (все, хотя бы одна, сколько, последняя), реестры (поиск значения, как ВПР) и значения компании; атрибуты в ней — плашки с названием. Наследование — только через формулы, без копий. **Подстановка** — формула, которая заполняет поле при открытии окна; после сохранения это обычное значение (ADR-0037).
- **Значения компании** — атрибуты с привязкой «Компания»: одно значение на всю компанию (код организации, префикс обозначений), доступное формулам (ADR-0037).
- **Список вариантов** — атрибут с выбором из справочника (`dictionaries`): варианты создаются в окне атрибута или берутся из существующего списка. Вариант удаляется (архива нет — вердикт 25.10.2026): значения с ним читаются пустыми. Системные справочники («Валюты», «Вид документа») правкой вариантов защищены.
- **Окно перехода** — диалог, открывающийся по кнопке маршрута: итог/отчёт, причина, файлы итога (в том числе выбранные из чата задачи), сообщения чата как отчёт, дозаполнение полей и трудозатрат. Пока обязательное (по гейтам кнопки) не заполнено, главная кнопка окна неактивна; настраивается в редакторе маршрута (#380).
- **Итог работы (результат задачи)** — отчёт исполнителя в окне перехода и в карточке: текст + сообщения/файлы чата; хранится ревизиями (`TaskResult`), текущая — последняя. Не путать с **итогом** закрытой задачи («выполнена/отменена/отклонена»).
- **Блок перехода** — компактная запись в ленте чата задачи о переходе: кнопка, «из → в», причина/комментарий, строка «Итог обновлён · N файлов»; автор — нажавший (#380).

- **Окно создания** — единственное окно создания задачи (#432): верх зафиксирован (название и тип), низ — форма выбранного типа, перестраивается на лету. Одно на все входы: кнопка «Создать», плюсик колонки, строка подзадачи, «В задачу» из сообщения. «Полной формы» нет — остальное живёт в карточке.
- **Форма создания (форма типа)** — настройка окна создания в узле «Создание» маршрута: упорядоченный список полей (системные и атрибуты типа), своё название поля, «обязательно при создании», скрытое поле с предустановленным значением, чипы-блоки («Чек-лист», «Планируемое время»). Раздел документа маршрута: правки вступают в силу после «Опубликовать».
- **Конструктор форм** — одна механика для всех форм ядра (окно создания, карточка, окна кнопок, строка реестра, вид папки, тип проекта): поля на холсте, ширина, своя подпись и подсказка поля в этой форме, привязка элемента к атрибуту, элементы без атрибута (заголовок, пояснение), состояние поля по статусу — скрыто, только чтение, обязательно (ADR-0037, #496).
- **Атрибуты типа** — привязка атрибута к типу (часть «Где используется»): тип видит только свои атрибуты (карточка, форма, окна, условия). Атрибут без привязок нигде не показывается. Заполненные значения при привязке не теряются.
- **Настройки типа** — панель типа: поля самого типа (название, значок, цвет, описание) и разделы «Доступ» (кто видит и создаёт), «Блоки карточки» (какие блоки показывать) и «Названия ролей» («Постановщик» → «Заявитель»). Сохраняются сразу, публикации не требуют. Флага «в пульсе проекта» у типа нет — что видно в пульсе, решает проект (#469, вердикт владельца 26.10.2026).

### Решающий

Сотрудник вне задачи, который по маршруту держит текущий шаг: должность,
ближайший руководитель автора/исполнителя, конкретные люди, поле
«Сотрудник(и)» или роль в проекте. Видит задачу и кнопку, получает
«Ждёт вашего решения»; после нажатия остаётся наблюдателем без звука.
Условие маршрута — `decider_in` (#433).
