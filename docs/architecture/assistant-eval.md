# Eval каталога инструментов ассистента (#926)

Измеритель качества выбора инструментов ИИ-ассистента: золотой набор реальных
запросов, детерминированный прогон и CI-гейт. Каталог растёт партиями (#927–#932);
без измерителя «стало ли модели удобнее» отвечается количеством инструментов, а
не качеством выбора. Методика принята ADR-0051.

## Что мерим

| Метрика | Определение | Порог гейта |
| --- | --- | --- |
| `recall@7` | доля ожидаемых инструментов, попавших в top-7 выдачи | ≥ 90% |
| `allExpected@7` | доля запросов, где ВСЕ ожидаемые инструменты в top-7 | справочно (цель ≥ 80%) |
| `wrongToolRate` | доля запросов, где в top-7 попал запрещённый (правдоподобно неверный) инструмент | < 5% |
| `refusalAccuracy` | доля noTool-запросов, где не выбран запрещённый инструмент и нет записи без операции | ≥ 95% |
| `clarifySafety` | доля запросов «нужно уточнение», где не выбран заведомо неверный инструмент | ≥ 90% |
| `top1Accuracy` | доля запросов, где первый инструмент — ожидаемый | справочно |

Метрики считаются для двух траекторий:

- **`tools.search`** — лексический поиск второй полки (top-7 кандидатов). Ошибка
  здесь не равна ошибке агента: кандидаты отсекает модель/диспетчер.
- **диспетчер (симулятор)** — детерминированный прокси LLM-диспетчера #917:
  понимание запроса (модуль, объект, класс действия, имя человека, номер
  сущности), проверка возможности операции (`hasCapability`) и скорер
  `tools/retrieval.ts`. Гейт по неверному инструменту и отказу — здесь.

Модель и сеть в CI не используются: прогон воспроизводим, стоит ноль и не
флакает. Живой прогон реальной модели — отдельная самопроверка перед партией
(см. «Что модель говорит о каталоге»), не гейт.

## Золотой набор

`apps/api/src/modules/assistant/eval/golden/` — 120 запросов четырёх ролей
(ГИП, секретарь, администратор, рядовой сотрудник), по 30 на роль:

- ~50% официальных формулировок, ~30% разговорных, ~20% с сокращением/опечаткой;
- 96 запросов с инструментами, 18 «инструмента нет» (`noToolCase`), 6 «нужно
  уточнение» (`shouldClarify`);
- у каждого кейса — `expectedTools`, `forbiddenTools` (правдоподобно неверный
  инструмент) и обоснование; данные обезличены (вымышленные ФИО, объекты, номера).

Проверки целостности — `eval/golden-set.test.ts`: размер 100–150, роли и формы,
существование id, отсутствие пересечения «ожидаем/запрещён», покрытие каталога,
отсутствие реальных почт/телефонов.

**Переобучение**: кейсы детерминированно делятся на `dev` (75%) и `holdout`
(25%) по хешу id; отчёт печатает обе части. Holdout не используется для правок
описаний — расхождение чисел сигнализирует о подгонке.

## Как гонять

```bash
pnpm assistant:eval       # гейт: печатает сводку, падает при регрессии
pnpm assistant:catalog    # линтер стандарта описаний + каталог
pnpm --filter @nodus/api exec vitest run src/modules/assistant/eval  # весь eval-слой
UPDATE_ASSISTANT_EVAL_REPORT=1 pnpm --filter @nodus/api exec vitest run src/modules/assistant/eval/eval-report.test.ts
```

Отчёт с числами до/после и списком промахов — `docs/architecture/assistant-eval-report.md`
(генерируется, руками не правится). Карта поверхностей — `assistant-surface.md`,
стандарт и каталог — `assistant-tool-standard.md`.

## Что модель говорит о каталоге

Детерминированный скорер не заменяет живой язык. Перед партией (и после неё)
проводится самопроверка: модели дают 30–50 задач сотрудников с каталогом
(название + описание + whenToUse), просят выбрать инструменты и логируют:
переспрашивания, путаницу имён, «не нашёл», недостающие в описании слова.
Результат — правки `title`/`keywords`/`whenToUse`, а не изменения скорера.
Живой прогон через провайдера ассистента выполняется владельцем при наличии
ключа; в ночной смене без ключа используется модель харнесса разработки — это
качественный сигнал, в гейт не входит.

## Добавление инструмента (обязательный цикл)

1. Маршрут API + zod-схема уже есть (I2), права — как у API (I8).
2. Определение в `tools/definitions/<модуль>.tools.ts`: `api`, `input`, `build`,
   `project`/декларативная `projection`, для записи — `card` (ADR-0048).
3. Стандарт в `tools/definitions/meta/<модуль>.meta.ts`: `why`, `whenToUse`,
   `whenNotToUse`, `subject`, `effect`, `example`, `returns`, `nextStep`, `intent`.
4. Тесты: проекция/сборка тела/карточка с человеческими именами, 403 без права,
   идемпотентность по id карточки.
5. Кейс(ы) в золотом наборе на реальной формулировке; `pnpm assistant:eval` —
   recall@7 не падает, неверный инструмент не растёт.
6. `assistant:surface` + `assistant:standard` — документация в том же коммите;
   README модуля — вручную.

Партия, ухудшившая метрики или не прошедшая линтер, не мержится: откат и
фиксация в отчёте. Партия, провалившаяся дважды, помечается `blocked`.

## Остаточные риски

- **Лексический прокси ≠ LLM.** Скорер объясним и воспроизводим, но не ловит
  сложные перифразы; живой eval обязателен перед пилотом.
- **Золотой набор создан агентами.** Формулировки правдоподобны, но не заменяют
  интервью; пополняется реальными фразами владельца/сотрудников.
- **Дубли смысла** ловятся линтером по порогу сходства — тонкие различия
  («история» vs «журнал») остаются на ревью описаний.
- **Опечатки** покрыты словарём и 4-буквенными ключами, а не полноценной
  морфологией/спелл-корректором; экзотические опечатки могут промахнуться.
- **Стоимость и задержка** диспетчера измеряются на живом прогоне (событие
  `tools.routed`); детерминированный eval их не заменяет.
