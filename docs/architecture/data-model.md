# Модель данных (верхнеуровневая)

Фиксирует состав и связи сущностей; детальная схема — в Prisma (`prisma/`). Новые **доменные** сущности — через ADR; вспомогательные таблицы (join, настройки) добавляются по мере реализации без ADR.

Читать: перед проектированием миграций и новых сущностей.

## Сущности

- **MessageLink** (проекция URL сообщения на запись, #211: витрина «Ссылки» и счётчики без скана текстов) — **LinkPreview** (кэш превью ссылок по нормализованному URL, статусы pending|ready|failed|blocked, TTL, #212/ADR-0018) — **ConversationVaultStats** (денормализованные счётчики витрины беседы, Δ в транзакциях состава) — **ThreadParticipant** (участник треда: автор/ответивший/наблюдатель/упомянутый + watermark прочитанности треда)
- **Notification** (получатель, kind «что случилось», priority urgent|high|medium|low «насколько важно» — ADR-0017, источник, payload-выжимка, прочитано/ознакомлено, seq-курсор дельты) — **NotificationDelivery** (журнал доставок ws/repeat) — **NotificationSetting** (личные настройки каналов и приоритетов)
- **UserPreference** (#745, таблица `user_preferences`: `user_id` PK — plain UUID без FK, I3; `data` JSONB — `UiPreferences` из contracts: порядок/скрытые модули навигации и `cardTabs` — личные области вкладок проекта/задачи/письма; `updated_at` Timestamptz — last-write-wins). Одна строка на сотрудника; файловые id вложений в `cardTabs` не хранятся — только плейсхолдер `files`; битый JSONB читается как дефолт, не роняет портал. API — `GET/PUT /api/v1/me/preferences` (модуль `preferences`, субъект — только текущий пользователь, I8).
- **Event** (таблица `events`: id, тип события, глобальный `seq`, actor, aggregate_type/id, payload JSONB, created_at, published_at — метка диспетчера outbox, fanout_at — метка realtime-фанута) — append-only, инвариант I9; **EventDelivery** (event_id × handler — дедуп at-least-once доставки обработчикам)
- **AuditLog** (actor, действие, сущность, детали, ip/user-agent) — append-only
- **(задел)** **Revision** (entity_type, entity_id, поле, old_value, new_value, author, created_at) — версии diff-аемого контента: описание задачи, тело письма, текст сообщения. Поле-уровневая история остальных изменений покрыта EventLog (I9)
- **FeatureFlag** (ключ, включён, scope)
- **Session** (user_id, refresh-token hash, устройство/user-agent, ip, expires_at, revoked_at) — ротация и отзыв сессий
- **(задел)** **PushSubscription** (user_id, endpoint, ключи p256dh/auth, user-agent)
- **FieldDefinition** (M10, ADR-0029, #431; ревизия #631 — одно определение на портал): `number` (внутренний номер, sequence, адрес формул #632), тип: text | long_text | number (точность) | money (сумма + валюта из системного справочника `currency`) | date | datetime | duration (минуты) | bool | enum | multienum (`dictionary_id`, по id элементов `dictionaries`) | user | users | department | project | counterparty | task | letter | node | link (URL или путь `\сервер\…`); название (≤ 60, уникально на портале без учёта регистра), подсказка, настройки типа, значение по умолчанию (статика или снимок «подразделение автора»), `report_indexed`, `is_company` (глобальная переменная — значение одно на компанию в `company_values`, привязок и значений у записей не имеет), порядок, автор. Продуктового лимита нет, технический потолок 1000. Удаление физическое и разрешено всегда (значения стирают обработчики события `deleted`); смена типа — только расширяющая (text→long_text, enum→multienum, user→users). **Привязки «Где используется»** — `field_bindings` (определение × `process_type|project_type|node_kind`, полиморфный `target_id` без FK; слот формы места задаёт видимость/обязательность, привязка без слота законна — системные поля сеются на все места). Значения — JSONB `custom_fields` задач, писем, проектов, папок и контрагентов по id определения (GIN `jsonb_path_ops`; элементы списков — по id справочника). Уникальность имени — выраженный индекс `lower(btrim(name))` в миграции.
- **Dictionary** (#54; код kebab-case — стабильный ключ потребителей, название, иерархический, системный — создан миграцией и нужен коду) — **DictionaryItem** (dictionary_id, parent_id? — только у иерархических, название, код? — уникален в справочнике, порядок, активен/архивен) — архивация вместо удаления (I15), FK Restrict; ссылающиеся модули хранят UUID элемента без FK (I3). Системные справочники и их стартовые элементы — данными миграции (`INSERT … ON CONFLICT DO NOTHING`: правки администратора не перетираются). **Запись (с #431, Р10):** список создаётся с вариантами (код `list-<8hex>` генерирует сервер), вариант переименовывается, **удаляется физически** (вердикт владельца 25.10.2026 — у вариантов атрибутов нет архива: значения с ним читаются пустыми) и упорядочивается; системный справочник защищён (`DICTIONARY_SYSTEM_LOCKED`), имя варианта уникально среди активных под advisory-локом справочника. Системный `currency` («Валюты»: BYN, RUB, USD, EUR, CNY) — миграцией. Полный админ-контур — M12
- **(задел)** **EntityLink** (from: тип+id, to: тип+id, тип связи: related|derived_from|blocks|belongs_to, автор, created_at) — универсальные связи поверх явных FK; основа графа знаний портала
- **(ядро автоматизации — ADR-0037; реализовано #631)** **FieldBinding** (атрибут × тип задачи/письма | тип проекта | вид папки — привязки «Где используется»; `field_definition_types` удалена); значение ячейки — значение или формула (плашки по id определений, результат вычисляется на чтении, кэш — по триггеру) — **CompanyValue** (значение глобальной переменной, PK = определение) — **FormLayout** (форма любого типа: элементы с привязкой к атрибутам, ширина, своя подпись, состояние поля по статусу) — **RegistryKind** (вид реестра: колонки-привязки, форма строки, права, «только добавление», аннулирование) + **RegistryRow** (вид, значения атрибутов JSONB, контекст создания — проект, папка, задача, автор, время; аннулирование с причиной) — **NumberSeries** (условия «отдельно для», период, шаг и вид номера — #630 модель v3: правило на определении атрибута `counter`, серия 1:1 c `field_definitions.number_series_id`; «при создании» — у привязки, `field_bindings.number_on_create`) — **AutomationRule** (событие, условия, шаги, владелец, вкл/выкл) + **RuleRun** (журнал запусков) — **SavedView** (вид записей: сущность, колонки, фильтры, группировки, рамка; уровень — по умолчанию у типа, проектный, личный). Системные поля сокращаются до минимума ядра: шифр проекта, код папки, заказчик становятся атрибутами (expand/contract)

## Правила схемы

- Суррогатные UUID PK; `created_at/updated_at` везде; FK с onDelete явно — **но только внутри одного модуля**: между таблицами разных модулей — plain UUID без FK-констрейнта (изоляция модулей, I3; связь живёт на уровне приложения и событий).
- Мягкое удаление только там, где есть бизнес-смысл (сообщения, файлы).
- Индексы под запросы списков и FTS — с первой миграции. **Каждая FK-колонка — с индексом** (PostgreSQL не индексирует FK сам: без индекса каждая Restrict/SetNull/Cascade-проверка при удалении родителя и каждый джойн — seq scan; аудит #317).
- Классификаторы сущностей (тип объекта, тип проекта, вид работ) — обязательные кастомные поля (I14); перечень утверждается владельцем.
- Таблица `messages` партиционируется по месяцам **по триггеру** — при достижении десятков миллионов строк (контроль перед пилотом при росте объёма). До того — обычная таблица; курсор пагинации по `seq` и временные фильтры закладываются с первой миграции, чтобы будущий переезд на партиции не менял контракты.
- Миграции задним числом не изменяются — только новые миграции.
