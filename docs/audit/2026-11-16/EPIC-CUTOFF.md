## 1. Название и цель

**«Отсечка аудита: портал не падает, не теряет данные и не показывает чужое»**

Простыми словами. Перед тем как пускать в портал отделы, 40 проверяющих прошли по всему коду и собрали 707 замечаний. Перепроверка показала: по-настоящему опасных — три, серьёзных — около двадцати, остальное — мелочи и задел на рост. Эпик закрывает только то, из-за чего в первый месяц работы может случиться одно из четырёх:

1. **Портал лёг.** Сбой почты или одна неудачная формула останавливают всё, а не только свою часть.
2. **Кто-то увидел или изменил чужое.** Снятые права действуют ещё четверть часа; в канал секретного проекта можно добавить постороннего; следующий человек за общим компьютером видит данные предыдущего.
3. **Данные потерялись или испортились молча.** Не записалось отработанное время; в номер документа попал технический код; уведомление зависло навсегда.
4. **После сбоя нечем восстановиться.** Новая установка поднимается без мессенджера; прерванное обновление оставляет портал лежать; проверки перед слиянием кода можно обойти.

Что это даёт: портал, который можно показывать отделам, не опасаясь, что первый же сбой почты или любопытный сотрудник его остановит.

## 7. Порядок выкатки

1. **До слияния:** вся ветка поднята в песочнице; пройден смок и сценарии Ф0 повторно (теперь они обязаны не воспроизводиться); владелец посмотрел изменённые экраны.
2. **Слияние:** squash в `main` при зелёном едином гейте.
3. **Демо-контур** (`nodus.by`, с `main`) — первая остановка: день работы без новых ошибок в логах.
4. **Прод — только по команде владельца «ОБНОВИТЬ ПРОД»**, навык `nodus-release`. Перед выкаткой: ручной дамп базы (пока нет #472), чтение `feature_flags`, проверка сохранённых формул на вложенные агрегаты.
5. **Флаги:** новых не вводим. Переключатели уже есть — `mail-reception` (выключает приём почты целиком), `OFFICE_EDIT_ENABLED`, новые переменные пула (AUD-022). Поведение AUD-007 (удаление файлов) стоит включать отдельной выкаткой после #472.
6. **После выкатки:** смок (`scripts/prod-smoke`), наблюдение за логами api и gateway на предмет `unhandledRejection`, `NOGROUP`, ошибок бюджета формул, сообщений о пропущенных письмах.
