# ADR-0039. Состояние главного окна оболочки между запусками — официальный tauri-plugin-window-state

- **Статус:** Принят
- **Дата:** 2026-11-13
- **Контекст:** issue #722 (P2, «оболочка не помнит состояние окна и свёрнутость левого меню»), указание владельца 10.11.2026: дефолт первого запуска не менять, помнить именно последнее состояние; окно — помнить режим (обычное/развёрнутое), а не открывать всегда полноэкранным.

## Контекст

Главное окно оболочки создаётся билдером с жёсткими параметрами
(`inner_size(1280, 800).min_inner_size(1024, 660).center()` в
`apps/desktop/src-tauri/src/lib.rs`): размер, позиция и признак
maximized/fullscreen не сохраняются между запусками. Пользователь каждый раз
получает окно 1280×800 по центру, даже если работал развёрнутым на втором
мониторе. Свёрнутость левого меню — веб-стор каркаса
(`apps/web/src/app/shell/shell-store.ts`): `menuCollapsed` есть в состоянии, но
`partialize` персистил только тему и служебную полосу, поэтому меню
разворачивалось после каждого F5 и перезапуска оболочки.

Требования (issue #722): помнить maximized/fullscreen и геометрию обычного окна;
на первом запуске/чистом профиле — текущий дефолт (1280×800 по центру, меню
развёрнуто); сброс настроек оболочки возвращает дефолт; в браузере меню тоже
переживает перезагрузку.

## Решение

### 1. Окно оболочки — официальный плагин `tauri-plugin-window-state` v2

Зависимость добавлена в `apps/desktop/src-tauri/Cargo.toml`, плагин
регистрируется в `lib.rs` с явными флагами:

```
SIZE | POSITION | MAXIMIZED | FULLSCREEN
```

- `VISIBLE` **не** восстанавливается: скрытость в трей — сессионное состояние,
  после выхода приложение всегда показывает главное окно.
- `DECORATIONS` не восстанавливаются: декорации окна — решение продукта, а не
  пользовательская настройка.

Восстановление происходит на `on_window_ready` — то есть при создании окна ДО
нашего `win.show()` (окно создаётся `.visible(false)` и показывается после
готовности мини-UI, канон #305) — мигания смены геометрии нет.

Без сохранённого состояния плагин записывает текущее состояние и **не двигает
окно**: дефолт первого запуска (1280×800 по центру) остаётся как был. Если
сохранённый монитор исчез (ноутбук в док-станции, отключённый внешний экран),
позиция не применяется — плагин проверяет пересечение с `available_monitors`,
окно остаётся по центру; размер применяется.

Сохранение — при move/resize (обновление кэша), на закрытии окна и на
`RunEvent::Exit` — файл состояния в каталоге приложения
(`.window-state.json`), вне репозитория и профиля пользователя портала.

### 2. Свёрнутость меню — persist веб-стора

`menuCollapsed` добавлен в `partialize` стора `nodus-shell-v1` и в
`shellEnvelopeSchema` (`.catch(false)`). Старый сохранённый envelope без поля
валиден и даёт `false` — развёрнутое меню, то есть продуктовый дефолт; версия
стора не поднимается (поднятие отбросило бы тему и полосу). Авто-раскрытия
меню на навигации в каркасе нет (раскрытие — только режим настройки
навигации), поэтому сохранённый выбор не затирается.

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
|---|---|---|
| Собственное хранение геометрии в app-data (`serde_json` + события окна) | Дублирует логику плагина: maximized требует запоминать позицию ДО максимизации (иначе окно восстанавливается в угол монитора), сохранение — по move/resize с отсечением minimized, восстановление — с проверкой существующих мониторов. Такое своё решение надо тестировать и сопровождать; плагин официальный и покрывает ровно это | Если плагин перестанет собираться с Tauri или понадобится нестандартная политика (например, якорение к «последнему активному» монитору) |
| Плагин с `StateFlags::all()` (включая VISIBLE/DECORATIONS) | VISIBLE восстановит скрытое в трей окно невидимым при следующем запуске (пользователь запустит приложение и не увидит окна); DECORATIONS — не пользовательская настройка | — |
| Не помнить окно (текущее поведение) | Прямое требование владельца 10.11.2026 | — |
| Синхронизировать свёрнутость меню на сервере (ui-preferences) | Настройка устройства и каркаса, а не данных портала; серверная модель персонализации — отдельная тема (партнёрская §10.5) | Когда персонализация каркаса переедет на API |

## Последствия

- Новая зависимость в оболочке (official Tauri plugin) + строка в
  `tech-stack.md`; релиз оболочки собирает CI (`desktop-release`), локально
  подписанные сборки не делаются.
- Сброс профиля оболочки (удаление `%APPDATA%\by.nodus.desktop*`) и очистка
  localStorage возвращают дефолт — критерий приёмки #722.
- На общем ПК свёрнутость меню — как и тема — привязана к устройству, а не к
  пользователю: второй вошедший видит выбор первого. Принято (тема ведёт себя
  так же); пересмотр — вместе с серверной персонализацией.
- Исчезнувший монитор: окно открывается по центру первичного, размер
  сохраняется — пользователь не получает окно за пределами экрана.

## Обоснование (research)

- Официальная документация Tauri 2: `v2.tauri.app/plugin/window-state/` —
  жизненный цикл (загрузка на setup, восстановление на создании окна,
  сохранение на выходе), рекомендация создавать окно с `visible: false`, чтобы
  восстановление не мигало.
- `docs.rs/tauri-plugin-window-state` — `StateFlags` (SIZE/POSITION/MAXIMIZED/
  VISIBLE/DECORATIONS/FULLSCREEN), `Builder::with_state_flags`.
- Исходник `tauri-apps/plugins-workspace/plugins/window-state/src/lib.rs`:
  восстановление позиции только если сохранённый прямоугольник пересекает
  существующий монитор; для maximized восстанавливается `prev_x/prev_y`
  (позиция до максимизации, Tauri issue #5812); состояние сохраняется на
  `RunEvent::Exit`; при отсутствии записи состояние инициализируется текущим.
