# ADR-0049. Каталог инструментов ассистента — контракт: типизированные проекции, сканер фантомов, карта поверхностей

- **Статус:** Принят
- **Дата:** 2026-11-17
- **Контекст:** эпик #889, issue #918; ADR-0043 (каталог = операция API), ADR-0048 (карточки действий); I12 (устаревшая документация = баг), I15 (никаких хард-строк), правило «изменение API = обновление zod-схем в том же коммите».

## Контекст

Каталог инструментов стал вторым потребителем API портала: каждый инструмент описывает маршрут, вход и **проекцию ответа**. Проекция — единственное место, где ответ API превращается в данные для модели. Пока проекции писались как `asRecord(...)` и обращения по строкам, случились две болезни:

1. **Дрейф API.** Маршрут или поле переименовали, а проекция осталась — тест на существование маршрута есть, на поля нет; ошибка всплывает уже в живом прогоне.
2. **Фантомные id.** Промпт или описание инструмента ссылались на удалённый `memory.list`; 18.11.2026 агент на живом прогоне заявил, что инструмент «не существует», и ушёл в обходной путь. Для модели упоминание в промпте = обещание инструмента.

Плюс ревьюер не видел, какие маршруты и DTO вообще «заняты» ассистентом: поверхность росла быстрее, чем документация.

## Решение

1. **Типизированные проекции.** `defineTool<S, TData>` (S — zod-схема входа, TData — тип проекции) и `asTyped<T>(contractSchema)` в `tools/projections.ts`: проекция объявляет тип из `@nodus/contracts`, а не собирает его «на глаз». Ответ валидируется схемой контракта (`asTyped`), поэтому переименование поля в контракте ломает сборку или тест, а не живой прогон модели.
2. **Сканер фантомных id.** `catalog-freshness.test.ts` собирает все упоминания `module.action` из системного промпта (в самом насыщенном варианте: все инструменты, память, MCP, продолжение) и из описаний/названий/ключевых слов инструментов; любое упоминание вне каталога — красный CI. Сканируются только пространства имён модулей ассистента, обычный текст с точками не задевается.
3. **Карта поверхностей.** `docs/architecture/assistant-surface.md` генерируется из каталога (`tools/surface.ts`): инструмент → название → вид → модуль → маршрут API → право → feature flag → горячая полка. CI сравнивает файл с генерацией (`surface.test.ts`) и падает при расхождении; обновление — `UPDATE_ASSISTANT_SURFACE=1` (команда в шапке файла).
4. **Правило DoD.** Изменил маршрут, DTO или право, которым пользуется ассистент, — в том же PR обнови проекцию инструмента, при необходимости `assistant-surface.md`, и прогони сканер. Это то же правило I12, но с механической проверкой.
5. **Смоук каталога.** Существующие тесты каталога (маршрут существует в OpenAPI, запись без карточки не регистрируется, лимит горячей полки) остаются обязательными; новые инструменты добавляются только вместе с тестом проекции на реальном ответе API (фикстура из контракта).

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
| --- | --- | --- |
| Генерировать проекции из OpenAPI | OpenAPI описывает форму ответа, но не «что нужно модели»; проекция — осмысленное сжатие, а не копия DTO | Появится машиночитаемая разметка «для агента» в схемах |
| Валидировать ответы в рантайме схемами контракта на каждом вызове | Двойная валидация на горячем пути; контракт уже проверен API | Если появятся внешние маршруты без zod |
| Сканировать весь `docs/` на фантомные id | Ложные срабатывания на исторические ADR и примеры | Никогда |
| Ручная карта поверхностей | Рассинхронизируется в первый же день (I12 без механизма) | Никогда |

## Последствия

**Проще:** переименование поля в контракте ловит CI, а не живая приёмка; ревьюер видит занятые маршруты одной таблицей; промпт не обещает несуществующих инструментов.

**Сложнее:** новый инструмент требует типизированной проекции и фикстуры (это осознанная цена); генератор карты надо запускать при каждом изменении каталога (команда в шапке файла и в DoD).

**Риски и меры:** сканер может пропустить id с заглавными буквами или дефисом — пространства имён фиксированы (`module.action`, snake_case), тест на самого сканера обязателен; карта может устареть при правке каталога без запуска теста — CI-проверка не даёт смержить.
