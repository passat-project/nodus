# ADR-0043. ИИ-агент портала: каталог инструментов, провайдеры, сессии и границы

- **Статус:** Принят
- **Дата:** 2026-11-17
- **Контекст:** решение владельца 17.11.2026 — сделать полноценного ИИ-агента портала, начиная с режима чтения; эпик #889; карточка инкубатора И-017 (один каталог — три потребителя, «три полки»); north-star §7; I2 (действие UI воспроизводимо через API), I8 (права на API), I9/I14 (события и данные), I10 (отключаемость), ADR-0032 (облачный контур поиска), #272 (ядро гибридного поиска), #19 (OpenAPI из кода). Концепт окна — ветка `feat/ai-assistant-concept` (геометрия и канон UI уже приняты).

## Контекст

Портал строится «под агента»: каждое действие уже воспроизводимо через API, данные структурированы, модули отключаемы. Но «чат с промптом» не масштабируется: при 30–50 инструментах точность выбора падает, а при сотнях описания инструментов съедают контекст. Нужна архитектура, в которую инструменты, навыки, MCP и знания добавляются без переписывания движка.

Владелец решил: первый режим — **только чтение**; все сотрудники; без навыков в первой версии; полноценная настройка провайдеров (OpenCode Go, OpenRouter, локальные); без лимитов запросов; MCP — только Exa; вложения — только метаданные; чаты — корпоративная переписка компании.

## Решение

1. **Модуль `assistant`** — не-ядровой модуль `apps/api/src/modules/assistant/`, за feature flag `assistant` (I10) и правом `assistant.use`; веб-фича `apps/web/src/features/assistant/`. Владелец данных — модуль; связность с другими модулями — только через API и `@nodus/contracts` (I3).
2. **Инструмент = действие API портала.** Каталог описывает операцию (метод + путь), zod-схему входа и компактную проекцию ответа. Исполнение — от имени сотрудника через Fastify `inject` с его `Authorization`: проходят те же guard-ы, права, валидация и идемпотентность, что и из UI. Второй бизнес-логики нет.
3. **Один каталог — три потребителя**: внутренний чат, будущий MCP-сервер и подсказки в UI. Имена инструментов — `module.action` (`tasks.list`), внешние — `ext.<server>.<tool>`; конфликты пространств исключены.
4. **Три полки**: 15–25 горячих инструментов в промпте; `tools.search` для полного каталога; навыки — позже. Поиск инструментов: сначала лексический по имени/описанию/ключевым словам, затем эмбеддинги на ядре #272. **Диспетчер (Decision-модель, #917) реализован:** дешёвая LLM по формулировке сотрудника и описаниям каталога выбирает top-7 до основного цикла; настройка — пара «провайдер + модель» в разделе «Провайдеры» (отдельной вкладки нет, решение владельца 18.11.2026). При успехе диспетчера активный набор = выбранные + `tools.search` БЕЗ горячей полки: 28 горячих + 7 выбранных превышают порог деградации выбора (~30 схем). Ошибка/таймаут/пустой ответ — горячая полка (запасной путь), событие журнала `tools.routed` фиксирует выбор и fallback.
5. **Read-only — жёсткий предохранитель** в реестре и исполнителе, а не в промпте: инструменты `kind: write` не регистрируются и не исполняются. Режим записи (Ф2) реализован отдельно по ADR-0048 — карточка подтверждения, байпас, пометка «через ИИ», идемпотентность.
6. **Сессии и прогоны — на сервере**: `assistant_sessions`, `assistant_messages`, `assistant_runs`, `assistant_run_events`, `assistant_tool_calls`. Стриминг — SSE поверх GET с восстановлением по `Last-Event-ID`; отмена — `AbortController`; результат не теряется при обрыве.
7. **Провайдер за портом `LlmProvider`**: реализация `OpenAiCompatibleProvider` (Chat Completions, стриминг, tool calls, usage) покрывает OpenCode Go, OpenRouter, OpenAI и локальные Ollama/vLLM. Настройки провайдеров и моделей — в БД, ключи шифруются `core/crypto`, наружу — только маска. Тяжёлые SDK не вводятся: native fetch Node 24.
8. **Границы данных**: вложения — метаданные всегда, текст PDF/DOCX — по ADR-0050 (`GET /files/:id/text`, права сотрудника, лимиты, без OCR); до #922 содержимое не читалось. Тела писем и чаты — в пределах прав сотрудника; чаты — корпоративная переписка компании, отдельного consent-переключателя нет.
9. **Навыки** — следующая фаза: `SKILL.md`-подобные инструкции с прогрессивным раскрытием (метаданные → тело → ресурсы), без исполняемого кода; редактор для админа.
10. **MCP** — следующая фаза и только как клиент для Exa (`https://mcp.exa.ai/mcp`, Streamable HTTP, `web_search_exa`/`web_fetch_exa`). MCP-сервер наружу и универсальный маркетплейс серверов сейчас не строятся; каталог к ним готов.
11. **RAG** — после #272: `search_knowledge` поверх FTS + pgvector + RRF + реранк, с цитатами и границами прав. Векторные эмбеддинги и реранк — за портами ADR-0032.
12. **Без квот запросов** (решение владельца): только технические предохранители — максимум шагов, таймаут прогона, лимит размера результата инструмента и истории; учёт токенов — для видимости.

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
| --- | --- | --- |
| Инструменты вызывают сервисы модулей напрямую (импорт) | Ломает I3/I6, дублирует права и видимость, расходится с UI | Если inject станет узким местом по latency |
| Все инструменты всегда в промпте | После 30–50 инструментов падает точность, растёт цена каждого запроса | Каталог ≤ 10 инструментов |
| Тяжёлый агентный фреймворк (LangGraph/AI SDK) | Лишняя зависимость и слой магии; свой цикл проще тестировать и контролировать | Появится durable-исполнение с ветвлением сложнее нашего |
| Навыки в первой версии | Решение владельца 17.11: сначала чтение и действия; навыки — позже | Ф4 |
| MCP-сервер наружу сразу | Нет потребителя; владельцу нужен только Exa как источник | Появится внешний агент-клиент |
| Per-user consent на чтение чатов | Чаты — корпоративная переписка компании, доступ уже определён правами; переключатель только пугает | Появится личная переписка вне корпоративного контура |
| Сеть до своего API вместо inject | Лишний сокет, порт и риск обхода границ | Выделение ассистента в отдельный процесс |

## Последствия

**Проще:** новый инструмент — это описание API-операции, а не новый код доступа к данным; права и аудит работают автоматически; каталог переиспользуется для MCP и подсказок; провайдер меняется настройкой; локальная модель подключается тем же портом.

**Сложнее:** качество проекций и описаний инструментов (иначе модель выбирает неверно); SSE-восстановление и отмена; шифрование и ротация ключей; контроль prompt injection через результаты инструментов; при росте каталога — поиск и диспетчер.

**Риски и меры:** инъекция в текстах — результаты инструментов помечаются как данные, обрезаются, ссылки открываются только кликом; утечка ключей — шифрование, маска, запрет логов; чужие сессии — проверка владельца и 404; дорогие циклы — максимум шагов и таймаут, учёт токенов; дрейф API — тест сверки каталога с OpenAPI.

## Обоснование (research)

- Anthropic, Tool Search Tool / advanced tool use (ноябрь 2025): >30–50 инструментов — падение точности; поиск инструментов экономит ~85% контекста; 3–5 горячих инструментов остаются загруженными.
- Semantic tool routing (MCP-Zero, Dynamic ReAct, практика MCP-gateway): namespace → retrieval → rerank → 3–5 инструментов; иерархическое сужение каталога.
- Agent Skills (Anthropic, 2025): прогрессивное раскрытие «метаданные → тело → ресурсы», без загрузки всего навыка.
- MCP specification 2025-11-25: Streamable HTTP, tools/resources/prompts, OAuth 2.1/PKCE, tool poisoning/rug pull/confused deputy — учтены в модели угроз.
- OpenCode Go: OpenAI-совместимый `https://opencode.ai/zen/go/v1`, DeepSeek V4.1 Flash — 0 дней хранения, не для обучения; OpenRouter: `https://openrouter.ai/api/v1`, Chat Completions, tools; Exa MCP: hosted `https://mcp.exa.ai/mcp`.
