# ADR-0050. Текст вложений для ассистента: PDF/DOCX, права, лимиты, кэш

- **Статус:** Принят
- **Дата:** 2026-11-17
- **Контекст:** эпик #889, issue #922; ADR-0043 п. 8 (границы данных: «вложения — только метаданные»), ADR-0014 (ONLYOFFICE), ADR-0015 (превью), I8 (права на API), I11 (self-hosted), I7 (логи без секретов).

## Контекст

До #922 агент видел вложения только описью: имя, формат, размер. Живые сценарии («что в акте КС-2», «какие суммы в смете») требуют текста документа. Варианты — отдать модели подписанный URL (она его не откроет и это утечка), читать файл на клиенте (противоречит I2/I8) или извлекать текст на сервере в пределах прав сотрудника. Владелец просил именно ответы по содержимому, а не ещё один список.

Ограничения: портал self-hosted (I11), в стеке уже есть PDF.js на клиенте (просмотр), ONLYOFFICE для офисных форматов; бюджет одного прогона ассистента ограничен таймаутом и лимитом результата.

## Решение

1. **Отдельный авторизованный маршрут `GET /files/:id/text`.** Не `@Public`, без подписанных ссылок: обычная авторизация портала, права — существующий `OfficeSessionService.resolveAccess` (владелец файла, участник беседы с файлом, видимое письмо/задача). Чужой файл — 404, как и в остальных маршрутах файлов. Маршрут — под фичефлагом `assistant` (I10): без ассистента это лишняя поверхность чтения документов. Отдача только текста; имя файла и вид — для подписи цитат. В метаданных вложений (`letters.get`, `letters.attachments`, `chat.messages`) появился `fileId` — без него инструмент не может назвать файл; подписанные `url`/`pdfUrl` по-прежнему не выводятся.
2. **Инструмент `files.extract_text`** (`kind: read`, горячая полка) — проекция с номерами страниц и честной пометкой сканов. Модель цитирует «файл, страница»; ссылка на карточку файла — существующая навигация.
3. **Форматы и парсеры.** PDF с текстовым слоем — `unpdf` (сборка PDF.js для Node, MIT, без воркера и нативной сборки); DOCX — `mammoth` (BSD-2, извлекает чистый текст). Старый `.doc`, картинки и таблицы со сложной вёрсткой — вне скоупа. Фактический формат проверяется по magic-байтам (`%PDF-`, ZIP-сигнатура), переименованный файл получает `FILE_TEXT_INVALID`.
4. **Сканы не распознаются (OCR — отдельная фаза).** Страница БЕЗ текста помечается как «без текста»; страница с парой знаков (штамп, колонтитул) остаётся текстом и не противоречит пометке. Инструмент честно сообщает «страница N — скан, текста нет», модель не выдумывает содержимое.
5. **Лимиты — предохранители, а не обещания:** размер ≤ 20 МБ (413), страниц ≤ 100, знаков ≤ 60 000, таймаут 25 с (504). Усечение помечается `truncated`; инструмент обрезает проекцию до ~14 000 знаков с явной пометкой о продолжении. Сверх этого: ZIP-бюджет DOCX (центральный каталог + ФАКТИЧЕСКАЯ распаковка каждой записи архива под общим потолком — mammoth читает не только `word/document.xml`, поэтому одной записи недостаточно), текст PDF читается потоком (`streamTextContent`) с обрывом на постраничном потолке элементов/знаков, по таймауту PDF-документ уничтожается (`destroy`), лимит извлечений на сотрудника (10/мин) и одновременных извлечений на процесс (2) — 429 `RATE_LIMITED`.
6. **Кэш по версии файла.** `file_text_extracts` (file_id уникален, `version` файла): новая версия — пересчёт, повторный вопрос — из кэша. Параллельные запросы одного файла дедуплицируются в процессе. Кэш — производные данные, не секрет, но и не публикуется: маршрут всегда проходит права заново (кэш не заменяет авторизацию). Конфиденциальное вложение отсекается ДО кэша.
7. **Без BullMQ.** Извлечение ограничено 25 секундами и объёмом, укладывается в HTTP-запрос ассистента; очередь потребуется для OCR/таблиц и массовой индексации (следующая фаза, там же RAG по #272).
8. **Приватность.** Тела писем и чатов читаются в пределах прав сотрудника; отдельного consent-переключателя нет (решение владельца, как с чатами). **Конфиденциальные вложения не читаются ИИ ни при каком режиме** (граница эпика #889): контекст письма выставляет `textDenied` в `FileAccessDecision`, маршрут отвечает 403 `FILE_TEXT_FORBIDDEN` даже участнику и держателю `correspondence.view_confidential` — просмотр в браузере/офисе это вето не затрагивает. Текст файла не пишется в логи, аудит и журнал прогона: в `assistant_tool_calls.result_preview` и событие `tool.finished` уходит только шапка файла (имя, вид, страницы), не содержимое.
9. **Заражённые файлы** (`scanStatus: infected`) — 410 без извлечения; неподдерживаемый формат — 415; парсер упал — 422 `FILE_TEXT_INVALID`; лимит запросов — 429 `RATE_LIMITED`.

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
| --- | --- | --- |
| Подписанный URL файла в модель | Модель не скачивает; ссылка = утечка мимо прав | Никогда |
| ONLYSERVER/ONLYOFFICE для текста | Тяжёлый конвертер ради текста; сервис для совместной правки | Нужны правки документа агентом |
| `pdf-parse` | Обёртка над старым PDF.js, заброшена; `unpdf` — поддерживаемая сборка | Нет обновлений `unpdf` |
| OCR сразу (tesseract) | Тяжело, неточна для актов; отдельная фаза и очередь | Сканы станут частым сценарием |
| Извлечение на клиенте | Нарушает I2/I8, права обходятся | Никогда |
| Очередь BullMQ на извлечение | Латентность ответа агента важнее фоновой обработки; лимиты укладываются в запрос | Массовая индексация/RAG |
| Кэшировать навсегда без версии | Файл можно заменить; старая версия текста = ложный ответ | Никогда |

## Последствия

**Проще:** агент отвечает по содержимому актов, смет и писем с цитатами по страницам; права и видимость — существующие; текст не уезжает во внешние хранилища (только выбранному провайдеру модели в рамках запроса).

**Сложнее:** две новые зависимости (`unpdf`, `mammoth`) и парсерный слой; кэш-таблица; лимиты надо объяснять в UI («файл слишком большой», «скан без текста»).

**Риски и меры:** парсер на враждебном файле — ZIP-бюджет и потолки распаковки, лимиты размера/страниц, таймаут с уничтожением PDF-документа, лимит частоты/параллелизма, без сети из парсера; утечка текста в логи — логирование только метаданных и шапка файла в превью; права забыли на новом маршруте — маршрут использует `resolveAccess` и покрыт тестами «чужой файл → 404»; конфиденциальное письмо — отдельное вето `textDenied` и тест 403 до кэша; старая версия в кэше — ключ по `version`; модель выдумает скан — проекция явно помечает `scannedPages`.
