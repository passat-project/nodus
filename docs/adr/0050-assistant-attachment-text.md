# ADR-0050. Текст вложений для ассистента: PDF/DOCX, права, лимиты, кэш

- **Статус:** Принят
- **Дата:** 2026-11-17
- **Контекст:** эпик #889, issue #922; ADR-0043 п. 8 (границы данных: «вложения — только метаданные»), ADR-0014 (ONLYOFFICE), ADR-0015 (превью), I8 (права на API), I11 (self-hosted), I7 (логи без секретов).

## Контекст

До #922 агент видел вложения только описью: имя, формат, размер. Живые сценарии («что в акте КС-2», «какие суммы в смете») требуют текста документа. Варианты — отдать модели подписанный URL (она его не откроет и это утечка), читать файл на клиенте (противоречит I2/I8) или извлекать текст на сервере в пределах прав сотрудника. Владелец просил именно ответы по содержимому, а не ещё один список.

Ограничения: портал self-hosted (I11), в стеке уже есть PDF.js на клиенте (просмотр), ONLYOFFICE для офисных форматов; бюджет одного прогона ассистента ограничен таймаутом и лимитом результата.

## Решение

1. **Отдельный авторизованный маршрут `GET /files/:id/text`.** Не `@Public`, без подписанных ссылок: обычная авторизация портала, права — существующий `OfficeSessionService.resolveAccess` (владелец файла, участник беседы с файлом, видимое письмо/задача). Чужой файл — 404, как и в остальных маршрутах файлов. Маршрут — под фичефлагом `assistant` (I10) и правом `assistant.use` (I8): отзыв права закрывает и AI-чтение, и парсинг-нагрузку. Ответ `Cache-Control: no-store` (текст документа не кэшируется прокси/общими профилями), чтение пишется в `audit_logs` (`files.text_read`, актор/файл/IP/trace — без текста, `@Audit` интерсептор). Отдача только текста; имя файла и вид — для подписи цитат. В метаданных вложений (`letters.get`, `letters.attachments`, `chat.messages`) появился `fileId` — без него инструмент не может назвать файл; подписанные `url`/`pdfUrl` по-прежнему не выводятся.
2. **Инструмент `files.extract_text`** (`kind: read`, горячая полка) — проекция с номерами страниц и честной пометкой сканов. Модель цитирует «файл, страница»; ссылка на карточку файла — существующая навигация.
3. **Форматы и парсеры.** PDF с текстовым слоем — `unpdf` (сборка PDF.js для Node, MIT, без нативной сборки); DOCX — `mammoth` (BSD-2, извлекает чистый текст). Старый `.doc`, картинки и таблицы со сложной вёрсткой — вне скоупа. Фактический формат проверяется по magic-байтам (`%PDF-`, ZIP-сигнатура), переименованный файл получает `FILE_TEXT_INVALID`. `isEvalSupported` в PDF.js 6 отсутствует: eval в движке удалён в v5 вместе с PostScript-компилятором (Exa/PR #21005), CVE-2024-4367 закрыт версией 4.2.67+, у нас 6.4.299 — опция не нужна.
4. **Сканы не распознаются (OCR — отдельная фаза).** Страница БЕЗ текста помечается как «без текста»; страница с парой знаков (штамп, колонтитул) остаётся текстом и не противоречит пометке. Инструмент честно сообщает «страница N — скан, текста нет», модель не выдумывает содержимое.
5. **Лимиты — предохранители, а не обещания:** размер ≤ 20 МБ (413), страниц ≤ 100, знаков ≤ 60 000, таймаут 25 с (504). Усечение помечается `truncated`; инструмент обрезает проекцию до ~14 000 знаков с явной пометкой о продолжении. Сверх этого: ZIP-бюджет DOCX (центральный каталог + ФАКТИЧЕСКАЯ распаковка каждой записи архива под общим потолком — mammoth читает не только `word/document.xml`, поэтому одной записи недостаточно; сверяются ВСЕ шесть полей EOCD, включая disk/entries-on-disk, и отвергаются ZIP64-записи и ZIP64-локатор в комментарии EOCD — иначе JSZip читает скрытый каталог в обход бюджета), текст PDF читается потоком (`streamTextContent`) с обрывом на постраничном потолке элементов/знаков, лимит извлечений на сотрудника (10/мин) и одновременных извлечений на процесс (2) — 429 `RATE_LIMITED`.
6. **Кэш по версии файла.** `file_text_extracts` (file_id уникален, `version` файла): новая версия — пересчёт, повторный вопрос — из кэша. Параллельные запросы одного файла дедуплицируются в процессе; обрыв одного запроса не отменяет общий разбор, пока его ждёт другой, а последний ушедший убивает worker. Кэш — производные данные, не секрет, но и не публикуется: маршрут всегда проходит права заново (кэш не заменяет авторизацию). Конфиденциальное вложение отсекается ДО кэша.
7. **Разбор — в `worker_threads`, не в event loop API.** PDF.js и синхронный inflate DOCX — CPU-работа: в основном потоке крафтовый файл останавливал бы все маршруты портала, а `setTimeout` не прерывает синхронные фазы (security-ревью 18.11.2026). Поэтому `file-text.worker.ts` разбирает файл в отдельном потоке с `resourceLimits` (512 МБ old generation / 64 МБ young): OOM враждебного документа получает `ERR_WORKER_OUT_OF_MEMORY` и убивает поток, а не процесс API. `file-text.runner.ts` по таймауту или обрыву HTTP-запроса (`AbortSignal` из `reply.raw close`) вызывает `terminate` — работа не переживает ответ. Поток создаётся на извлечение (старт ~30–50 мс ≪ 25 с лимита; извлечения редки), память документа не остаётся между запросами. BullMQ сюда не подходит: его in-process worker исполняет процессор в том же потоке, CPU-bound разбор всё равно блокировал бы API; очередь остаётся для OCR/массовой индексации, где важна фоновая обработка.
8. **Приватность.** Тела писем и чатов читаются в пределах прав сотрудника; отдельного consent-переключателя нет (решение владельца, как с чатами). **Конфиденциальные вложения не читаются ИИ ни при каком режиме** (граница эпика #889): контекст письма выставляет `textDenied` в `FileAccessDecision`, маршрут отвечает 403 `FILE_TEXT_FORBIDDEN` даже участнику и держателю `correspondence.view_confidential` — просмотр в браузере/офисе это вето не затрагивает. Текст файла не пишется в логи, аудит и журнал прогона: в `assistant_tool_calls.result_preview` и событие `tool.finished` уходит только шапка файла (имя, вид, страницы), не содержимое; запись аудита `files.text_read` содержит только метаданные (файл, версия, IP, traceId).
9. **Заражённые файлы** (`scanStatus: infected`) — 410 без извлечения; неподдерживаемый формат — 415; парсер упал — 422 `FILE_TEXT_INVALID`; лимит запросов — 429 `RATE_LIMITED`.

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
| --- | --- | --- |
| Подписанный URL файла в модель | Модель не скачивает; ссылка = утечка мимо прав | Никогда |
| ONLYSERVER/ONLYOFFICE для текста | Тяжёлый конвертер ради текста; сервис для совместной правки | Нужны правки документа агентом |
| `pdf-parse` | Обёртка над старым PDF.js, заброшена; `unpdf` — поддерживаемая сборка | Нет обновлений `unpdf` |
| OCR сразу (tesseract) | Тяжело, неточна для актов; отдельная фаза и очередь | Сканы станут частым сценарием |
| Извлечение на клиенте | Нарушает I2/I8, права обходятся | Никогда |
| Очередь BullMQ на извлечение | In-process BullMQ-воркер исполняет процессор в том же потоке — CPU-bound разбор всё равно блокировал бы API; латентность ответа агента важнее фоновой обработки | Массовая индексация/RAG, OCR |
| Разбор в основном потоке с таймаутом | `setTimeout` не прерывает синхронные фазы PDF.js/inflate: крафтовый файл останавливает весь портал (security-ревью 18.11.2026) | Никогда |
| Кэшировать навсегда без версии | Файл можно заменить; старая версия текста = ложный ответ | Никогда |

## Последствия

**Проще:** агент отвечает по содержимому актов, смет и писем с цитатами по страницам; права и видимость — существующие; текст не уезжает во внешние хранилища (только выбранному провайдеру модели в рамках запроса).

**Сложнее:** две новые зависимости (`unpdf`, `mammoth`) и парсерный слой; кэш-таблица; лимиты надо объяснять в UI («файл слишком большой», «скан без текста»).

**Риски и меры:** парсер на враждебном файле — ZIP-бюджет и потолки распаковки, лимиты размера/страниц, разбор в отдельном потоке с `terminate` по таймауту/обрыву (event loop API не блокируется), лимит частоты и **одно параллельное извлечение на сотрудника** (иначе один актор занимает оба слота процесса), без сети из парсера; `resourceLimits` воркера ограничивает V8-heap, но не внешнюю память `ArrayBuffer` — остаточный риск OOM контейнера на крафтовом PDF принимается осознанно (файл ≤ 20 МБ, 2 слота); **в репозитории memory-лимит контейнера и алерт RSS не заданы** — это настройка выкатки (runbook), решение владельца; до её ввода риск остаётся и пересматривается при инциденте или переходе на отдельный процесс разбора; утечка текста в логи — логирование только метаданных и шапка файла в превью, `Cache-Control: no-store`, аудит без текста; кэш текста снимается при включении конфиденциальности (PATCH и окно регистрации) или удалении письма (события `correspondence.letter_updated`/`letter_deleted` с `fileIds`), плюс перепроверка прав перед записью кэша; права забыли на новом маршруте — маршрут использует `resolveAccess`, право `assistant.use` и покрыт тестами «чужой файл → 404»; конфиденциальное письмо — отдельное вето `textDenied` и тест 403 до кэша; старая версия в кэше — ключ по `version`; модель выдумает скан — проекция явно помечает `scannedPages`; рестарт API в окне резерва продолжения — `queued` закрываются `interrupted`, пачка возвращается в `open`.
