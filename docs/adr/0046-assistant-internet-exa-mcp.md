# ADR-0046. Интернет через облачный MCP Exa — управляемое исключение I11

- **Статус:** Принят
- **Дата:** 2026-11-17
- **Уточнение:** п. 2 («единственный внешний сервер») заменён ADR-0047 — реестр MCP равнозначен, подключаются все включённые серверы. Остальные пункты (ключ, границы данных, лимиты Exa) действуют.
- **Контекст:** I11 (self-hosted, zero cloud в рантайме) и north-star §7 («приоритет self-hosted, облако — исключение через ADR»). ADR-0032 разрешил облачные эмбеддинги/LLM смыслового поиска, ADR-0044 — облачного LLM-провайдера ассистента. Эпик #889, фаза Ф3 (#901): ассистент должен искать свежие нормы, цены и поставщиков в интернете со ссылками на источники. Своего поискового индекса у портала нет и в roadmap его нет; парсить поисковики самостоятельно — нарушение их условий и нестабильно.

## Контекст

Локальная модель может рассуждать, но не знает, что происходит в мире после её обучения. Для строительной компании это критично: изменения СП/СНБ, цены материалов, новые поставщики. Ассистент должен уметь: (1) сформулировать поисковый запрос, (2) получить выдачу со ссылками, (3) прочитать выбранную страницу, (4) сослаться на источник. Хранить и обслуживать свой веб-индекс — отдельный продукт, несоразмерный порталу.

Exa — hosted MCP-сервер (`https://mcp.exa.ai/mcp`, Streamable HTTP, инструменты `web_search_exa` и `web_fetch_exa`), который уже поддержан реестром MCP-серверов #902. Ключ — `x-api-key`; OAuth-режим не используем (нужен интерактивный браузерный вход, портал — серверный клиент). Query-параметр `exaApiKey` не используем: ключ только заголовком, чтобы он не попадал в URL и логи прокси.

## Решение

1. **Облачный MCP Exa — управляемое исключение из I11**, только для интернет-поиска и чтения публичных страниц. Действует, пока администратор завёл и включил MCP-сервер с ключом. Нет сервера/ключа — инструментов интернета нет, портал полностью self-hosted (ассистент работает по данным портала и честно говорит, что поиск не настроен).
2. **Единственный внешний сервер** — Exa. Другие MCP-серверы реестр технически примет, но подключение иного внешнего поиска — новое решение владельца, а не настройка по умолчанию. Из инструментов Exa портал использует ровно `web_search_exa` и `web_fetch_exa`; `agent_run` (многошаговый внешний агент) и `web_search_advanced_exa` не включены: внешний агент — неконтролируемая цепочка запросов и расходов.
3. **Инструменты каталога** — `ext.exa.web_search_exa` и `ext.exa.web_fetch_exa`, `kind: read`, `module: ext`, горячая полка. Права — `assistant.use` и флаг `assistant`; отдельного права на интернет нет (решение владельца: доступность ассистента = доступность поиска).
4. **Ключ — в настройках портала** (раздел «MCP»), шифруется `core/crypto` как ключи провайдеров; наружу только `hasKey`/`keyHint`. Сохранённый ключ не уходит на другой origin при смене адреса. Адрес — только https/443/публичный хост (гвард клиента).
5. **Границы данных — минимизация, а не жёсткий фильтр.** Наружу уходит только сформулированный моделью поисковый запрос (≤ 400 символов) и URL страницы; URL с логином/паролем отклоняется. Технически модель НЕ имеет инструментов, читающих тела писем, файлов и переписки (только проекции до 200–600 символов), а ключ и тело внешних ответов не попадают в логи. Но содержимое этих проекций модель видит, поэтому гарантия «в запрос не попадёт текст портала» обеспечивается правилами промпта, а не серверным фильтром: пользователь может сам попросить найти фразу, а инъекция из данных может подтолкнуть модель вложить фрагмент. Остаточный риск компенсируется аудитом `assistant_tool_calls.args` (видно, что именно ушло) и минимизацией выдач. Результаты Exa — внешние данные и в промпте помечаются как таковые.
6. **Лимиты и отказоустойчивость:** таймаут MCP-вызова 20 с, результат инструмента обрезается по `maxToolResultChars` (16 000), чтение страницы — 8 000 символов, запрос ≤ 400 символов, выдача 1–10 результатов (по умолчанию 5). Сбой MCP — ошибка вызова (`ASSISTANT_TOOL_FAILED`) с понятным текстом, прогон продолжается; «Стоп» рвёт вызов. Кэша нет в v1.
7. **Источники — ссылками.** Промпт требует указывать название и адрес страницы из выдачи и запрещает придумывать URL; ответ без ссылок на внешний факт считается неполным.
8. **Наблюдаемость:** каждый интернет-вызов — строка `tool_calls` прогона (имя, длительность, успех); ключ и тело внешних ответов в логи и аудит не пишутся.

## Приватность и остаточные риски

- **Exa хранит и использует запросы по стандартному договору.** Политика Exa (обновлена 29.06.2026) прямо говорит: Query Data используется для улучшения продуктов, включая обучение и дообучение моделей. Zero Data Retention доступен только на Enterprise-плане (12 000 $/год). Портал не покупает ZDR: это внешний облачный поиск, и заказчик должен знать, что поисковые запросы уходят в Exa по её условиям. Мера — минимизация: только короткий запрос и URL, без персональных данных и содержимого портала; при требовании ZDR — Enterprise-договор Exa (решение владельца, не код).
- **DNS-rebinding и подмена адреса** MCP-сервера — остаточный риск, зафиксированный в ADR-канале #902/README: адрес задаёт только администратор с `portal.settings.manage`, порт 443 и TLS-проверка остаются.
- **Качество и свежесть выдачи** — на стороне Exa; портал не гарантирует полноту и требует ссылку, чтобы сотрудник мог проверить факт.
- **Инъекция через внешнюю страницу** — страница может содержать инструкции. Защита та же, что для данных портала: результаты приходят в блоке `<data tool="…">`, промпт объявляет их данными, а не командами (ADR-0043).

## Альтернативы

| Альтернатива | Почему отклонена | Когда пересмотреть |
| --- | --- | --- |
| Свой поисковый индекс в портале | Отдельный продукт (краулер, индекс, ранжирование), несоразмерно порталу | Появится требование «данные не покидают контур» и бюджет на поиск |
| Прямой HTML-парсинг Google/Яндекса | Нарушает условия сервисов, нестабилен, блокировки | Никогда |
| Keyless-режим Exa (без ключа) | Rate-limit, только IPv4, нет гарантий квоты; ключ владельца — управляемый доступ | Если нужен «попробовать без ключа» — включить отдельной настройкой |
| OAuth-режим Exa | Нужен интерактивный вход в браузере; портал — серверный клиент | Появится штатный OAuth-контур для MCP |
| `agent_run` Exa (внешний агент) | Неконтролируемая цепочка внешних шагов и расходов; решение владельца — обычный цикл портала | Явное решение владельца |
| Локальная модель с web-плагином | Требует локального железа и своего поиска; нет ссылок-источников как контракта | Локальный контур с собственным поиском |

## Последствия

**Проще:** ассистент отвечает на вопросы о внешнем мире со ссылками; код не зависит от поисковика (MCP-реестр); отключение — снятие флага/сервера, портал возвращается в zero cloud.

**Сложнее:** зависимость от облачного сервиса в рантайме (деградация — понятная ошибка, не падение); админ должен завести ключ; политика хранения Exa требует осознанного согласия заказчика.

**Риски и меры:** утечка содержимого портала — правило промпта, лимит запроса, отсутствие доступа к телам; обучение на запросах — минимизация данных, ZDR только по договору; сбой/лимит Exa — ошибка вызова с повтором модели, портал работает; злоупотребление поиском — технические предохранители прогона (шаги, таймаут).

## Обоснование (research)

- Exa docs «Exa MCP»: hosted endpoint `https://mcp.exa.ai/mcp`, инструменты `web_search_exa` и `web_fetch_exa` включены по умолчанию, `x-api-key` — штатная авторизация; keyless-режим rate-limited и IPv4-only; `agent_run` требует OAuth/ключа.
- Exa auth.md: `https://mcp.exa.ai/mcp` — MCP-сервер, `https://api.exa.ai` — REST API; `x-api-key` или `Authorization: Bearer`.
- Exa Privacy Policy (29.06.2026): Query Data используется для улучшения продуктов, включая обучение и fine-tuning; персональные данные в запросы не вносить.
- Exa Zero Data Retention: доступен только Enterprise-плану (12 000 $/год); покрывает Search, Contents, Agent, Answer.
- exa-labs/exa-mcp-server (GitHub): OAuth и API-ключ равнозначны для MCP; `?exaApiKey=` существует, но портал использует заголовок (ключ не в URL).
- ADR-0032/ADR-0044: облачный контур уже принят как временное исключение; тот же принцип — отключаемость и минимизация данных.
