# ADR-0045. Markdown в ленте ИИ-ассистента: react-markdown + remark-gfm + rehype-sanitize

- **Статус:** Принят
- **Дата:** 2026-11-17
- **Контекст:** эпик #889, issue #897 (решение владельца 17.11.2026 на живой приёмке Ф1); ADR-0043; канон UI `nodus-ui-style`; I11 (zero cloud — зависимость локальная, рендер на клиенте).

## Контекст

Модели отвечают в markdown: списки, жирный, таблицы, код. Окно ассистента показывало сырой текст — `**`, `-`, простыни таблиц. Ассистент — единственное место портала, где ответ приходит от модели, а не от сотрудника: содержимое недоверенное (модель пересказывает письма и сообщения портала, где может быть инъекция), поток приходит по дельтам (в том числе оборванный).

Канон мессенджера — «простой текст + превью ссылок» (вердикты 2026-09): менять его нельзя, markdown живёт ТОЛЬКО в ленте ассистента.

## Решение

1. **Зависимости**: `react-markdown` (рендер в React-дерево без `dangerouslySetInnerHTML`), `remark-gfm` (таблицы, зачёркивание, task lists, автолинки), `rehype-sanitize` (белый список тегов/атрибутов). Все три — MIT, локальный рендер, сетевых вызовов нет.
2. **Санитайзер обязателен и входит в тот же ADR**: ответ модели — недоверенный ввод. `rehype-sanitize` с дефолтной схемой (GitHub) идёт после `remark-gfm`; `rehype-raw` НЕ подключается — сырой HTML в markdown не парсится, тем самым `<script>`, `<iframe>`, `onerror` не попадают в дерево вообще.
3. **URL**: `urlTransform` (дефолтный `defaultUrlTransform`) плюс собственное правило ссылок: внешние — `https?` с `target="_blank" rel="noopener noreferrer"`; внутренние `?cards=<kind>:<id>` — через существующий мост карточек; прочие протоколы (`javascript:`, `data:`, `vbscript:`) отбрасываются.
4. **Изображения не рендерятся.** `![x](https://…)` загружался бы браузером автоматически (трекинг-пиксель, эксфильтрация через URL ответа модели); раздел issue «изображения из markdown не входят», а внешние картинки в письмах портала уже блокируются до явного разрешения (ADR-0027). Компонент `img` возвращает `null`, тест «нет `<img>` и нет внешнего URL в DOM» — в наборе.
5. **Карточки — только проверенные.** `?cards=`-ссылка открывается мостом лишь для относительного `?cards=kind:<uuid>` с видом из белого списка: id подставляется в путь API карточки (`/tasks/<id>`), поэтому не-UUID и внешний URL с `cards=` карточкой не считаются (`assistant-card-link.ts`, общий с строками инструментов). Централизованная UUID-валидация самого стека карточек — отдельный issue (предсуществующая дыра deep-link).
6. **Место**: только лента ассистента (`features/assistant`). Общий `ChatMessageItem` получает опциональный слот текста (`textSlot`): мессенджер его не передаёт и рендерит простой текст как раньше; ассистент передаёт markdown только для сообщений ассистента (вопрос сотрудника — как есть).
7. **Оборванный стрим и стоимость рендера**: рендер идёт по накопленному тексту; react-markdown парсит документ целиком на каждый рендер, поэтому компонент мемоизирован, набор компонентов — модульная константа, а перерисовка отложена (`useDeferredValue`): недописанный ```‑блок или половина строки таблицы дают корректный частичный рендер, а не падение; лента не перепарсивает все видимые ответы на каждую дельту. Тест «оборванный блок» — в наборе.
8. **Стили**: токены темы (`bg-muted`, `border-border`, `font-mono`), обе темы; таблица — компактная, горизонтальный скролл ВНУТРИ пузыря (ширину окна не ломает); код-блок — копирование кнопкой; подсветка синтаксиса — отдельным решением (не входит).

## Альтернативы

| Альтернатива | Почему отклонена |
| --- | --- |
| Рендерить markdown в мессенджере тоже | Канон чатов — простой текст: markdown ломает привычку и вставляет разметку в деловую переписку |
| `dangerouslySetInnerHTML` + собственный парсер | XSS-поверхность вручную; react-markdown строит React-элементы, инъекция тегов невозможна по конструкции |
| `marked` + `DOMPurify` | Императивный DOM-путь, лишняя цепочка «строка → HTML → sanitize → React»; теряется контроль над ссылками и код-блоками |
| Подсветка синтаксиса (shiki/prism) сразу | Вес и тема-палитра ради первой версии; владелец просил читаемость, не подсветку |
| `rehype-raw` для HTML из ответа | Не нужен: модели не требуют HTML, а разрешение сырого HTML расширяет поверхность атаки |

## Последствия

**Проще:** ответы по 20 задачам и таблицам читаются как документ; код можно скопировать; ссылки открываются безопасно; мессенджер не изменился.

**Сложнее/риски:** три новые зависимости (обновления — через общий цикл); перерисовка длинного текста на каждой дельте (снята отложенным рендером); санитайзер может резать легитимные конструкции — схема расширяется точечно, с тестом; XSS-векторы обязаны оставаться в тестах (регресс-защита).

## Обоснование (research)

- react-markdown: официальная документация — `allowedElements`/`components`/`urlTransform`, `defaultUrlTransform` разрешает только `http(s)`, `irc(s)`, `mailto`, `xmpp` и относительные URL; официальная рекомендация — при `rehype-raw` обязательно `rehype-sanitize` (мы raw не включаем).
- Спецификация безопасности: react-markdown не использует `dangerouslySetInnerHTML`; санитайз остаётся вторым слоем (защита в глубину) на случай расширения схемы.
- Streaming: официальный код `Markdown` парсит полный документ синхронно (`processor.runSync`) — инкрементального парсинга нет; отсюда `useDeferredValue`, чтобы кадры стриминга не блокировались длинным ответом.
- GFM: `remark-gfm` — таблицы, task lists, зачёркивание, автолинки (соответствует ожиданию «как в GitHub»).
