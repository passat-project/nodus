# Монорепо и toolchain (pnpm, turbo, TS, ESLint)
- **CI-гейт diff-coverage (изменённые строки ≥ 80%) НЕ входит в локальные `pnpm lint/typecheck/test/build`** — зелёные локальные гейты не гарантируют PR: перед пушем прогонять `pnpm test:coverage` + `pnpm diff-coverage` (тот же скрипт, что в CI, читает lcov после coverage-прогона). Файлы вне `coverage.include` своего пакета (например, vite-плагины в корне пакета) в lcov не попадают и считаются 0% при живых тестах — включать явно (воспроизведено PR #624: 13.4% при зелёных локальных гейтах, починено include + тестами обвязки).

- **pnpm 10 НЕ читает поле `pnpm` в package.json** («The pnpm field is no longer read»): настройки (auditConfig.ignoreGhsas, overrides, onlyBuiltDependencies…) живут в **pnpm-workspace.yaml** (подтверждено docs.pnpm.io/settings, 03.10.2026 #187: ignoreGhsas в package.json молча игнорировался и аудит продолжал падать).

- pnpm 11 блокирует install-скрипты зависимостей: пакеты с бинарниками (esbuild, unrs-resolver) — в `allowBuilds` в `pnpm-workspace.yaml`, иначе падают в рантайме с невнятной ошибкой (в pnpm 10 механизм был `onlyBuiltDependencies`).
- **`turbo test` включает ВСЕ пакеты workspace с test-скриптом**: новый пакет с особыми рантайм-требованиями (браузеры Playwright в tests/e2e) падает в CI без этих требований — исключать фильтром в корневом скрипте (`turbo test --filter=!@nodus/e2e`), прогон — отдельной командой (`pnpm test:e2e`) и отдельной CI-джобой (подтверждено воспроизведением в issue #3).
- **YAML GitHub Actions: двоеточие+пробел в незакавыченной строке** (`name: E2E (путь: логин)`) — ошибка «workflow file issue» без job-логов, вся джоба молча не стартует; перед пушем workflow-файлов — локальный YAML-парсинг (подтверждено воспроизведением в issue #3).
- **Фоновые процессы в GitHub Actions умирают в конце шага** без `nohup ... > /tmp/x.log 2>&1 &`: «запустил сервер одним шагом, жду другим» падает с connection refused (подтверждено воспроизведением в issue #3).
- **`vite preview`/`vite dev` биндят `localhost`, который может уйти в ::1** (как и alpine-gotcha с musl, но на любой ОС): в CI и скриптах — явный `--host 127.0.0.1`, health-curl на тот же адрес (подтверждено воспроизведением в issue #3).
- pnpm 11 отклоняет зависимости, опубликованные < 24 ч назад (политика `minimumReleaseAge`, анти-supply-chain): свежая версия «не резолвится» — либо ждём окно, либо осознанное исключение в `minimumReleaseAgeExclude` там же.
- **pnpm 11 НЕ читает `pnpm.overrides` из package.json** («The "pnpm" field is no longer read», миграция на pnpm.io/settings): overrides живут ТОЛЬКО в `pnpm-workspace.yaml`, селективные селекторы версий там же без кавычек (`undici@>=8.0.0: 8.10.2` — кавычки в ключе ломают парсер селектора; подтверждено предупреждением самого pnpm и docs.pnpm.io/settings, #161).
- **Свежий security-advisory роняет CI-гейт `pnpm audit` на ВСЕХ открытых PR разом** (транзитивные цепочки не зависят от кода ветки): лечится селективными overrides в `pnpm-workspace.yaml` и ребейзом зависимых PR — иначе каждый PR «красный» без вины авторов (репро 30.09: undici GHSA-rfgv-xxqx-mfg5, #160/#161).
- **lint-staged гоняет eslint по ВСЕМ staged-файлам, включая временные**: probe-скрипт в `tests/e2e/tmp-*.mjs`, попавший в индекс через `git add -A`, роняет коммит (no-undef на импортах playwright) с неочевидным выводом в логе хука. Канон: временные пробы удалять ДО `git add` (подтверждено воспроизведением дважды, issue #4).
- **jsdom 30.1 × vitest ≤5.0.2 ломает `URL.createObjectURL` в jsdom-тестах** («Cannot read properties of undefined (reading '_buffer')»): compat-слой vitest ищет impl Blob через собственный Symbol, а jsdom 30.1 унёс его в приватное поле `#impl` (подтверждено upstream vitest-dev/vitest#11336, 14.10.2026). Держим jsdom 30.0.x — исключён из dependabot (`.github/dependabot.yml`), правило снять после фикса апстрима.
- Каждый пакет, наследующий пресеты `@nodus/config` (tsconfig/eslint), обязан декларировать его в своих dependencies/devDependencies — pnpm не даёт «соседских» пакетов, `extends` упадёт с «file not found».
- **Type-aware правила ESLint (`no-floating-promises`, projectService) требуют, чтобы файл принадлежал TS-проекту**: файл вне любого `tsconfig.json` даёт фатальную ошибку парсинга, и остальные правила на нём молчат (тест-кейсы `tests/lint/fixtures` перестали ловить boundaries, пока у фикстур не появился свой `tsconfig.json`); первый lint холодного проекта под параллельной нагрузкой turbo длится > 5 с — дефолтный таймаут vitest валил тест-кейсы линтера, таймаут поднят в скрипте `test` (воспроизведено дважды, #317).
- ESLint при явном пути к файлу берёт ближайший к нему `eslint.config.*` (а не корневой): вложенный конфиг `tests/lint/fixtures` не содержит ignores и файлы фикстур линтуются — исключения фильтруются вручную в `lint-staged.config.mjs`.
- **eslint-plugin-boundaries v7: паттерн file-дескриптора (`boundaries/files`) с полным путём от корня (`apps/api/src/modules/**/*.port.ts`) НЕ матчится — категория молча не назначается** (политика-исключение `to.file.categories` не срабатывает, запрет выше остаётся в силе); рабочая форма — `**/*.port.ts`, область сужается элементом в политике (`to: { element: { type: 'api-module' }, file: { categories: 'module-port' } }`). Порядок политик: побеждает последняя совпавшая, внутри одной политики disallow сильнее allow (docs jsboundaries.dev «Policies»). Миграция `mode: 'file'` → file-дескрипторы — официальный гайд v6→v7. (воспроизведением на фикстуре `tests/lint`, #320)
- **ESLint `max-lines` с `skipBlankLines+skipComments` (наш конфиг, max 500) считает МЕНЬШЕ `wc -l`** — пустые и коммент-строки выкидываются из счёта (подтверждено eslint.org/docs/latest/rules/max-lines): файл с wc=587 проходил гейт «на глаз» годами и упал только когда lint-staged впервые коснулся его коммитом (#243: conversations.repository.ts). Канон: размер файла проверять `npx eslint <файл>`, не wc; pre-commit (lint-staged) линтует только ИЗМЕНЁННЫЕ файлы — переразмерный файл молчит, пока ты его не тронешь.

- **Workspace-пакет `@nodus/contracts` отдаёт себя через `dist`**: после правки `src` контрактов тесты/typecheck потребителей тихо идут по СТАРОЙ сборке (значение undefined, `.includes(undefined)` молча false) — `pnpm --filter @nodus/contracts build` обязателен между правкой и прогоном. То же после `git checkout` ветки с другими контрактами: `src` меняется, `dist` остаётся от прежней ветки — vite build падает MISSING_EXPORT молча-старым экспортом (воспроизведено дважды: 05.11, PR #624).
- **Прямая зависимость обязана стоять ТОЧНО на версии override из `pnpm-workspace.yaml`**: диапазон в package.json + frozen-lockfile CI = OUTDATED_LOCKFILE; `pnpm install --lockfile-only` сам переписывает spec под override (проверено по lockfile #212).
- **`pnpm --filter pkg cmd -- --flag` доносит CLI литеральный `--`** (флаги не применяются, prisma висит на интерактивном промпте): флаги — через `pnpm --filter pkg exec <cli> --flag`, всегда с `</dev/null` (без stdin промпт падает громко, а не висит).
- **jsdom (nwsapi) не матчит не-BMP символы в attribute-селекторах** (`querySelector('[aria-label="👍"]')` → null при живом элементе, байты идентичны): искать `Array.from(...).find(el => el.getAttribute(...) === …)`; textContent-проверки эмодзи тоже ломаются, если глиф стал `<img alt>`.
- **Тест с захардкоженной «сегодняшней» датой — бомба замедленного действия** (упадёт сам через дни без чужих правок): даты — только динамические (`new Date()`) или `vi.setSystemTime` с возвратом; ловят только полные сьюты, не точечные прогоны.
- **Хук-менеджер — lefthook, но любая проверка в хуке всё равно требует `node` в PATH** (#706): husky падал с `code 127` там, где git запускает хук через свой sh, а PATH содержит только `/usr/bin`-подобные каталоги; lefthook git запускает как обычный хук-скрипт, а сами команды хука исполняет `sh` с PATH git'а — поэтому в рабочем окружении с node в PATH коммит проходит без `--no-verify` (проверено: `git commit` → `✔️ lint-staged`, `✔️ secrets`). Если node нет в PATH вообще, ни один менеджер хуков не спасёт — это ожидаемо; жёсткий барьер по секретам всё равно в CI. Спутник: `prepare` — свой `scripts/install-hooks.mjs`: в контексте без `.git` (docker build из `turbo prune`) он молча выходит, а на клонах с `core.hooksPath=.husky/_` сначала снимает устаревший путь, иначе `lefthook install` отказывается ставить хуки.
- **У gitleaks нет `detect --staged`** (в 8.30 подкоманды `dir` и `git`): staged-скан — `gitleaks git --staged`, рабочее дерево — `gitleaks dir <path>`; `detect` печатает usage и выходит с кодом 1, что легко принять за «секрет найден». Дефолтный конфиг allowlist'ит документальные примеры (`AKIAIOSFODNN7EXAMPLE`, тестовые `ghp_ABCDEF…`) — проверку делать реалистичным токеном (`ghp_` + 36 случайных alnum), иначе «зелено» ничего не значит (воспроизведено #706).
- **Vitest исполняет фабрику `describe.skipIf(cond)` даже когда набор скипнут** (#715, ревью 12.11.2026): конфиг/клиенты, созданные в фабрике, бросают на сборке тестов и валят файл вместо скипа — любой setup с env/сетью переносится в `beforeAll` под тем же `skipIf`.
