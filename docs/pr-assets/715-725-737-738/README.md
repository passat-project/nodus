  профиля: только «Профиль» и «Выйти»; вход в настройки портала остался один —

## #737 — состояние перетаскивания карточки канбана

- `02-kanban-drag__light.png`, `02-kanban-drag__dark.png` — первая карточка
  колонки «В РАБОТЕ» («Демо #434 · четыре из пяти, последний ждёт») удержана
  и проведена **внутри** колонки вниз, к стыку второй и третьей: борд
  переставил её живьём ещё до отпускания (в кадре она — третья, между
  «отчёты по разделу ОВ1» и «Проба замков …48.049Z»), drop показал бы ровно
  этот слот. Кадр снят до отпускания, затем Escape — данные не менялись.

## #725 — аватар: 24 Мп фото проходит, ошибка видна

- `03-avatar-before__light.png`, `03-avatar-before__dark.png` — своя карточка
  сотрудника без фото (инициалы) — состояние «до». Перед кадром старое фото
  убрано штатным «Убрать фото» (контекстное меню аватара).
- `04-avatar-after__light.png`, `04-avatar-after__dark.png` +
  `04-avatar-after-crop__*.png` — результат загрузки синтетического JPEG
  6000×4000 (24 Мп, 2,37 / 2,39 МБ): фото встало, тост «Фото обновлено».
  До фикса такое фото молча отклонялось серверным пиксельным потолком.
  В сеть ушло ~210 КБ вместо 2,4 МБ — клиентское сжатие сработало
  (`facts.json`, подтверждение — `.live-stack/api.log`).
- `05-avatar-error__light.png`, `05-avatar-error__dark.png` — ошибка показана
  пользователю тостом, а не «ничего не произошло»: выбран не тот формат
  (проверка до загрузки; отказ сервера по коду ошибки показывается тем же
  тостом — unit-тесты `avatar-invalidation.test.tsx`).
