# Runbook: создание сотрудника на проде

Учётная запись реального сотрудника на прод-контуре (nodus.by). Тестовые учётки песочницы сюда не относятся (они живут только в `nodus_night`, навык `nodus-dev-testing`).

1. `POST /api/v1/directory/users` под админом (вход `admin@nodus.by`): заголовок `Idempotency-Key` (новый uuidgen на каждый вызов), пароль 12–128 символов, только ASCII, обязательно верхний и нижний регистр, цифра и один из спецсимволов `@$!%*?&` (`passwordSchema` контрактов); логин — рабочий email в нижнем регистре (нормализация на входе, ADR про регистронезависимость).
2. Должность и подразделение — только существующие активные объекты своего вида (`management`/`legal`). Если кадровой должности ещё нет, сначала создать её: `POST /api/v1/directory/positions` с `{ "name": "...", "kind": "management" }`. Не выдумывать подразделение под одного сотрудника — при отсутствии отдела определить его в корень «ПассатПроект» и перевести позже.
3. Роль (`employee`/`head`/`admin`) — по `roleIds`; id ролей перечитать из БД, не хардкодить: `docker exec nodus_postgres psql -U <pguser> -d nodus -c "select id, code from roles;"`.
4. Добавление в канал «Новости компании» — прямой INSERT в `conversation_members` с явным `now()` для `joined_at` и `updated_at` (у `updated_at` нет DEFAULT в БД — значение ставит клиент Prisma, gotchas).
5. Проверка: логин под новой учёткой на nodus.by (или `POST /api/v1/auth/login` + `GET /api/v1/auth/me`); первую смену пароля сотрудник делает сам.
