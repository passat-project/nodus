# Runbook: обновление прода (docker-контур nodus.by)

**Цель:** выкатить выпуск `vX.Y.Z` с `main` на прод-контур этого хоста
(контейнеры `nodus_*`, `:3000/:3001/:3002`, туннель `nodus.by`) так, чтобы
пользователи получили новую версию и окно «Что нового».

Полный цикл выпуска (сбор изменений, тексты, релизный PR, тег, GitHub
Release) — навык `nodus-release`; этот runbook — шаги выкатки, смок и откат.
Будущий прод в компании обновляется так же: по тегу из чистого дерева.

**Предусловия:**

- выпуск смержен в `main`, тег `vX.Y.Z` создан и запушен;
- выкатка идёт из релизного worktree `../nodus-rel` — все команды этого
  runbook выполняются из него; прод собирается ИЗ его рабочего дерева, а
  основное дерево занято фича-ветками сессий — собирать прод из него
  нельзя; worktree отсутствует — создать: `git worktree add ../nodus-rel
  --detach vX.Y.Z` и скопировать боевой `.env` из основного дерева (без
  `MAIL_TEST_*`; права каталога — `repo-bootstrap.md` §9);
- рабочее дерево `../nodus-rel` чистое (`git status` пуст): незакоммиченное
  уедет на прод;
- `.env` заполнен, `NODUS_WEB_MOCK=false` (боевой режим web — build-arg,
  gotchas «VITE_* — build-time»);
- `NODUS_DESKTOP_DIR` задан **абсолютным** путём вне git-деревьев
  (`D:/NodusProd/desktop`): относительный резолвится от каталога
  compose-проекта и молча гасит кнопку «Скачать приложение» и автообновление
  оболочки (инцидент 02.11, #560);
- выпуск содержит миграции — сначала бэкап БД: `docker exec nodus_postgres
  pg_dump -U <pguser> nodus | gzip > ../nodus-backup-$(date +%Y%m%d-%H%M).sql.gz`
  (файл вне репо); «No pending migrations» в логе — не доказательство:
  применённость верифицируется по `_prisma_migrations` (список = локальные
  миграции `apps/api/prisma/migrations/`).

## Шаги

1. Встать на выпуск в `../nodus-rel` (`main` здесь не переключается — ветка
   занята основным деревом):
   ```bash
   cd ../nodus-rel
   git fetch origin
   git switch --detach vX.Y.Z
   git describe --tags --exact-match   # → vX.Y.Z, иначе стоп
   ```
2. Пересобрать и перезапустить (только изменённые сервисы пересоздаются;
   данные в томах `nodus_*data` не трогаются):
   ```bash
   docker compose --profile tunnel up -d --build
   ```
   Миграции БД применяет api при старте (`prisma migrate deploy` в CMD
   образа) — отдельной команды нет. Сборка web+api+gateway — несколько минут.
3. Дождаться здоровья: `docker ps --filter name=nodus_` — web/api/gateway
   `healthy` (api после миграций — до ~1 мин).

## Смок (только чтение — создавать данные и гонять пробы на проде запрещено)

```bash
curl -fsS http://localhost:3001/api/v1/health          # api жив, JSON 200
curl -fsS -o /dev/null -w "%{http_code}\n" https://nodus.by/   # 200 через туннель
node scripts/prod-smoke.mjs                            # главная, api, манифест оболочки, установщик
docker exec nodus_web sh -c "grep -l 'releases/X.Y.Z.json' /usr/share/nginx/html/assets/*.js" \
  | head -1                                             # бандл несёт новый выпуск
docker logs --since 5m nodus_api 2>&1 | grep -iE "error|migrat" | tail -20
```

`prod-smoke.mjs` — обязательный шаг: он проверяет то, чего старый чеклист не
видел, — что `/desktop/latest.json` отдаётся, версия в нём совпадает с
выпущенной, URL установщика абсолютный и файл скачивается. Красный смок =
выкатка не принята (портал без раздачи оболочки — флаг `--allow-no-desktop`).

Последняя команда — только у выпусков с текстами «Что нового» (технический
выпуск JSON не добавляет). Логи api: применённые миграции и отсутствие
ошибок старта.

## Откат

Выпуск сломал прод (контейнер не healthy, смок красный):

1. `git switch --detach v<предыдущий>` → `docker compose --profile tunnel up -d --build`.
2. **Миграции назад не откатываются** (только вперёд, навык
   `prisma-migrations`): expand-миграции (новые таблицы/колонки) старому коду
   не мешают; если выпуск содержал contract-изменение (drop/rename) — откат
   кода невозможен без восстановления БД, STOP & ASK владельца.
3. Worktree остаётся на открученном теге до следующего выпуска (шаг 1
   переставит его на новый) — отдельно возвращать нечего. Доклад владельцу +
   issue `type:bug` с механизмом; тег сломанного выпуска не удаляется
   (история), исправление выходит следующим патчем.
