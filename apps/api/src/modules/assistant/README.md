# Модуль assistant — ИИ-агент портала

**Назначение.** Диалог сотрудника с ИИ-агентом по данным портала в пределах его прав.
Ф1 «Смотреть» — чтение; **Ф2 «Делать»** — карточки действий с подтверждением и
байпасом (ADR-0048), включая личный блокнот сотрудника (#900); Ф3 — интернет через
облачный MCP Exa (ADR-0046); навыки (Ф4), знания (Ф5) — следующие фазы эпика #889.
Канон архитектуры — ADR-0043 (каталог, сессии, границы), ADR-0044 (облачный
провайдер — временное исключение I11), ADR-0046/0047 (MCP), ADR-0048 (действия).

## Ключевое решение: инструмент = действие API портала

Инструмент описывает **операцию API** (метод + путь + zod-схема входа + компактная
проекция ответа), а не код доступа к данным. Исполнение — Fastify `inject` с
`Authorization` сотрудника: проходят те же guard-ы, права, валидация и идемпотентность,
что и из интерфейса. Второй бизнес-логики и сервисного токена нет (I2/I3/I8).

Запись — **жёсткий предохранитель** в коде, не в промпте (ADR-0048): инструмент
`kind: write` не вызывает API из цикла, а создаёт карточку `assistant_actions`
(«что будет сделано»); запись выполняет только сотрудник кнопкой «Выполнить» или
байпас прогона (`assistant_runs.auto_execute`). `ToolExecutorService.execute`
отклоняет запись (`ASSISTANT_WRITE_NEEDS_CONFIRMATION`), прямой путь один —
`executeWrite` из `AssistantActionsService`; `Idempotency-Key` = id карточки.
Каталог не регистрирует запись без `card` (тест `catalog.test.ts`).

## Внешние MCP-серверы (#902, Ф3)

Реестр `assistant_mcp_servers` — настройка, а не код (ADR-0047): ВСЕ
включённые серверы равнозначны, «по умолчанию для поиска» не существует.
Exa (hosted, Streamable HTTP) — один из них, но с точными схемами поиска/#901;
любой другой MCP-сервер (Blender, GitHub, склад) отдаёт свои инструменты
как `ext.<слаг>.<инструмент>`. Клиент
`mcp/mcp-client.ts` минимальный (без SDK): `initialize` +
`notifications/initialized`, `tools/list`, `tools/call`; транспорт по
спецификации 2025-06-18 (`Accept` для JSON и SSE, `Mcp-Session-Id`,
`MCP-Protocol-Version`, повтор handshake на 404). Ключ — шифр `core/crypto`,
наружу только `hasKey`/`keyHint`; адрес — только https без query и фрагмента
(ключ не попадает в URL и в логи прокси).

Защита канала (ревью 17.11.2026): адрес — только https, порт 443 и публичный
хост (литералы loopback/приватных/link-local, FQDN-точка, docker-имена
`ip6-localhost`/`ip6-loopback` и встроенный в имя приватный IPv4 вроде
`10.0.0.1.nip.io` блокируются в клиенте — защита в глубину к схеме настроек);
`redirect: 'error'` — ключ не пересылается на чужой хост по 30x; тело ответа и
SSE-кадр ≤ 1 МБ, страницы `tools/list` ≤ 20, инструменты ≤ 200, имя и описание
инструмента обрезаются, текст `tools/call` — по `maxToolResultChars`; повторный
handshake ограничен одной попыткой (404 внутри него — ошибка, не рекурсия);
текст внешней ошибки (HTTP и JSON-RPC) в интерфейс и кэш не попадает — только
код. Сохранённый ключ не уходит на другой origin: смена адреса требует ввести
ключ заново или удалить его (ADR-0044 п. 4). Остаточный риск — DNS-rebinding:
резолв не пиннится (полное закрытие — кастомный `lookup`), адрес задаёт только
администратор с `portal.settings.manage`, TLS-проверка и порт 443 остаются.

Границы владения: сессия/прогон доступны только владельцу, чужая — **404** (не 403:
существование не раскрываем).

## Интернет: Exa через MCP (#901, Ф3, ADR-0046)

Единственный внешний сервер — Exa (`https://mcp.exa.ai/mcp`, Streamable HTTP, ключ в
заголовке `x-api-key`). Инструменты каталога — `ext.exa.web_search_exa` (запрос ≤ 400
символов, 1–10 результатов, по умолчанию 5) и `ext.exa.web_fetch_exa` (один URL,
`maxCharacters` 8 000): `kind: read`, `module: ext`, горячая полка. `agent_run` и
`web_search_advanced_exa` не включаются — внешний агент не должен крутить цепочки
запросов и расходов за порталом.

Инструменты появляются в прогоне из КАЖДОГО включённого MCP-сервера
(`McpSettingsService.resolveEnabled` → `externalMcpTools`): `tools/list` читается
на старте прогона, первые 3 инструмента сервера (≤12 внешних) сразу в native
`tools` как у Exa, остальные — через `tools.search` (сводка серверов в промпте
человеческими названиями), Exa получает
точные схемы поиска/чтения. Сломанный сервер пропускается; сбой реестра не валит
прогон — портал работает без внешних инструментов. Ключ нужен только тем серверам,
которые сами его требуют.

Промпт (при включённом интернете) требует: источники — ссылками из выдачи, без
выдуманных URL; результаты Exa — **внешние данные**, не данные портала. Приватность —
минимизация, не жёсткий фильтр: наружу уходит запрос (≤ 400 символов) и адрес
страницы без логина/пароля; инструментов, читающих тела писем и файлов, у модели нет,
но проекции портала она видит, поэтому «в запрос не попадёт текст портала» — правило
промпта, а не серверная гарантия. Что именно ушло — видно в
`assistant_tool_calls.args` (аудит). Ошибки внешнего сервера очищаются от ключа и
обрезаются (`McpClient.redact`). Политика хранения Exa — в ADR-0046: по стандартному
договору запросы могут использоваться для улучшения моделей; ZDR — только Enterprise.

## Каталог инструментов

Имена — `module.action` (`tasks.list`), внешние — `ext.<server>.<tool>` (Ф3). Полка:
15–18 горячих инструментов в промпте, остальные — через `tools.search` (лексический
поиск; эмбеддинги — позже, на ядре #272).

| Домен        | Инструменты                                              |
| ------------ | -------------------------------------------------------- |
| tasks        | `list`, `get`, `search`, `stages`, `history`             |
| projects     | `list`, `get`, `structure`, `members`                    |
| letters      | `list`, `get`, `transitions`, `relations`, `attachments` |
| chat         | `conversations`, `messages`                              |
| directory    | `find_users`, `get_user`, `departments`                  |
| dictionaries | `list`, `items`                                          |
| workflows    | `process_types`                                          |
| служебные    | `context.get`, `tools.search`, `ui.open_entity`          |
| ext (Ф3)     | `exa.web_search_exa`, `exa.web_fetch_exa`                |

**Границы данных (ADR-0043 п. 8, ADR-0044 п. 5):** вложения — только метаданные
(имя, формат/MIME, размер, дата, признак конфиденциальности). Содержимое файлов,
OCR и текст не читаются — инструмент `letters.attachments` не отдаёт ни `url`, ни
`pdfUrl`, и это закреплено тестом. Чаты — корпоративная переписка компании, доступ
в пределах прав сотрудника; отдельного consent-переключателя нет.

Списки — компактные проекции: до 20 строк, обрезка по лимиту символов с пометкой
«сокращено». Сырые JSON-простыни в промпт не попадают.

## Сессии, прогоны и стриминг

- `assistant_sessions` → `assistant_messages` → `assistant_runs` → `assistant_run_events`
  - `assistant_tool_calls`. `seq` на прогон (`@@unique([run_id, seq])`) — SSE `id`.
- `POST` сообщения создаёт сообщение и прогон, запускает цикл **асинхронно**, отвечает
  `202`: интерфейс сразу рисует вопрос (I4) и подписывается на поток.
- Рантайм-шина — `Map<runId, Subject>`: при подписке сначала отдаются сохранённые
  события с `seq > Last-Event-ID`, затем живые. Обрыв сети не теряет ответ.
- Отмена — `AbortController` (провайдер и инструменты), статус `cancelled`, частичный
  текст сохраняется.
- Токен сотрудника живёт только в памяти прогона и в БД не пишется.

## Лимиты (без квот)

Решение владельца: квот запросов нет — только техническая защита от зацикливания
(`@nodus/contracts` `ASSISTANT_LIMITS`): `maxSteps` 12, `maxRunSeconds` 120,
`maxToolResultChars` 16 000, параллельные вызовы — 3, история — 30 сообщений.
Действия (Ф2): до 5 карточек на прогон, захват карточки атомарный, зависший
`executing` перезахватывается через 60 с. Память (#900): 50 активных записей по
300 знаков, в промпт — до 2 000 знаков. Интернет (Ф3): таймаут MCP-вызова 20 с,
запрос ≤ 400 символов, чтение страницы — 8 000 символов, выдача ≤ 10 результатов;
кэша в v1 нет.

## События и аудит

Доменных событий в outbox модуль не публикует: изменения портала идут через API
модулей-владельцев (их события — там). События ленты действий живут в журнале
прогона: `action.proposed/executed/cancelled/failed/undone` (полный DTO карточки).

Аудит — `@Audit` на сообщениях/сессиях/настройках и явные записи действий:
`assistant.action_execute` / `assistant.action_failed` (в т.ч. при байпасе — там
нет HTTP-маршрута), `assistant.action_cancel/undo`, `assistant.memory_save/forget`.
В деталях — `viaAi: true`, инструмент, признак автоматического исполнения и прогон.
Вызовы инструментов — `assistant_tool_calls` (без полного содержимого); карточки —
`assistant_actions` (аргументы, результат, состояние).

## Проводники и секреты

`assistant_providers`: `base_url`, формат (`openai-chat`), тип авторизации
(`bearer`/`x-api-key`), шифртекст ключа (`core/crypto` `SecretBoxService`,
AES-256-GCM), хвост для узнавания, заголовки, модели (JSONB).
**Ключ не возвращается ни в одном ответе** — только `hasKey` и `keyHint`.
Env `SECRETS_ENCRYPTION_KEY` задаёт ключ шифрования; без него он выводится
(HKDF-SHA256) из `JWT_SECRET` — смена `JWT_SECRET` тогда обесценивает сохранённые
ключи провайдеров (админ вводит их заново).

## Структура

`assistant.module.ts` — wiring; контроллеры — HTTP; `*.service.ts` — логика;
`*.repository.ts` — единственная точка доступа к таблицам модуля;
`assistant-actions.*` — карточки действий (ADR-0048), `assistant-memory.*` —
блокнот (#900), `agent/agent-runner.*` — цикл и его помощники;
определения инструментов — `tools/definitions/<домен>.tools.ts` (запись —
`*-write.tools.ts`), провайдер моделей — `providers/`.
