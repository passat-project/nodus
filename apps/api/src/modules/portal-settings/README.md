# Модуль `portal-settings` — настройки портала

Назначение: общие настройки портала в таблице `portal_settings`
(ключ-значение, JSONB). Первая жилица — «Файловые серверы» (#558, ADR-0029
Р11): список папок `\\server\share`, внутри которых десктоп-приложение
открывает файлы значений «Ссылка или путь».

## API

| Метод | Путь                            | Право                    | Назначение                                 |
| ----- | ------------------------------- | ------------------------ | ------------------------------------------ |
| GET   | `/api/v1/settings/file-servers` | аутентификация           | Список разрешённых папок (читают все)      |
| PUT   | `/api/v1/settings/file-servers` | `portal.settings.manage` | Полная замена списка (идемпотентна, аудит) |

Тело PUT — `{ servers: string[] }` (`fileServersBodySchema` контрактов):
только `\\server\share`, без хвоста пути, максимум 50, без дублей без учёта
регистра. Ответ — `{ servers, updatedAt }`; пустой список значит «ничего не
открывается».

## Хранение и границы

- Ключ `desktop.fileServers`, значение `{ servers: string[] }`. Чтение
  толерантное: битые элементы и дубли отбрасываются, мусор не роняет
  страницу.
- `portal_settings` принадлежит модулю; связность — только
  `@nodus/contracts`. Доменных событий нет (это настройка, не сущность);
  запись действия — аудит `settings.file_servers_update`.
- Проверка прав — на API-гварде (I8), не только в интерфейсе. Матрица
  «Права доступа» раздела «Настройки» выдаёт `portal.settings.manage`.
- Список читается вебом и передаётся в мост оболочки как аргумент: Rust
  повторно проверяет грамматику пути, канонизирует цель (симлинк/junction
  наружу отвергается) и сверяет её с переданным порталом списком. Это защита
  от ошибки/подмены значения; граница доверия — origin портала (ADR-0019,
  ADR-0029 Р11), а не отдельная авторизация оболочки.
