# Модуль projects (API)

Ядро «Проектов» (#52, ADR-0030): проект-договор и «темы», типы, портфели,
двухрежимное участие, видимость `open|secret`, канал и дерево структуры
(#467, ADR-0030 «Дополнение»). Проект — контейнер задач: `Task.projectId` и
`Task.nodeId` — plain UUID без FK (I3), задачи живут в модуле tasks и
видимость их фидов расширена скоупом проектов (Р3 — в README tasks).

Модуль за фичефлагом `projects` (I10): флаг и права доезжают миграцией
`20261105000000_projects_core`, сид повторяет для свежей установки;
выключенный флаг закрывает HTTP (404), порты остаются живыми и нейтральными.

## Модель (вердикты владельца 29.10)

- **Проект** — шифр (системный атрибут «Шифр» `SYSTEM_FIELD_IDS.projectCode`;
  дубли разрешены — В2 #631; заказчик — атрибут «Заказчик», тоже системный),
  название, описание, цвет, тип (`project_types`, сид «Договор»/«Тема»; у
  типа — форма слотов атрибутов Р10 #631: посев «Договор» — «Шифр» обязателен,
  «Тема» — скрыт, везде «Заказчик» optional), портфель (`project_groups`,
  плоский список), даты, `custom_fields` JSONB. Колонки `code`/`client_id`
  заморожены (не читаются, значения переехали в атрибуты миграцией #631).
- **Руководство** — системные поля Руководитель (по умолчанию создатель) +
  Помощники (≤10): права уровня постановщика на все задачи проекта (Р12),
  правка полей, состав секретного. Каталог ролей проекта отменён — доп. роли
  атрибутами. Создатель, назначивший руководство другим, — наблюдатель-создатель.
- **Статусы**: `active` / `completed` (метка с `completed_at`) / `archived`
  (заморозка: создание задач — 422, правка полей и передача руководства —
  только `project.manage`; возврат — руководитель или `project.manage`).
- **Видимость**: `open` — список всем, состав живёт из задач; `secret` —
  список/карточка только участию + `project.view_secret` (роль «Системный
  надзор» для системной учётки; админы по умолчанию НЕ видят — модель
  Битрикс-суперадмина, ADR-0030). Смена на секретный — только руководитель,
  раскрыть может и помощник. Дефолт новых — настройка портала
  (`projects.defaultVisibility`, дефолт 'open').

## Участие — двухрежимное (Р2)

`project_participants` (PK проект+сотрудник+источник; у человека может быть
несколько источников одновременно):

| Источник                | Кто пишет                                                                                                                                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `manager` / `assistant` | синк из полей проекта при create/update/transfer (`syncManagement`)                                                                                                                         |
| `task`                  | только открытые: проекция живых задач (постановщик + ответственный + соисполнители, БЕЗ наблюдателей задач) по событиям `task.*` — идемпотентный пересчёт к `TASK_PROJECT_READER.membersOf` |
| `member`                | только секретные: руководство добавляет вручную (может получать задачи)                                                                                                                     |
| `observer`              | секретные — приглашение руководством; открытые — «Присоединиться» (joined); создатель-не-РП (creator)                                                                                       |

Открытый проект: участники руками не добавляются (живут из задач), но
руководство может вручную добавлять и снимать НАБЛЮДАТЕЛЕЙ (просмотр без прав
правки — вердикт 29.10 В2: «задавали наблюдателей для проектов, а участники
добавлялись бы автоматически из задач»); `open→secret` снимает динамику задач
(состав секретного полностью ручной), `secret→open` немедленно пересчитывает
из живых задач. `membersCount`/`membersPreview` — участники БЕЗ наблюдателей;
наблюдатели — отдельное поле карточки (`observers`). Секретный: задачи состав не
расширяют конструктивно — в задачу нельзя назначить (любой ролью, включая
наблюдателя) того, кто не состоит в проекте (`assertMembersAllowed` → 422).

События: `project.created` / `project.updated` (поля + clientId/
previousClientId для crm-проекции, `status` при статусном действии) /
`project.participants_changed` — outbox в той же транзакции (I9); изменение
состава поднимает `updated_at` проекта. Тот же журнал читает вкладка
«История» (`GET /projects/:id/history`, keyset по `seq`) — своей таблицы
история не заводит.

Обязательные слоты формы типа (I7/I8): создание без значения / очистка
патчем — 422 `PROJECT_FIELDS_REQUIRED {typeId, fields, reason: create|clear}`
(#631 Р10; «Шифр» — обычный атрибут в слоте).

## Дерево проекта (#467, ADR-0030 «Дополнение»)

Узлы-папки со свободной вложенностью («папки в проводнике, задачи — файлы»,
вердикт владельца 30.10); задачи — листья (`tasks.node_id`, модуль tasks).
Узлы БЕЗ архивации: пустой удаляется, непустой — 409 `PROJECT_NODE_NOT_EMPTY`.
Лимиты (контракты `NODE_LIMITS`): ≤1000 узлов на проект, глубина ≤10, детей
≤100, пакет ≤50; срез узлов одного проекта — без курсора (легализованное
исключение из I7, ≤1000). Порядок среди детей — fractional-ключ `order`
TEXT COLLATE "C" (канон 20261016180000, ключи — `core/lib/fractional-index.ts`);
все мутации — под advisory-локом структуры проекта (сериализация проверок
лимитов/циклов и записи).

- **Вид папки** (`node_kinds`, #556) — настраиваемый тип: ярлык (значок +
  цвет) и `config` — форма создания (слоты атрибутов в состояниях
  hidden/optional/required; системного ключа `code` больше нет — «Код»
  посевной атрибут, Р9 #631) и закрытый список `capabilities`
  (`document_changes`, `pulse_row`, `schema_row`). Слот формы вида и
  привязка «Где используется» (`field_bindings`, kind `node_kind`) — одна
  сущность: запись формы синхронизирует привязки. Справочник
  «Автоматизации»; удаление = архивация (папки архивного вида создавать
  нельзя — 409, существующие живут и правятся); имя уникально lower(btrim) —
  выраженный индекс в миграции; посев 6 видов (стадия, очередь, пусковой
  комплекс, здание по генплану, раздел, этап) + «Комплект» («Марка» и «Код»
  обязательны, три возможности). Все мутации — под
  advisory-локом `nodus:node_kinds`, событие `project.node_kind_changed`
  (каталожное, gateway → presence) в той же tx.
- **Значения атрибутов папки** (`project_nodes.custom_fields`, #556) — JSONB
  по id определения, GIN `jsonb_path_ops`; хранятся ВСЕ значения, включая
  скрытые сменой вида (форма фильтрует `nodeFormValues`); проверка — порт
  `CUSTOM_FIELD_REGISTRY` со скоупингом target `node_kind` (слот формы
  вида И ЕСТЬ привязка — Р3 #631). Политика формы — `node-form.policy.ts`
  (одна точка): обязательные после умолчаний при создании, очистка
  обязательного — 422 `clear`, смена вида — умолчания нового вида и
  проверка по next (`kind_change`). «Код» папки — системный атрибут
  `SYSTEM_FIELD_IDS.nodeCode` в слоте вида; legacy-поле `code` тела
  переводится в значение атрибута.
- **Допустимые виды типа проекта** (`project_types.kind_ids`, null — все):
  создание/смена вида вне списка — 422 `PROJECT_NODE_KIND_NOT_ALLOWED`;
  существующие папки не ломаются.
- **Код папки** — системный атрибут «Код» (Р9 #631): дубли разрешены (В2),
  правка `null` очищает; колонка `project_nodes.code` заморожена.
- **Права**: чтение структуры — видимость проекта (как карточка, секретный
  не-участнику — 404); мутации узлов — руководство проекта или
  `project.manage` (как правка полей); архив проекта — заморозка (400).
- **Rollups** прямых задач узла (счётчики, план/факт минут, ближайший/
  поздний срок) — порт `TASK_PROJECT_READER.nodeRollups` (один GROUP BY у
  владельца данных, I3); завершённость — канон `isCompletedState`;
  суммы поддерева клиент собирает по дереву (узлов ≤1000). Карточка проекта
  несёт `structureSummary {nodeCount, hasTaskNodes}` — сводку дерева для
  карточки; первичная вкладка всегда «Структура» (вердикт 04.11.2026).
- События (outbox в той же tx, I9; gateway не маршрутизирует узлы — реалтайма
  структуры до пилота нет): `project.node_created / node_updated /
node_moved / node_deleted`; `node_updated` несёт `customFieldChanges` и
  ключи `cf.<id>`; каталог видов — `project.node_kind_changed` (presence).
  Мутации — аудит (`project.node_*`) и `Idempotency-Key`. Негодный узел
  (не найден/чужой проект) — 422
  `PROJECT_NODE_INVALID` без оракула.

## API (`/api/v1/projects`, `@RequireFeature('projects')`)

| Метод и путь                                                          | Право                            | Что                                                                                                                                                                      |
| --------------------------------------------------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /?search=&portfolioId=&status=&visibility=&role=&cursor=&limit=` | —                                | журнал: видимый срез (открытые + моё участие), keyset `(updated_at,id)`                                                                                                  |
| `GET /:id`                                                            | —                                | карточка (секретный — участию/надзору, иначе 404 без оракула)                                                                                                            |
| `GET /:id/history?cursor=&limit=`                                     | —                                | вкладка «История»: outbox-события агрегата, новые первыми, keyset `seq`                                                                                                  |
| `POST /`                                                              | `project.create`                 | создание; дефолт видимости — настройка портала                                                                                                                           |
| `PATCH /:id`                                                          | руководство или `project.manage` | правка полей; `visibility→secret` — только руководитель                                                                                                                  |
| `POST /:id/status`                                                    | руководство или `project.manage` | статусы; возврат из архива — руководитель или `project.manage`                                                                                                           |
| `POST /:id/transfer`                                                  | действующий руководитель         | передача руководства; прежний без иных источников — наблюдатель-создатель                                                                                                |
| `GET /:id/members?cursor=&limit=`                                     | —                                | вкладка «Участники»: строки-источники                                                                                                                                    |
| `POST /:id/join` · `POST /:id/leave`                                  | —                                | вступление/выход (открытый; leave — только свой ряд вступившего)                                                                                                         |
| `POST /:id/members` · `DELETE /:id/members/:userId`                   | руководство (секретный)          | ручной состав member/observer (замена второй роли того же человека)                                                                                                      |
| `GET/PUT /settings/portal`                                            | PUT: `project.setup.manage`      | дефолт видимости новых проектов (окно «Настройки портала»)                                                                                                               |
| `GET/POST /types`, `PATCH /types/:id` (+archive/restore)              | `project.setup.manage`           | типы проектов: имя, значок, цвет, форма слотов `form` (слот = привязка атрибута, Р10), допустимые виды папок `kindIds` (null — все; негодный id — 422)                   |
| `GET/POST /groups`, `PATCH /groups/:id` (+archive/restore)            | `project.manage`                 | портфели (плоский список)                                                                                                                                                |
| `GET /projects/node-kinds`; POST/PATCH/архивация/restore              | мутации: `project.setup.manage`  | виды папок: форма, возможности (#556); имя lower(btrim) — 409; форма с неизвестным атрибутом — 422; запись формы синхронизирует привязки вида (слот = привязка, Р3 #631) |
| `GET /:id/structure`                                                  | —                                | дерево: папки (плоско, по order) + rollups + виды + ссылки значений одной пачкой (#467, #556)                                                                            |
| `POST /:id/nodes` · `POST /:id/nodes/batch` (≤50 имён)                | руководство или `project.manage` | создание папок/пакета (лимиты на пакет); значения по форме вида; архив проекта — 400                                                                                     |
| `PATCH /:id/nodes/:nodeId`                                            | руководство или `project.manage` | имя / код (null очищает) / вид / значения атрибутов                                                                                                                      |
| `POST /:id/nodes/:nodeId/move`                                        | руководство или `project.manage` | перенос: parentId (null — корень) + якорь beforeId/afterId; цикл — 409                                                                                                   |
| `DELETE /:id/nodes/:nodeId`                                           | руководство или `project.manage` | удалить ПУСТОЙ узел (задачи/дети — 409)                                                                                                                                  |

Права: `project.create` — всем ролям (CROSS JOIN миграцией);
`project.manage`/`project.setup.manage` — админ; `project.view_secret` —
роль «Системный надзор»; `project.channel.post` — **никому** по умолчанию,
включая админа (канал-объявление, паттерн Slack; выдаётся точечно матрицей
прав; исключение в `all-permissions.ts`).

## Порты (ADR-0012)

- `PROJECT_READER` (потребители: tasks, correspondence, custom-fields):
  `refsFor` (невидимые → пропущены), `viewScopeFor` (множества Р3, кэш 5 с),
  `assertTaskProjectVisible` (422 #432), `assertMembersAllowed` (422),
  `projectTaskRights` (supervisor), `assertNodeAllowed(projectId, nodeId)`
  (узел этого проекта, иначе 422; архивный проект — 400, дерево заморожено #467), `lockNodeStructure(tx, projectId)`
  (advisory-лок структуры на привязку задачи — не гоняется с удалением узла).
  Выключенный флаг — нейтрален.
- `PROJECT_CHAT_READER` (потребитель: chat): `roster`/`canView`/`canPost`/
  `refs` — канал проекта. Выключенный флаг — `roster` → null, `canView` →
  false.
- `TASK_PROJECT_READER` (живёт в tasks, потребители — проекция Р2 и
  структура #467): `membersOf(projectId)` (без наблюдателей задач),
  `projectIdOf(taskId)`, `nodeRollups(projectId)` (агрегаты прямых задач
  узлов), `hasNodeTasks(projectId)`.

`projects-ports.module.ts` — тонкий модуль экспорта портов (без HTTP);
`projects.module.ts` — контроллеры и сервисы. Канал проекта — модуль chat
(зеркало task-chat, Р8), не здесь.
