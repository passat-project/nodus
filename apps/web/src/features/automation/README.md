# features/automation

Раздел «Автоматизация» — единый дом настройки (эпик #377, north-star §5):
вкладки в топбаре шелла — **«Процессы»** (#428, ADR-0024; единый вход #857),
**«Атрибуты»** (#431, ADR-0029), «Реестры» и **«Права доступа»** (#379,
ADR-0034). Вкладки «Схемы проектов» больше нет (#857): легаси-адрес
`tab=project-schemas` перехватывает `beforeLoad` маршрута /automation
(`app/legacy-automation-search.ts`: `type`→`ptype`, `kind`→`ftype`).

**Веб-раздел — композиция API двух модулей.** «Процессы» (`apps/api/src/modules/workflows`,
ADR-0024): типы процессов, их маршруты и публикация — эндпоинты `/workflows/types*`,
`/workflows/*` (README `apps/api/src/modules/workflows/README.md`). Типы категории
`task` дополнительно читают задачные хуки — `shared/api/process-types-api.ts`.
«Права доступа» — API модуля `directory` (`/directory/roles*`, README
`apps/api/src/modules/directory/README.md`): общая матрица «роль × право»
живёт в `shared/access` и `shared/api/roles.ts` (её же переиспользуют другие
модули и #432).

## Состав (#378, #431, #379)

  (`fields` → реестр атрибутов, `access` → матрица прав, иначе «Процессы»);
  «Процессы» и «Атрибуты» — окна-сплиты, матрица — таблица во всю ширину.
  Слоты «Процессов» (рабочая область типа проекта, окна создания, архивация

  projects (I6, прецедент renderCreateField).
- `components/processes/processes-screen.tsx` — единый вход «Процессы»
  (#857, единая модель §5): окно-сплит в грамматике мессенджера. Слева
  колонка из ЧЕТЫРЁХ групп в строгом порядке — Проекты (последней строкой
  «Без проекта»), Задачи, Письма, Папки; справа — по выбору строку:
  редактор маршрута (возможно, с дорожкой «Договор → Задание смежнику»

  `?type=` (маршрут), `?ptype=` (тип проекта), `?ftype=` (экран типа папки
  на всю область — перехватывает `AutomationRoute`, колонка скрыта),
  `?noproject=1`; приоритеты и умолчания — чистая функция
  `resolve-surface.ts` (ftype > type > ptype > noproject; умолчание —
  первая живая строка «Проектов», без права — первый тип задач; выбранный

  `project.setup.manage`, «+» в заголовках — по правам (у «Писем»
  создания нет: каталог заморожен, #55).
- `components/processes/unified-type-list.tsx` (+ `unified-type-row.tsx`,
  `unified-type-menus.tsx`, `unified-meta.ts`) — колонка: группы
  сворачиваются, поиск один на все (фильтрует по имени, раскрывает группу
  с найденным, прячет пустые), «+» в заголовке создаёт тип категории
  (в т.ч. копией), архив — свёрнутой группой внизу со всеми категориями
  вместе. Строка: плитка-значок + имя + мета (проекты — «7 типов»,
  задачи/письма — «Разрешён: Договор, Тема +2» / «Разрешён везде» /
  «Без проекта» из `typeConfigOf(t).creation`; конфигурация скрыта
  сервером — меты нет; папки — «1 атрибут»), меню «⋯» по ховеру —
  настройки/копировать/архив.
- `components/types/*` — диалог создания типа процесса
  (название/значок/цвет/основа «копия или простой»; категория — задача),
  настройки типа — правая панель-колонка (свойства сохраняются сразу,
  оптимистично).
- `components/editor/*` — редактор маршрута (#378 ред. 2, рефы Jira / Трекер):
  - `route-toolbar.tsx` — верхний бар окна h-14 с линией: тип и состояние,
    проблемы, «+ Статус», «+ Переход», «Упорядочить»; справа «Сбросить» и
    «Опубликовать» (не уезжает никогда — контейнерные брейкпоинты);
  - `route-canvas.tsx` — холст `shared/flow` (ADR-0022): общая раскладка,
    12 точек подключения, подписи на стрелках, метка «Любой статус», старт
    «Создание задачи»; масштаб и отмена — слева внизу; клик по любому узлу
    открывает панель (статус — свою, метка — своей кнопки, старт —
    начального статуса);
  - `panel/*` — правая панель: полновысотная колонка как панель беседы
    мессенджера (`side-panel.tsx`, выезжает и сужает холст), одна анатомия у
    статуса, кнопки и действия (`panel-kit.tsx`: поля → строки «›» → удаление),
    разделы «Действия» (кнопки без смены статуса, #633: список, порядок,
    добавление) и «Кнопки из статуса» (порядок, добавление, «Как увидят в карточке»
    со «Смотреть как»), «Кто видит», «Условия перехода», «Особые правила»
    (условие пропуска — постановщик = исполнитель или утверждающий сам сдал,
    #430);
    «Настройки типа» из меню «⋯» строки открываются ДЛЯ ЭТОЙ строки
    (`settingsTypeId`, а не boolean + selected) — выделение редактора не
    меняется (#409);
  - `publish-dialog.tsx` — сводка, обязательные переносы, блок «Кого
    затронет» (типы и число сущностей в полёте, #430) и live-warnings;
    отказы сервера понятны: 409 — «Загрузить свежую версию», 422 «нужен
    перенос» — выбор цели, 422 «схема с проблемами» — список, прочее — текст
    ошибки.
- `model/route-doc-store.ts` — zustand-стор рабочей копии (ADR-0021):
  документ со статусами, кнопками и ОБЩЕЙ раскладкой холста, история
  (снимки ≤100), черновик в localStorage `nodus-workflow-draft-v2:<workflowId>`
  (zod на границе, версия-гейт). `dirty` — только правки структуры
  (`structureChanged`): расстановка — оформление. При загрузке baseline и
  документ проходят ОДНУ канонизацию (`canonicalDocument`: sortOrder
  статусов — индекс в группе, кнопок — индекс в группе fromStageId), потому
  что сервер отдаёт глобальную нумерацию, а клиент после правок — групповую;
  без этого вход показывал ложное «есть изменения» (#409). После публикации
  правки закрыты (`pendingReload`), пока не придёт свежий документ сервера:
  `sync()` перечитывает его по смене версии — `baseVersion` берётся только
  из документа сервера, черновые `new:*` повторно не уходят.
- `model/route-doc-layout.ts` — сопровождение раскладки на каждом шаге:
  `freezeLayout` («что видишь — то и стоит»: первая правка фиксирует
  картинку целиком), `settleLoops` (сдвинутые обходы не слипаются),
  `settleLabels` (подписи не наезжают на узлы и друг на друга),
  `persistedLayout` + `layoutFingerprint` (что и когда автосохранять).
- `model/use-layout-autosave.ts` — расстановка уходит на сервер сама
  (`PUT /workflows/:id/layout`, 600 мс тишины, без новой версии);
  смена типа, уход со страницы и «Опубликовать» отправляют несохранённое
  сразу (`flushLayoutAutosave`: места стоящих элементов сервер при
  публикации берёт из сохранённой раскладки). Чужая сохранённая
  расстановка той же версии приходит в открытый редактор (`sync` →
  `adoptSavedLayout`), свои неотправленные места остаются.
- `lib/plural-ru.ts` — формы множественного числа (сводка публикации).
- `api/automation-api.ts` — CRUD типов, публикация и сохранение расстановки,
  подсказки имён `useStageNames` (кэш — `workflowKeys.stageNames`, #430); кэш
  типов — `automationKeys`, в `shared/api/automation-keys.ts`: его читает
  WS-инвалидация каталожных событий `workflow.*`; кросс-фичевые хуки типов
  категории задачи — `shared/api/process-types-api.ts` (там же
  `defaultProcessType` — тип по умолчанию экспресс-формы и доски проекта).
  Моки — `api/mocks/automation-handlers.ts` (проверки
  `checkWorkflowDocument`, конфликт версий, переносы, постоянные id вместо
  `new:*` при публикации — `publish-resolve.ts` — как сервер).

## Окно перехода (#380)

Инспектор кнопки: раздел «Окно перехода» (`window-section.tsx`) — тумблер,
заголовок (пусто — название кнопки), шесть разделов в фиксированном порядке:
поля, трудозатраты (режим «если ещё не списаны» / «всегда»), итог, файлы
(подпись + минимум 0–5 = валидатор `result_files`), сообщения из чата как итог,
причина/комментарий. «Обязательно» у времени/итога/файлов правит **гейты**
(Р3), у причины и сообщений — собственный флаг раздела. «Посмотреть окно» —
настоящий `TransitionWindow` в режиме превью (без данных, отправка неактивна).
Правки формы — `model/transition-form.ts`; документ публикуется вместе с
кнопкой, черновики без формы читаются через default.

## Правила v2 (#430)

- **Присвоить номер** (#630, Р6): в панели кнопки задачи — тумблер «Присвоить
  номер» + выбор counter-поля типа (`transition-rules.ts`: `assignNumberFieldOf`
  / `setAssignNumber` → пост-функция `assign_number {fieldId}`); у писем —
  read-only «Настраивает система», как раньше. Нет counter-полей — тумблер
  выключен с подсказкой. Публикация проверяет цель (`number_field_not_in_type`
  / `number_field_not_counter`), серверная выдача — Пакет 2 #630.

- **Третий итог** — в панели статуса сегмент «Выполнена / Отменена /
  Отклонена»; уведомление `task.rejected` — автору и исполнителю.
- **Смысл кнопки** — сегмент «Ждёт нажатия / Служебная» в панели кнопки;
  умный дефолт от цели (пауза/отмена — служебная), при смене цели
  пересчитывается, если пользователь не выбрал вручную. `intent` идёт в
  документ/DTO и будет читаться «Моими действиями» (#438).
- **Подсказки имён** — `stage-name-field.tsx` (Popover под полем, клавиатура,
  счётчик «N маршрутов») + `GET /workflows/stage-names`; live-проверка
  получает имена и показывает `stage_name_shared`/`stage_name_similar`.
- **Предпросмотр публикации** — `publish-affected.tsx`: типы и «N задач в
  полёте» (незакрытые стадии, без мягко удалённых); `problems` редактора
  показывают warnings в диалоге, блокируют только ошибки.

## Вкладка «Атрибуты» (#431, ADR-0029; ревизия UI 25.10.2026)

Реестр атрибутов — кастомных полей сущностей (в коде — `custom field`):
определения по сущностям (задачи/письма/проекты/контрагенты), значения — в
JSONB сущности по id определения. Термин «Атрибуты» и модель «список по
центру, как в Битриксе» — вердикт владельца; архива нет: «Удалить» и флаг
«Скрытый атрибут».

- `components/fields/fields-tab.tsx` — шапка журнала (заголовок + счётчик,
  пилюля сущности, «Создать», поиск, шестерёнка) + каноническая таблица
  `shared/views` (`custom-fields.list`, колонки — `field-columns.tsx`) +
  меню строки (`field-row-menu.tsx`: изменить, поднять/опустить — порядок
  карточки, скрыть/показать, удалить) + островок пачки
  (`field-bulk-island.tsx`). Маршрут
  `/automation?tab=fields[&scope=<сущность>][&field=<id>]` (field — окно
  атрибута). Права — `custom_field.manage`; без права — просмотр.
  Для типа «Список»/«Несколько значений» и правки вариантов нужно ещё
  `dictionary.manage`: без него плитки недоступны с подсказкой, варианты —
  только чтение; название/подсказку существующего списка править можно,
  а отметка «По умолчанию» остаётся доступной — это настройка атрибута,
  не справочника (#491).
- `field-dialog.tsx` (+ `field-type-picker`, `field-dialog-form`,
  `field-settings`, `field-options-editor`, `field-default-value`) — ОДНО
  окно создания и правки фиксированной высоты: слева колонка типов, справа
  форма; всё правится в черновике (`lib/field-draft.ts` + тест) и уходит
  на сервер по «Создать»/«Сохранить» (варианты справочника → атрибут).
  Тип после создания закреплён, модификаторы («Многострочный», «Несколько
  значений») — односторонние; умолчание списка — флажок на варианте (модель
  Битрикс24), остальных — редактор карточки.
- `counter-rule-section.tsx` (+ `counter-rule-dialog.tsx`,
  `counter-template-editor.tsx`, `lib/counter-rule.ts`) — тип `counter` (#630, Р6):
  в основном окне — компактная сводка единого правила с примером; кнопка-калькулятор
  открывает конструктор «разрез × период × шаблон × старт» с живым предпросмотром
  и счётом выданных номеров; уходит в `numbering` тела create/PATCH определения.
  Разрез-формула — общий `TypeFormulaDialog`, который заменяет окно правила без
  третьего модального слоя; рендер предпросмотра — контрактный
  `renderNumberTemplate` (одна грамматика с сервером). Обычные `bindingFormulas`
  у counter отсутствуют: калькуляторы в «Где используется» скрыты, черновик и
  тела create/PATCH их не несут; серверный запрет — Пакет 2.
- `field-delete-dialog.tsx` — удаление одного/пачки: число заполненных
  карточек (сотрутся) и маршруты процессов, где атрибут стоит в окне или
  условии, — тогда удаление заблокировано со списком (`GET …/usage`).
- `api/custom-fields-api.ts`, `api/dictionaries-api.ts` — правка
  определений (оптимистично с откатом), удаление, «где используется»,
  применение черновика вариантов (`commitOptionDrafts`: удалить →
  переименовать → добавить → порядок).
- `lib/field-type-families.ts` — 20 типов → 17 семейств и модификаторы
  (семейство `counter` — #630).

## Вкладка «Права доступа» (#379, ADR-0034)

Срез общей матрицы «роль × право» по правам раздела: строки — каталог
`PERMISSION_CATALOG` контрактов (`module: 'automation'` — «Настраивать
процессы и маршруты», «Управлять атрибутами», «Управлять справочниками»),
столбцы — роли портала. Вкладка появляется по каталогу: `accessTab('automation')`
в `nav-registry` возвращает пусто у раздела без прав.

- `shared/access/module-access-matrix.tsx` — тело вкладки: шапка h-14,
  пилюля «Только просмотр» без `role.manage`, матрица, подпись «Изменения
  применяются у сотрудников после перезагрузки страницы или повторного входа».
- `shared/access/access-matrix.tsx` — презентационная матрица (прокрутка
  подводом к краю, закреплённые шапка и колонка прав, замок у «Администратора»).
- `shared/api/roles.ts` — роли и точечное переключение права
  (`PUT/DELETE /directory/roles/:id/permissions/:permission`), оптимистично и
  только по своей ячейке. Моки — `shared/access/mocks/roles-handlers.ts`
  (домен `roles`).
- Создание ролей и состав «кто в роли» — не здесь (инкубатор, И-022).

## Окно создания и настройки типа (#432, ADR-0024 п.5)

- **Форма создания** — раздел документа маршрута (`document.creation`),
  настраивается ВКЛАДКОЙ рамы типа «Форма создания» (единая модель
  «Процессов», #857): узел «Создание» на холсте (`START_NODE_ID`) и клик по
  проблеме формы в чипе «Проблемы» включают вкладку (проблема — и раскрывают
  настройки поля). Вкладка `components/editor/creation-form-tab.tsx` —
  редактор окна ЦЕЛИКОМ: то же тело `shared/forms/builder/form-builder-body.tsx`,
  что у окна кнопки перехода (лист в натуральную величину, «+» между строками,
  лоток «Добавить в окно», «Закрепить также»); хост полей —
  `creation-form-host.tsx` (#496: поля, атрибуты и блоки одним списком, общие
  настройки, формула названия). Правки идут прямо в черновик маршрута, каждая
  — один коммит стора (шаг истории), без «Готово»/«Отмена»; вступают в силу
  после «Опубликовать». Без права и у письма — просмотр; пока
  `document.creation === null` — тихая заметка «Стандартная форма». Один
  редактор на экран: под `suspended` вкладка пустая, как «Маршрут». Правой
  панели узла «Создание» и окна-конструктора формы нет: панель (`panel/
editor-panel.tsx`) открывается только нодами схемы. Правила слотов — общая
  грамматика `contracts/creation-form.ts` (`requiredAllowed`,
  `presetAllowed`, `checkCreationForm`): те же коды проблем, что в чипе
  публикации.
- **Карточка типа процесса в «Процессах»** (#857, ревизия 26.11.2026) —
  `components/processes/process-type-card.tsx`: одна рама с типом проекта и
  папки, вкладки — только большие поверхности: «Маршрут» (редактор схемы,
  действия «Опубликовать / статус / переход / упорядочить» — в правой части
  полосы вкладок через портал `route-editor.tsx` → `route-toolbar.tsx` и
  шестерёнка настроек; инструменты холста — только на «Маршруте», чип
  проблем и «Опубликовать» общие), «Форма создания» (см. выше) и «Где
  создаётся» (#665,
  `components/processes/process-type-creation-tab.tsx` — журнальный список
  типов проектов с тумблерами, bulk-островком и созданием типа проекта).
- **Рама без мерцания при выборе** (#857, К4) — `components/processes/
processes-screen.tsx`: пока списки колонки грузятся, рабочая область пуста
  (`aria-busy`; заглушка «Создайте первый процесс» — только по пустым
  спискам); пока грузится маршрут следующего типа, рама держит прежнюю пару
  «тип + маршрут» и меняется один раз (`keepPreviousData`); первого маршрута
  рама ждёт и появляется сразу с графом (отказ сервера — «недоступно», под
  карточкой стека — рама без редактора). Маршруты живых типов предзагружаются
  при входе в раздел (`api/routes-prefetch.ts`: в свободное время, потолок
  `ROUTE_PREFETCH_LIMIT`), места бара заполняются только при смонтированном
  редакторе; вид холста при появлении или смене графа ставит свой синхронный
  впис `shared/flow/flow-autofit.tsx` (не `fitView` движка: тот идёт через
  очередь и кадр и вписывал прежний граф под новый тип — К4, Д1).
- **Рабочий масштаб холста** (#857, Д2) — `shared/flow/working-viewport.ts`
  (чистая функция + unit-тест): `zoomFit` (padding 0,2, maxZoom 1) не ниже
  `WORK_ZOOM_FLOOR` 0,6 — весь граф по центру; ниже — масштаб 0,6, граф
  началом (в `WORK_INSET` 32 px от края), если граф шире холста, иначе по
  центру; по вертикали так же: по центру, выше холста — верхним краем в 32 px.
  Действует при появлении графа, смене типа и «Упорядочить» (плавно, 200 мс);
  размер холста и добавление статуса вид не трогают. «Вписать» на панели
  холста — весь граф целиком при любом размере (`minZoom` холста 0,1).
  Ключ вписа (`fitKey`) обязан меняться в одном рендере с узлами — из того же
  снапшота источника графа, иначе вписывается прежний граф. Размер холста впис
  берёт из самого элемента: стор движка узнаёт о смене размера позже измерения
  узлов (рамы задачи и письма разной высоты), впис по прежней высоте уводил
  граф от центра на полразницы.
- **Окно настроек типа** (`process-type-settings-dialog.tsx`; из `⋯` строки
  и шестерёнки полосы) — в стиле окна атрибута: название, значок, цвет,
  описание, «Где создаётся» (без проекта, вид папки), доступ
  (`editor/panel/type-settings-access.tsx`), блоки карточки и названия ролей
  (`editor/panel/type-settings-card.tsx`), нумерация письма (read-only) и
  архив; у писем всё только для чтения (каталог системный, #55).
  Сохраняются СРАЗУ (`PATCH …/config`, оптимистично, мутации одного типа по
  очереди; текст — по уходу фокуса, `commit-field.tsx`). «Создают: никто,
  кроме администратора» — это `creatable=false` (прежний `PATCH` типа);
  «Стандартный» заблокирован (по нему создают быстрые входы). Состав
  карточки — представление, не права. Флага «в пульсе проекта» у типа нет
  (вердикт владельца 26.10.2026): что видно в пульсе, решает проект (#469).
- Примитивы панели — `panel-kit.tsx` (`PanelField`, `PanelNote`,
  `SwitchRow`, `SectionLink`, `ModeChoices`, `PanelAction`, `PanelDanger`):
  тихие ghost-действия вместо outline-кнопок, тумблер одного размера.

## Границы

- Фича **не импортирует** `features/tasks` (eslint-boundaries): общее живёт
  в `shared/flow` (движок холста, ADR-0022), `shared/workflow`
  («Схема маршрута», группировка панели процесса, значки типов),
  `shared/access` (матрица прав) и `shared/api/*-keys.ts`.
- Без права `workflow.manage` (по умолчанию — администратор; выдаётся во
  вкладке «Права доступа»): холст и панели только для чтения, бейдж
  «Только просмотр»; расстановка не сохраняется.
- Маршрут правится на клиенте и публикуется целиком (`display`/порядок кнопок
  задаёт сервер); удаления нет — архив (ADR-0021).

## Коллективная кнопка (#434, UI-срез)

- Раздел «Кнопку жмут несколько» живёт в панели КНОПКИ — `transition-press-section.tsx`; настройка — `transition.press`. Отдельного статуса и маршрута нет: обычная кнопка «Завершить»/«Ознакомлен» собирает отметки.
- Источники «кто жмёт» — `press-source-editor.tsx` (соисполнители, все сотрудники, роль, сотрудники, поле). Демо-тип «Заявка» — `request-workflow-document.ts`.
- Что заполняет каждый участник, задаёт ОКНО КНОПКИ (`transition.form`): поля, время, итог, файлы, сообщения и комментарий настраиваются в «Окне перехода» → «Редактировать окно» (#496). Отдельного списка разделов у сбора нет — окно одно на кнопку.
- Публикация и бэкенд подключены: `press` проходит publish → БД → документ, `PressRoundsService` стартует раунд и выполняет кворум, публикация при открытом раунде блокируется. Моки — только на `:5173`; `:4173` всегда non-mock.
