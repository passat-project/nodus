# Фича portal-tabs — web (#1038 фаза C)

Вкладки браузерного типа на веб-уровне (ADR-0055): полоса живёт в панели
безрамочного окна (`app/shell/shell-panel.tsx`), поэтому вся фича активна
ТОЛЬКО внутри оболочки — в браузере панели нет и стор не активен (контроллер
монтируется из AppShell с гардом `isDesktopShell()`).

## Модель (`model/tabs-store.ts`)

- Вкладка — адрес (pathname+search, БЕЗ hash) + закреп + сессионный заголовок
  (`title`, не персистится); у каждой вкладки СВОЯ история переходов
  (`histories: Record<id, {entries, index}>`, лимит 50, новая запись обрезает
  хвост «вперёд» — модель браузера). Персист (ключ `nodus-portal-tabs-v1`,
  envelope-валидация) — только `tabs` (id/url/pinned) и `activeId`: после
  рестарта история вкладки = её текущий адрес.
- `navSeq` — счётчик НАМЕРЕНИЙ навигации (switchTab/openTab(focus)/back/
  forward/closeTab активной): его рост контроллер исполняет навигацией
  роутера. `recordNavigation` намерения НЕ даёт — отражает уже случившийся
  переход. `activate` — низкоуровневая активация без намерения (роутер ведёт
  вызвавший — мост deep-link).
- Закреплённые — всегда ведущая группа; `moveTab` клампится в незакреплённый
  диапазон, закреплённые не перетаскиваются. Закрытие активной — сосед слева,
  нет — сосед справа; последняя — новая «/home».

## Контроллер (`model/use-tabs-controller.ts`)

Единственная точка связки с роутером TanStack (useRouter), монтируется ОДИН
раз из `app/shell/app-shell.tsx`. Три эффекта: старт сессии (seed текущим
адресом / restore navigate replace на активную, useLayoutEffect — до краски);
применение намерений (подписка стора: navSeq растёт → navigate push на
текущую запись активной вкладки); запись внешних навигаций
(`router.subscribe('onResolved')` — адрес, отличный от текущей записи
активной вкладки, пишется `recordNavigation`; «свои» переходы приходят ровно
на запись вкладки — совпадение адресов работает вместо внутреннего флага).
Здесь же регистрируется мост `shared/lib/tab-bridge.ts` (до регистрации no-op).

## Состав

- `components/tabs-strip.tsx` — полоса: иконка модуля (единый
  `app/shell/nav-registry`) + заголовок (сессионный `title` || метка модуля),
  ✕ по ховеру, закреплённые без заголовка, переполнение — горизонтальный
  скролл, «+» — новая вкладка `/home`; средний клик закрывает, ПКМ —
  закрепить/закрыть (Radix ContextMenu), HTML5 DnD без библиотек — сброс
  мягкой пунктирной зоной на кромке вставки.

## Точки «Открыть в новой вкладке» (через tab-bridge, focus:false — фон)

- Моно-вкладки раздела в топбаре: средний клик + ПКМ `tabOpenInNew`
  (`app/shell/top-bar.tsx`, только в оболочке — в браузере штатные ссылки).
- Строки списка бесед мессенджера: средний клик → вкладка `/chat/<id>`
  (`features/chat/components/conversation-list.tsx`).
- Заголовок «Чат·Имя»: `features/chat/pages/chat-page.tsx` ставит
  сессионный заголовок активной вкладке, уход со страницы снимает.
- Deep-link оболочки: `shared/desktop/use-desktop-bridge.ts` —
  `openOrFocusTab(url, '/chat')` (своя /chat-вкладка активируется, нет —
  новая) + navigate моста; трэд #300 — `?thread=`.

## Ограничения

- Заголовок ставится АКТИВНОЙ вкладке (порт моста); свой заголовок ставит
  пока только чат — cleanup его снимает только при уходе с маршрута беседы,
  когда активна вкладка беседы или вкладка без заголовка.
- В браузере средние клики/ПКМ-пункты вкладок не работают (гард
  isDesktopShell) — штатное поведение браузера не перехватывается.
- Точки «открыть в новой вкладке» — минимальный набор плана; расширение —
  отдельным решением.
