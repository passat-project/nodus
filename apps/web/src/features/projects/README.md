# features/projects

Проекты (#52, ADR-0030) в теме «Инструмент»: журнал-таблица, карточка в общем
стеке (ADR-0009), окно создания, вкладка «Схемы проектов» «Автоматизации».
Модуль на живом API; моки MSW повторяют серверные правила для демо-сборки.

## Журнал (`pages/projects-page.tsx`)

- **Левая колонка папок-портфелей** (#559, ADR-0030 доп. 02.11: портфель —
  папка журнала, не раздел «Автоматизации»): `components/portfolio-rail.tsx` +
  чистая модель `lib/portfolio-folders.ts`. Строки — «Все проекты» («Мои
  проекты» в режиме «Мои»), живые портфели со счётчиками `действует / всего`,
  «Без портфеля»; архивные папки — блок «Архив», ВСЕ (пустая архивная папка
  тоже видна — её нужно возвращать, а не терять). Выбранная папка раскрывает
  строки статусов «действует / завершён / в архиве» — это тот же серверный
  фильтр `status`. Клик по папке — фильтр `portfolioId` журнала
  (`none` — без портфеля); выбор живёт в строке инструментов (`useListToolbar`)
  и переживает reload вместе с пресетами.
- **Создание/переименование/архив/возврат портфеля — в этой колонке**:
  инлайн-поле `+` (`components/portfolio-create-field.tsx`), меню «шашки»
  строки папки, окна `components/portfolio-dialogs.tsx`. Меню есть только у
  настоящих портфелей: у «Все проекты»/«Без портфеля» нет id для
  `PATCH/DELETE /projects/groups/:id`. Права: создание — `project.create`;
  переименование/архив/возврат — `project.manage` (UI прячет, сервер —
  истина, I8). Мутации оптимистичны с откатом
  (`api/project-catalog-mutations.ts`).
- **Перетаскивание проекта на папку — смена портфеля** (`api/project-portfolio-mutation.ts`,
  `DataTable.rowDrag`, права — `lib/project-edit-rights.ts`): тащит тот, кто
  правит проект (руководство или `project.manage`); архивный проект —
  только `project.manage` (поля заморожены, иначе 403). «Без портфеля»
  принимает бросок (`portfolioId: null`), архивные папки — нет. Строки
  журнала — `role="row"` с `draggable`; папка подсвечивается при наведении.
- **Счётчики папок** — `GET /projects/groups/counts?scope=all|mine`
  (`api/portfolio-counts.ts`, ключ `projects.groups.counts.<scope>`): сервер
  считает ТОТ ЖЕ срез, что журнал (режим «Все/Мои» и видимость секретных) —
  журнал листается курсором, из загруженной страницы полного числа не вывести.
- Каноническая таблица `shared/views` (`DataTable`, ключ колонок
  `projects.list`, реестр `shared/views/project-table-fields.tsx` —
  `useProjectTableFields()`: системные поля + атрибуты портала, привязанные
  к типам проектов, группой «Атрибуты» в шестерёнке, #632).
- Шапка правой зоны — ОДНА строка: заголовок + счётчик загруженных, «Создать»
  СЛЕВА от поиска (закон кнопки создания; из папки — с предзаполненным
  портфелем), поиск с панелью фильтра, переключатель «Все / Мои», шестерёнка
  колонок.
- Фильтры — СЕРВЕРНЫЕ (`GET /projects?scope=&search=&role=&visibility=&status=&portfolioId=`)
  с курсорной пагинацией (keyset `updated_at,id`); чипы и пресеты — общая
  строка инструментов (`shared/views/project-filter-fields.ts`; «Без портфеля»
  — сентинел `none`). Поиск деферится (`useDeferredValue`), чтобы ввод не
  дёргал сеть на каждый символ.
- Строка: меню «шашки» — открыть, копировать ссылку + доменные действия
  руководства (завершить, в архив с подтверждением, вернуть в работу).
- Открытие карточки — `openCard({ kind: 'project', id }, rect)`.

## Карточка (`components/project-card.tsx`)

Раскладка — вердикт владельца 10.11.2026 (#735/#746): вся карточка — полотно
областей вкладок (1–2). Статичной левой панели «О проекте» и нижнего бара
больше нет; «О проекте» — обычная вкладка. Порядок/области/ширины/скрытые и
первая вкладка — личные настройки сотрудника (`cardTabs.project`, #745;
localStorage-кэш на пользователя + серверный GET/PUT).

- **О проекте** (`project-about-panel.tsx`): обычная вкладка на общей колонке
  данных карточек (`CardDataColumn`, как в карточке задачи) — равные отступы
  от краёв области, центрирование и аккуратное расширение при растягивании
  (вердикт владельца 11.11.2026). Колонка прокручивается в пределах карточки
  (#798): панель вкладки — полноразмерная flex-колонка (`CardTabPanelLayer`),
  поэтому `flex-1` колонки получает высоту области. Содержимое: описание, паспорт
  полей-реестром (`lib/project-passport.tsx` — руководство, заказчик, сроки,
  состав, создатель, активность; ссылки открываются карточками стека), блок
  «Атрибуты» области `project` (`CustomFieldsBlock`). Сетки полей —
  по @container: на широкой вкладке две колонки.
- **Действия в шапке** (`project-action-bar.tsx` → `ProjectHeaderActions`):
  тихая «Редактировать» (pencil, без primary-заливки), меню «⋯» (завершить,
  в архив с подтверждением, вернуть в работу, передать руководство,
  «Присоединиться/Покинуть»). Кнопка раскладки `Columns2/Combine` — между
  ними (общий `CardLayoutButton`). В архиве правка и передача — только
  `project.manage`, сервер отклонит (I8). Правый слот полосы вкладок остаётся
  за тогглом панели «О канале» (`PanelRight`).
- **Полоса вкладок** (`project-tab-strip.tsx` + общий
  `shared/ui/entity-card/card-tab-areas.tsx`): системный порядок «Структура /
  Задачи / О проекте / Канал / Участники / История» + «+» (личный набор).
  **Системный дефолт нового сотрудника — две области**: «О проекте» отдельной
  вкладкой слева, все остальные справа, активна «Структура» (вердикт
  владельца 11.11.2026); «+»/личный порядок перекрывают. Карточка
  открывается на ПЕРВОЙ ВИДИМОЙ вкладке личного порядка; без личного
  порядка — «Структура» (системный дефолт). «Структура» больше не закреплена:
  скрыть можно любую, кроме последней видимой. Drag:
  перестановка/перенос между областями/сплит к краю/merge; контекстное меню и
  клавиатура — альтернатива без drag (WCAG 2.5.7). «Чат проекта» появится
  вместе с пространством проекта (#456) — до него вкладки нет.
- Вкладки монтируются при первом показе и живут скрытыми (`inert`), содержимое
  переносится между областями без ремаунта: прокрутка, фильтры и черновик чата
  не теряются.
- **Задачи** (`project-tasks-tab.tsx`): те же задачи (`GET /tasks?projectId=`),
  виды «Список» (DataTable `projects.tasks`) и «Канбан» (общий движок
  `shared/ui/board`, ключ `projects.kanban`), primary-кнопка «Создать»
  (окно создания задачи с подставленным проектом), quick-add и DnD.
- **Структура** (`structure/components/structure-tab.tsx`, #467/ADR-0030):
  дерево узлов-папок с задачами-листьями (`GET /projects/:id/structure` —
  узлы + виды уровней срезом целиком; задачи — существующий фид
  `useProjectTaskPages`, `tasks.nodeId`). Сборка строк и агрегаты поддерева —
  чистая `structure/lib/structure-tree.ts` (план/факт/ближайший/поздний/
  прогресс из ПРЯМЫХ rollup узлов, тесты там же); секция «Без узла» внизу.
  Механика: меню строки (шашка + ПКМ — один реестр `structure-menus.tsx`),
  окна создания/пачки/правки/переноса, DnD `structure/lib/use-structure-dnd.ts`
  (узлы и мультиселект задач, зоны четверти, низ раскрытого узла = первым
  ребёнком, блок циклов, авто-раскрытие 700 мс; строки статичны — только
  индикация). План/факт строки задачи — `TaskListItem.plannedMinutes` /
  `spentMinutes` (поле плана добавлено в контракт списка задач для этой
  колонки); у узла — суммы поддерева. Перенос задач — одиночный PATCH
  `nodeId` (`useMoveTaskNode`), bulk `set_node` — для мультиселекта.
  «Задача» на узле — пресет окна создания
  (`TaskCreatePrefill.nodeId` + contextLabel, поля «Узел» в форме нет).
- **Канал** (`project-channel-tab.tsx`, `project-chat.tsx`):
  `GET /chat/conversations/by-project/:id` (find-or-create; не участнику —
  404). Композер гасится для тех, кому нельзя публиковать
  (`project.access.canPostToChannel`), треды открыты всем участникам; панель
  «О канале» — ПОЛНОВЫСОТНАЯ вталкивающая колонка карточки (как в задаче и
  письме), её шапка h-10 продолжает полосу вкладок; открыта только на вкладке
  «Канал».
- **Участники** (`project-members-tab.tsx`): строки-источники группируются по
  сотруднику, у каждого чипы всех источников. Руководство добавляет руками:
  в секретном — участника или наблюдателя, в открытом — только наблюдателя
  (участники живут из задач, вердикт 29.10 В2; участнику из задач наблюдателя
  не предлагают, #714); снятие — по ручным рядам, подпись кнопки называет
  реально снимаемую роль («Убрать наблюдателя» / «Убрать из состава»).
  Паспорт показывает «Участники» (без наблюдателей) и отдельное поле
  «Наблюдатели» (просмотр без прав правки).
- **История** (`project-history-tab.tsx`, подписи — `lib/project-history.ts`):
  лента outbox-событий проекта (`GET /projects/:id/history`, I9) — создание,
  правки полей, статусы, состав; новые первыми, добор курсором. У открытого
  проекта не-участник видит ленту только с момента раскрытия (#748, вариант Б) —
  внизу подпись «История открыта с {дата}»; участие и `project.view_secret`
  видят полную ленту. Состав читается действием (#699): «Добавлен участник /
  наблюдатель», «Снят …», «Наблюдатель → участник», «Вступил / покинул проект»;
  очистка при смене видимости — системная строка со счётом. Автопересчёт из
  задач (`roster_synced`), служебный пресет создания и пересчёт формул
  (`automatic`) в ленте не выдаются за действия человека: пересчёт формулы
  помечен «Автоматически»; значения «было → стало» не показываются — строка о
  сути изменения.

## Создание и справочники

- Единое окно создания (`project-create-dialog.tsx`) монтируется в оболочке
  (`project-create-host.tsx`), открывается из журнала и любого пикера проекта
  (`shared/ui/project-picker.tsx` → `shared/projects/project-create-store.ts`).
  Порядок полей: название → ТИП (сразу после названия — от типа зависит набор
  полей, как в задачах; схема типа — #38/#468) → атрибуты слотами формы типа
  (посевной «Шифр» — обычный слот: `required` у «Договора», `hidden` у «Темы»;
  политика `codeField` заморожена и не читается) →
  руководитель (дефолт создатель), помощники, портфель (+создание на месте),
  заказчик (`CounterpartyCombobox`), видимость (дефолт — открытая, #738:
  настройки «видимость новых проектов» нет), даты (свой `DateTimePicker` без
  времени), описание.
  Подсказок-комментариев под полями нет — метки и контролы на одной линии.
- `pages/project-schemas-page.tsx` — вкладка «Схемы проектов» «Автоматизации»
  (`app/automation-route.tsx`, право `project.setup.manage`), каркас #38:
  окно-сплит как «Процессы» — слева типы проектов с плитками значков и метой
  «N видов» (`components/project-type-column.tsx`: поиск, «+», меню строки
  «Настройки типа / Архивировать»), справа канвас типа
  (`components/project-schema-canvas.tsx` — место будущей схемы проекта),
  правая панель `components/project-type-settings.tsx`: корень (название,
  значок, цвет) и страницы-разделы поверх панели со стрелкой «назад» —
  «Виды папок» (`components/project-type-kinds.tsx`: тумблер «вид доступен
  типу», создание вида на месте, «Включить все виды») и «Шифр проекта»
  (`hidden | optional | required`, его читают окна проекта). `kindIds: null`
  у типа — все виды справочника; снятый вид остаётся у уже созданных папок.
  Клик по виду открывает панель вида (`node-kinds/components/node-kind-panel`:
  форма создания и возможности) поверх панели типа. Архив типа — не удаление.
  Портфелей в «Автоматизации» нет — это папки журнала «Проекты» (#559).
- Окно «Настройки портала» удалено вместе с единственной жилицей — настройкой
  «видимость новых проектов» (#738, вердикт владельца 10.11). **Правило:**
  настройки портала не размещаются в меню профиля (профиль — только действия
  профиля); единственный вход, когда у окна появятся разделы, — левое меню
  «Настройки» (канон места #276), пустое окно не рендерится вовсе.

## Данные и ключи

- `api/projects-api.ts` — журнал (`useProjectsJournal`), карточка
  (`useProjectDetail`), история (`useProjectHistory`), состав
  (`useProjectMembers`), задачи проекта (`useProjectTaskPages`,
  `useMoveProjectTask`); реэкспорт справочников.
- `api/project-mutations.ts` — создание (оптимистичная вставка в подходящие
  журналы), правка полей, статусы, передача руководства.
- `api/project-member-mutations.ts` — join/leave, ручной состав, атрибут
  проекта (все оптимистично, I4).
- `api/project-catalog-mutations.ts` — типы, портфели-папки (создание/
  переименование/архив/возврат), настройки портала.
- `api/project-portfolio-mutation.ts` — смена портфеля проекта
  перетаскиванием (оптимистично: журналы, справочник, карточка).
- `api/portfolio-counts.ts` — счётчики папок журнала (`groups/counts`).
- Ключи — `shared/api/projects-list.ts` (`projectsKeys`): `options`
  (справочник целиком для пикеров), `types`, `groups` (+ `groupsPrefix`,
  `groupCounts`), `journal`, `detail`, `members`, `history`. Инвалидация
  модуля — префиксом `projects`.
- `structure/api/structure-api.ts` — дерево и мутации узлов (создание/пачка/
  правка/перенос/удаление — оптимистично по `projects.structure.<id>`),
  перенос задач `set_node`; `node-kinds/api/node-kinds-api.ts` — мутации видов
  папок (реестр читает `shared/api/node-kinds.ts`, ключ
  `projects.node-kinds`).
- `shared/api/projects-available.ts` — «Проект» в задачах/письмах доступен,
  когда миры совпадают: оба на моках ИЛИ оба живые и флаг `projects` включён
  (`/auth/me.modules`).
- `lib/project-journal.ts` — чистые параметры URL и `matchesProjectFilters`
  (оптимистичная вставка только в подходящие кэши, сентинел `none` — папка
  «Без портфеля»); `lib/portfolio-folders.ts` — папки журнала: счётчики,
  «Все проекты»/«Без портфеля», архивные папки с остатком, строки статусов;
  `lib/project-members.ts` — группировка строк-источников; `lib/project-role.ts`
  (shared) — сильнейшая роль для чипа/фильтра.
- Фильтр «Портфель» в списках **задач и писем** — `shared/views/portfolio-filter-fields.ts`
  (появляется там же, где фильтр по проекту; связь «проект → портфель» из
  справочника проектов; архивные папки — с пометкой «(архив)», чтобы чип фильтра
  читался названием, а не uuid-ом). Фильтр журнала проектов —
  `shared/views/project-filter-fields.ts`.

## Моки (`api/mocks/`)

`projects-handlers.ts` — агрегат: справочники ПЕРЕД `/projects/:id`
(gotcha msw-query); чтение с видимостью секретных и keyset-курсором; мутации
с теми же отказами (409 дубль шифра, 403 права, 422 состав/видимость);
`project-catalog-handlers.ts` — типы/портфели/настройки; `structure-handlers.ts`
— дерево узлов (валидация контрактами; 409 не-пустой узел/шифр/цикл/лимиты;
`/projects/node-kinds` — ДО `/projects/:id`); канал проекта —
`features/chat/api/mocks/project-conversation-handlers.ts`. Демо-мир:
`shared/mocks/data/projects.ts` (данные), `project-views.ts` (DTO/видимость),
`project-store.ts` (создание/статусы/передача), `project-update-store.ts`
(правка полей — диффом, очистка состава при смене видимости),
`project-member-store.ts` (вступление/уход/ручные роли и семантика строк
истории), `project-events.ts` (журнал истории),
`project-nodes.ts` (структура демо-проекта p4: Здание 1/2 с разделами
АР/КР/ИОС, виды папок справочника — «Комплект», «Раздел», «Этап» и др.;
rollup по прямым задачам; часть задач демо-стора несёт `nodeId` —
`task-items.ts`).
