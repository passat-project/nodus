# shared/custom-fields — кирпичи кастомных полей (#431, ADR-0029)

Общий слой значений и редакторов атрибутов (термин UI — «Атрибуты»):
им пользуются карточка задачи (блок «Атрибуты»), окно перехода и (далее) #432/#435/#469/#55/#52. Грамматика
значений — в `@nodus/contracts` (`custom-field-values.ts`), здесь только
представление, ввод и запросы.

## Правила

- Значения — по id определения, ключ `cf.<uuid>` в окнах и гейтах; `null`
  в правке удаляет ключ (пустое не хранится).
- Тип меняется только расширяюще (text→long_text, enum→multienum,
  user→users); чтение толерантное (`readCustomFieldValue`).
- Правка в карточке оптимистичная: `useUpdateTaskCustomField` кладёт значение
  и ссылку выбора в кэш детали и журналов до ответа сервера, откат — по
  снапшотам (канон patterns.md).
- Глобального «скрытого» атрибута больше нет (О2 #631): видимость задаёт
  слот формы места (`hidden` / `optional` / `required`); слот `hidden` не
  рендерится, но остаётся привязкой и доступен условиям процессов.
- Ввод правки по месту — того же габарита, что строка-значение
  (`editorInputClass`/`editorTextareaClass`): активация не сдвигает карточку.
- Ссылки для показа приходят в детали сущности (`customFieldRefs`); строки
  списков несут значения, а с #632 — ещё ссылки и формульное состояние
  (`AttributeCarrier`): по ним рисуются атрибутные колонки видов. Задача
  отдаёт всё это в DTO списка давно; письма и проекты — после расширения
  контракта списков (бэкенд, #632 Пакет 2a), до этого колонки-атрибуты есть,
  но значения пустые (UI читает «когда есть»).

## Формулы (#632, ADR-0037 п.3)

- Ячейка — значение ИЛИ «=формула»: своя формула делает значение read-only
  (правка = снять формулу, Р5); формула типа/вида показывается значком fx,
  правка значения её подавляет, меню «Как у типа» очищает значение и
  возвращает формулу. Состояние ячеек приезжает в DTO `customFieldFormulas`
  (`origin: own | type | value` + ошибка).
- Движок — `@nodus/formula-engine` (тот же, что у API и моков); редактор
  строит AST из плашек, строка формулы парсится ограниченной грамматикой
  (не Excel-строка): литералы, операторы, функции каталога, неявная склейка.
- Ошибка ячейки не блокирует карточку: значение пустое, бейдж «!» с
  подсказкой по коду из `ui.formulas.errors`.
- Колонки видов показывают то же состояние (`shared/views/attribute-fields.tsx`):
  значок fx и бейдж «!» — пометки-`span` в строке таблицы (правка формулы
  живёт в карточке), ошибка видна и при пустом значении. Инвалидация по
  адресному `custom_field.formula_changed` — `shared/socket/custom-fields-invalidation.ts`
  (деталь + списки хоста по `hostKind`).
- Мок-мир (`formula/*-state|resolver|mocks|dto|handlers.ts`) повторяет
  правила сервера: формулы типа/вида считаются НА ЧТЕНИИ (DTO клонируется,
  демо-данные не мутируются), своя формула материализует значение в
  `customFields` при сохранении, ручная правка значения снимает свою формулу
  (PATCH/PUT у владельца), 422 — по каталогу `FORMULA_*`. Демо-формула —
  тип «Комплект»: «Шифр комплекта» = шифр проекта — № по ГП ближайшей папки
  «Здание по генплану» — марка и номер комплекта (значения enum в формулах —
  подписи вариантов справочника, не id).

## Привязка к местам (#631)

Атрибут живёт у мест: `bindings {processTypeIds, projectTypeIds, nodeKindIds}`
в определении, пикер «Где используется» в окне атрибута и сводка в реестре.
Слот формы вида/типа проекта и запись пикера — одна сущность `field_bindings`:
запись формы добавляет привязку для нового слота и снимает её для снятого;
снятие привязки в пикере чистит слот. Привязка без слота законна — её сеет
миграция (системные поля на все места) и ставит пикер; запись формы такие
привязки не сносит (#646).

## Место «Папки» (#556, ревизия #631)

Виды папок — такое же место привязки (`bindings.nodeKindIds`), как типы
процессов и проектов; отдельной области `scope` больше нет. Слот формы вида
и привязка — одна сущность; удаление атрибута чистит слоты видов и значения
папок, использование видами не блокирует.
