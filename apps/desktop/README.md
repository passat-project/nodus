# apps/desktop — десктоп-оболочка Nodus

Тонкий клиент портала (M17, issue #254, **ADR-0019**): главное окно грузит
удалённый адрес портала (бандл веб-приложения НЕ встраивается), поверх — трей,
кастомные попапы уведомлений с быстрым ответом, бейдж непрочитанных,
автообновление самой оболочки с сервера портала. Windows 10/11 (WebView2).

## Структура

```
apps/desktop/
├── src/                    # мини-UI оболочки (React+Vite, токены @nodus/ui)
│   ├── setup/              #   экран «Адрес портала» (+офлайн/обновление)
│   ├── popup/              #   попап уведомления (+ плашка «Скрыть все»)
│   └── shell/              #   типизированные IPC-обёртки мини-UI
└── src-tauri/
    ├── capabilities/       # статические capability локального UI (shell-ui)
    ├── permissions/        # права команд моста (раздаются runtime-capability)
    └── src/
        ├── lib.rs          # композиция: окна, события, гвард навигации
        ├── portal.rs       # адрес портала, конфиг-эндпоинт, подключение
        ├── bridge.rs       # init-script моста + команды «веб→оболочка» + тема UI
        ├── popups.rs       # стек попапов: ≤3 новейших у пола, кумулятив, очередь
        ├── fade.rs         # арбитраж угасания: активность пользователя → ~3 с
        ├── activity.rs     # детектор ввода (клик/клавиша, БЕЗ движения мыши)
        ├── badge.rs        # пиксельный рендер счётчика (только панель задач)
        ├── tray_menu.rs    # трей: открыть/автозапуск/обновления/смена сервера
        ├── deep_link.rs    # схема nodus:// (холодный старт)
        └── updates.rs      # пассивный updater с сервера портала (minisign, #263)
```

## Контракты

- `GET /api/v1/desktop/config` → `desktopConfigSchema` (contracts) — публичный.
- Протокол моста — `packages/contracts/src/desktop/desktop-bridge.schema.ts`:
  команды «веб→оболочка» (`window.nodusDesktop.*`), события «оболочка→веб»
  (`__nodusDesktopInvoke`). Rust-зеркала: `bridge.rs`/`popups.rs` —
  **рассинхрон = баг** (тесты протокола: `apps/web/src/shared/desktop/`).
  Внимание пользователя (#770, ADR-0038): событие `shell-visibility`
  (`{ visible }`) — скрытие в трей, `shell-focus` (`{ focused }`) — фокус
  главного окна; шлётся на `WindowEvent::Focused`/`Resized` как
  `focused && !is_minimized()` (повторы дедуплицируются в `ShellState`),
  потому что WebView2 при минимизации может сохранять и видимость вкладки,
  и `document.hasFocus()`.
  Попап об ответе в трэде несёт `threadRootId` (#300): клик «Открыть»
  (событие `open-conversation`) раскрывает окно треда в портале.
  Цель попапа — ровно одна: беседа (`conversationId`), письмо
  (`letterId`, #618: «Поступило письмо» канцелярии, без быстрого ответа) или
  скачанный файл (`download`, #647: имя файла + `success`, карточка «Файл
  скачан» с кнопкой «Показать в папке»); клик по попапу письма шлёт событие
  `open-letter` → портал открывает карточку письма; гашение попапов
  (`dismiss_popups`) — по ключу цели (беседа или письмо, модель Telegram
  unlinkHistory). Абсолютный путь скачанного файла в контракт НЕ входит —
  он живёт только в Rust, команда `popup_reveal_download` берёт его из
  payload попапа и проверяет каталог «Загрузки» (симлинки наружу
  отвергаются), открытие — `reveal_item_in_dir` (проводник с выделением).

- Обновления: `GET <портал>/desktop/latest.json` + установщики (`/desktop/`
  статика nginx, env `NODUS_DESKTOP_DIR`); pubkey зашит в `tauri.conf.json`.
- Ссылки (#644): JS-перехват `<a target="_blank">` плагина opener **выключен**
  (`open_js_links_on_click(false)`) — он глушил клики отказом ACL. Решение
  принимает веб-перехватчик `apps/web/src/app/shell/use-link-interception.ts`:
  внутренние карточки открываются стеком, внешние http(s) и `mailto:`/`tel:` —
  командой моста `open_external` (системные приложения). `on_new_window`
  остаётся страховкой: URL уходит в систему, окно WebView2 не создаётся.

## Уведомления — только попапы оболочки (#650)

Единственный канал уведомлений — попапы оболочки (ADR-0019). Браузерного
пути (`Notification` API, opt-in фоновой вкладки, запрос разрешения) в
портале больше нет; нативные Windows-тосты исключены решением владельца
(они подчиняются «Не беспокоить»/политикам Windows и могут не показаться).
В браузере уведомлений нет — работа идёт через оболочку.

- Что уведомляет: сообщение чата (попап с быстрым ответом), письмо
  («Поступило письмо», клик открывает карточку), завершённое скачивание
  (имя файла + «Показать в папке»; неудача — карточка ошибки без кнопки).
- Поведение: стек ≤ 3 (новейший внизу), при активности угасание ~3 с,
  `urgent` висит до реакции; карточка скачивания информационная —
  автоскрытие 8 с, hover держит паузу; «Скрыть все» гасит стек.
- Окно попапа НЕактивируемое (`.focusable(false)`): приход уведомления не
  забирает системный фокус — можно продолжать печатать в Nodus или в другом
  приложении. «Ответить» временно активирует окно (`set_focusable(true)` +
  `set_focus`), а Esc/закрытие/отправка возвращают фокус туда, откуда он был
  взят (`activated_from`, #709). Ручной `WS_EX_NOACTIVATE` не использовать:
  `win.show()` стирает его при пересборке ex-style (gotcha «Десктоп»).
- Тема — тема приложения (не Windows), строки — i18n `ui.desktop`.

## Автообновление (пассивный поток, #263)

Обновление **не ставится без решения пользователя**: фоновая проверка после
подключения к порталу → тихое скачивание (`check_and_prepare`) → индикаторы —
зелёная точка на кнопке «Скачать приложение» в шапке портала (событие моста
`update-state`) и пункт трея «Перезапустить (версия)». Попап кнопки берёт
ПЕНДИНГ-версию из моста, а веб-манифест — только как источник текста «что
нового» (и показывает его, лишь когда версия манифеста совпала с пендингом:
долгоживущее окно портала может держать манифест старше выпуска, #739).
Установка — по клику
(`apply_update` / пункт трея): passive-установщик завершает процесс и
сам возвращает приложение (NSIS `/R`, `restart_after_install`). Безусловный
путь `run_updater` (сразу скачать и поставить) остаётся только экрану
«обновите приложение» (гейт `NODUS_MIN_SHELL_VERSION`). Каналы обновлений не
пересекаются: манифест несёт target-ключи `windows-x86_64-nsis`/`-msi`,
апдейтер выбирает по типу своей установки (`upgradeCode` зафиксирован в
`tauri.conf.json`). Раздача и выпуск — runbook `docs/runbooks/desktop-deploy.md`:
подписанный выпуск собирает CI (`.github/workflows/desktop-release.yml`, ключ в
окружении `desktop-signing`, запуск после Approve владельца), на сервер файлы
кладёт `scripts/desktop-publish.mjs` в версионные каталоги `releases/<версия>/`.

## Безопасность (границы, ADR-0019)

- Токены/креды не покидают веб-приложение: мост переносит только команды
  дисплея; ACL моста выдаётся runtime-capability РОВНО origin'у портала
  (`dynamic-acl`, минимальный набор прав в `permissions/shell-bridge.toml`).
- Гвард навигации: локальный мини-UI (схема app (`http`/`https`/`tauri`) И
  host `tauri.localhost` — схема проверяется ДО host: `file://tauri.localhost/…`
  отклоняется, #716) и origin портала; всё прочее — системный браузер.
  `open_external` принимает только http/https/mailto/tel; новые окна
  WebView2 не создаются (`on_new_window` → системное приложение, #644).
- Адрес портала валидируется (схема/хост, без пути и user-info).

## Команды (из каталога apps/desktop)

```bash
pnpm build                                   # мини-UI → dist/
pnpm exec tauri dev                          # окно-оболочка (dist без dev-сервера)
pnpm exec tauri build                        # NSIS + MSI (+ .sig при ключе)
pnpm exec tauri signer generate -w <путь>    # пара minisign (приватный — вне репо!)
```

Dev-режим: адрес портала вводится на экране подключения (песочница live-stack
`http://127.0.0.1:4173`); живые проверки — только по канону `nodus-dev-testing`.
Порядок сборки после правок контрактов: `contracts build` → `desktop build` →
`cargo build` (ассеты вшиваются компилятором).

## Лимиты и ограничения

- Попапы: столбик ≤ 3 (новейший внизу, сверх — очередь-докат); автоскрытия
  НЕТ — пока пользователь неактивен (нет кликов/клавиш) попапы висят вечно,
  при активности медленно угасают ~3 с; hover и поле ответа ставят паузу.
  Исключение — карточка скачивания (#647): информационная, сама уходит через
  8 с, hover держит паузу. Плашка «Скрыть все» — только при полном столбике,
  гасит всё разом.
- Раскладка — по якорю монитора (#588): курсор → монитор главного окна →
  первичный монитор. `GetCursorPos` недоступен вне input desktop (локскрин,
  логон, смена пользователя, RDP) — резервные якоря не дают окнам остаться на
  системном каскаде в левом верхнем углу; позиция попапа задаётся сразу
  билдером окна, а после возврата сессии тикер переставляет стек на монитор
  курсора без клика пользователя.
- Карточка — референс Telegram (03.11): аватар-кружок почти во всю высоту
  (задаёт высоту карточки), имя и превью (2 строки) прижаты к верху,
  отступы симметричные (`p-2`); отступ под крестик — только у строки имени,
  превью использует ширину целиком (короткая фраза не уезжает на 2-ю строку).
- Высота попапа — ПО ФАКТУ контента (#406): мини-UI измеряет карточку
  (ResizeObserver) и шлёт `popup_set_height`; оболочка раскладывает стек по
  фактическим высотам и применяет позицию+размер одним `SetWindowPos`.
  Захардкоженные «88/124» нельзя: rem-утилиты наследуют `--ui-scale` (1.25),
  и поле ответа вырастает за окно. Карточка — `overflow: clip` (не `hidden`):
  `hidden` остаётся scroll-контейнером, и scroll-into-view фокуса уводит
  заголовок и крестик за верхнюю границу. Крестик абсолютный и доступен
  всегда, в т.ч. с открытым полем ответа; Esc закрывает поле, затем попап.
- Показ попапа — ready-gate (#305): окно создаётся скрытым, мини-UI pull'ает
  данные с темой, применяет её до рендера и после первого кадра зовёт
  `popup_ready` — только тогда оболочка показывает окно (fallback ~1.2 с,
  если вебваlew не поднялся: уведомление важнее одного некрасивого кадра).
  Так исчезают чёрный composite прозрачного окна до первой отрисовки и
  гонка каналов темы («первое уведомление чёрное в светлой теме»).
- Тема попапов следует теме ПРИЛОЖЕНИЯ (портал сообщает через `set_ui_theme`,
  тема кладётся в payload попапа), не теме Windows. Бейдж непрочитанных —
  только на панели задач (в трее чистый знак). Закрытие попапа крестиком
  не разворачивает свёрнутое приложение («пользователь занят»).
- Значок ЕДИНЫЙ для всех мест (окно, панель задач, ярлык, трей): тёмно-синяя
  скруглённая плитка с белым знаком, читается на любой теме Windows —
  рантайм-перекраса по теме нет (#263). Мастер — `docs/design/logo/Nodus_значок_приложения.svg`;
  набор `src-tauri/icons/` генерирует `pnpm --filter @nodus/desktop exec tauri icon` — правки только через перегенерацию.
- Обновления контента (весь портал) — деплой сервера; оболочка обновляется
  только при смене самой себя (скачивается тихо, ставится по решению
  пользователя, подписано).
- Вкладки/несколько окон портала — вне MVP (инкубатор, И-021).
- Фон log: `%LOCALAPPDATA%\by.nodus.desktop\logs/`; адрес: `%APPDATA%\by.nodus.desktop\portal.json`.
